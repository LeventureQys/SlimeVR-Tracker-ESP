## 自决区（已决策，理由如下；不同意请指出）

### Q2. UI 布局"拧巴"的定位与修复方案（需求 #1）

- **问题定位**：`archived/src/ui/main_window.cpp`（81-231 行）`buildInterface()` 方法。
  - 右侧 `propertiesDock` 使用 `QVBoxLayout` 垂直堆叠：modeCombo + manualPanel + simulationPanel + imuPanel + stretch。
  - 三个面板（手动关节 / 六路模拟 / 真实 IMU）同时创建但通过 `setVisible()` 切换，每个面板内部有多行控件。
  - `resize(1420, 900)` 但未设置 dock widget 的最小宽度或 QSplitter。
  - 状态栏三个 QLabel 的 stretch 比例 (1:2:0) 可能导致文字截断。
- **修复方案**：
  1. 为右侧 dock 设置 `setMinimumWidth(320)` 和 `setFeatures(QDockWidget::DockWidgetMovable | QDockWidget::DockWidgetFloatable)`。
  2. 给 properties 内容区加 `QScrollArea` 包裹，防止小窗口下控件被截断。
  3. 调整左侧 dock 最小宽度（`setMinimumWidth(180)`），避免骨骼树过窄。
  4. 状态栏 QLabel 设置 `setSizePolicy(QSizePolicy::Preferred, QSizePolicy::Fixed)`。
- **置信度**：90%。**分区**：自决区。

### Q3. 3D 渲染"高频彩色点 + 光线反射不正确"（需求 #2）

- **问题定位**：`archived/src/render/hand_render_widget.cpp`
  - **彩色点**：`drawSkeleton()`（682-741 行）使用 `GL_PROGRAM_POINT_SIZE` + `GL_POINTS` 绘制骨骼点，`gl_PointSize` 设为 `8.0 * devicePixelRatioF()`。在高 DPI 屏幕上可能产生较大彩色点。同时 `drawMeshes()` 和 `drawSkeleton()` 共享深度缓冲，overlay 点可能与 mesh 表面 z-fight 产生彩色闪烁。
  - **光线反射**：mesh fragment shader（416-428 行）使用极简 Blinn-Phong：单方向光 `(0.35, 0.7, 0.55)`，ambient 0.28，diffuse 0.72，**无 specular 高光**。这意味着模型表面没有镜面反射，看起来"哑光"而非"有光泽"。此外，`mat3(transform)` 用于法线变换，当 skinning 矩阵含非均匀缩放时法线会偏移。
- **修复方案**：
  1. **彩色点**：在 `drawSkeleton()` 中，绘制 overlay 前 `glDisable(GL_DEPTH_TEST)` 或使用 `glPolygonOffset` 避免 z-fight；将骨骼点大小适当减小。
  2. **光照**：在 fragment shader 中增加 Blinn-Phong specular 项（`pow(NdotH, shininess) * specularStrength`），使模型表面有光泽反射感。
  3. **法线修正**：确保 skinning 矩阵的法线变换使用 `(M^-1)^T` 或至少 `normalize(mat3(transform) * aNormal)` 后再传入 fragment shader（当前已有 normalize，但可加 specular 改善观感）。
- **置信度**：85%（彩色点与 z-fight/point size 关联度高；光照缺少 specular 是确定的）。**分区**：自决区。

- **决策**：单文件 `imu_data.csv`，列：`timestamp_ms, accel_x, accel_y, accel_z, gyro_x, gyro_y, gyro_z, angle_x, angle_y, angle_z, mag_x, mag_y, mag_z, battery_pct, temp_c, frame_count`。使用 Qt 的 `QTextStream` 写入，每帧一行。
