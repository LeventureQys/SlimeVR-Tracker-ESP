# 手套六 IMU 实时解算 Qt 工具 MVP v0.1.0 验收文档

## 1. 文档目的

本文供零上下文验收 Agent 或测试人员使用。验收对象位于 `Document/Research/手套IMU解算MVP/`，目标程序为 `SixImuSolverQt`。验收必须按“编译测试 → 单元测试 → 启动测试 → 功能完整性测试 → 整体与真实硬件测试”顺序执行；上一层失败时停止后续放行，并记录所属 SubStage。

## 2. 验收依据

- `需求文档.md` v0.3；
- `设计文档.md` v0.1.0；
- `阶段二问题清单.md`；
- `Document/Wit 手套资料/串口输出解析协议文档.md`；
- `Document/Wit 手套资料/parse_six_imu.py`；
- 单设备默认换算参考 `Document/Wit 手套资料/archived/Adapter/IMU_Example_Qt/src/wit_protocol_parser.cpp:90`。

冲突时：用户需求与问题清单决策优先，其次设计文档，再次参考实现。

## 4. 第一层：编译测试

### 4.1 配置

```powershell
cmake -S . -B build -DBUILD_TESTING=ON -DCMAKE_PREFIX_PATH="<Qt6安装路径>"
```

期望：退出码 0；找到 Core、Gui、Widgets、SerialPort、Test；生成构建目录。

### 4.2 构建

```powershell
cmake --build build --config Debug -j8
```

期望：退出码 0；生成：

- `SixImuSolverQt.exe`；
- `test_protocol.exe`；
- `test_sequence_grouper.exe`；
- `test_madgwick_filter.exe`；
- `test_settings.exe`；
- `test_main_window.exe`。

失败判定：任何编译或链接错误。不得因测试目标失败而只构建主程序并放行。

证据：完整命令、退出码、日志文件。

## 5. 第二层：自动化单元测试

### 5.1 执行

```powershell
ctest --test-dir build -C Debug --output-on-failure
```

期望：所有测试通过，0 failed。

### 5.2 协议用例

| ID | 输入/步骤 | 期望 |
| --- | --- | --- |
| P01 | 文档示例合法帧 | 地址、SEQ、九轴和 CRC 正确 |
| P02 | 帧在每个字节边界拆分 | 补齐前无输出，补齐后恰好一帧 |
| P03 | 连续 2、6、100 帧粘包 | 数量、顺序、内容一致 |
| P04 | 噪声、伪头、残帧后合法帧 | 自动恢复，无死循环和无界缓存 |
| P05 | payload/CRC 单 bit 翻转 | 错帧拒绝，CRC 计数增加，后续恢复 |
| P06 | LEN 非 0x12 | 错帧拒绝，长度计数增加，后续恢复 |
| P07 | int16 最小最大、正负 | 大端和符号正确，无溢出 |
| P08 | 未知地址 | 有效协议帧计数和未知计数增加，不分组 |
| P09 | 九轴全零 | 帧有效且 `allZero=true` |
| P10 | reset | 缓存和统计清空 |

CRC 独立参考：至少用协议文档示例帧和一个测试编码器固定向量验证，不得只用产品 CRC 生成再验证自身。

### 5.3 分组用例

| ID | 输入/步骤 | 期望 |
| --- | --- | --- |
| S01 | 同 SEQ 六地址任意顺序 | 第六路到达后发布一次完整组 |
| S02 | 两个 SEQ 交错 | 不混组，按完成次序发布 |
| S03 | 同地址重复不同 payload | 重复计数，最新覆盖 |
| S04 | 只输入五路并继续创建新组 | pending 超 8 后淘汰最早不完整组 |
| S05 | SEQ FE、FF、00、01 | 四组正常，无普通整数排序错误 |
| S06 | 未知地址 | 不占六路位图 |
| S07 | reset | pending 与统计清空 |

首版不要求基于毫秒超时或已发布历史去重；验收不得添加设计外判定。分组有界规则只使用最多 8 个 pending。

### 5.4 Madgwick 与六路融合用例

| ID | 输入/步骤 | 期望 |
| --- | --- | --- |
| A01 | raw accel/gyro=16384，mag=120 | 8g、1000°/s、1参考值 |
| A02 | 静止 `[0,0,1g]`、gyro 0 | 四元数有限、范数误差≤1e-9 |
| A03 | 已知单轴恒定角速度 | 旋转方向正确，角误差符合测试容差 |
| A04 | 有效磁场 | `NineAxis` |
| A05 | 磁场全零、非有限、越界 | `SixAxis`，不视为硬错误 |
| A06 | dt=0、负、>0.1 或非有限 | 硬错误，整组状态不提交 |
| A07 | 任一路硬错误 | 六路原子回滚，不混合新旧状态 |
| A08 | 六路相同输入 | 六路姿态等价，允许 q/-q |
| A09 | 成功零位标定 | 六路 relative 接近单位旋转 |
| A10 | 无有效六路时标定 | 失败且不改变旧零位 |
| A11 | 应用设置 | 六路融合与零位重置 |
| A12 | 长序列 | 无 NaN/Inf，无范数发散 |

欧拉角只作观察值；姿态误差使用 `2*acos(abs(dot(qExpected,qActual)))`，不逐分量判断符号。

### 5.5 设置与 Dialog 用例

| ID | 输入/步骤 | 期望 |
| --- | --- | --- |
| C01 | 空临时 QSettings | 16g、2000dps、120、beta0.1 等默认值 |
| C02 | 保存非默认参数并新建实例 | 全部值一致加载 |
| C03 | 缺键/错误类型/非法组合 | 按设计回退，不崩溃 |
| C04 | NaN/Inf/越界/min≥max | 校验失败，不保存 |
| C05 | Dialog 修改后 Cancel | 运行值和持久值不变 |
| C06 | Restore 后 Cancel | 原设置不变 |
| C07 | Restore 后 OK | 默认值保存并可重载 |
| C08 | QSettings sync 失败 | save=false，运行设置不替换 |

所有用例必须使用临时 INI 路径，不污染 `SlimeVRResearch/SixImuSolverQt` 生产设置。

### 5.6 UI 用例

- 主窗口关键 objectName 全部存在；
- 六个 `SensorPanel` 存在且地址映射正确；
- 注入快照后 raw、relative quaternion、Euler、SEQ 和状态正确；
- UI 通过 33 ms 定时刷新，不由每帧直接重绘；
- 开启 demo 禁用真实串口操作；
- 标定按钮只在六路有效时启用；
- 参数保存后显示需重新标定；
- 超过 500 ms 显示超时且保留最后值。

## 6. 第三层：启动测试

### 6.1 自动演示启动

```powershell
.\build\Debug\SixImuSolverQt.exe --demo --quit-after-ms 3000
```

期望：

- 主窗口成功创建；
- 状态明确包含“演示模式”与“非真实设备数据”；
- 六路原始值和姿态至少更新一次；
- 运行约 3 秒后退出码 0；
- stdout/stderr 无 `ASSERT`、`fatal`、未处理异常和崩溃；
- 无持久在线进程。

证据：命令、开始/结束时间、退出码、日志；可补充截图，但截图不能替代退出码和日志。

### 6.2 非法参数

```powershell
.\build\Debug\SixImuSolverQt.exe --quit-after-ms 0
```

期望：明确错误并非零退出，不启动隐藏常驻进程。

## 7. 第四层：功能完整性测试

### F01 串口界面

1. 启动程序；
2. 点击刷新；
3. 验证列表与系统串口一致；
4. 空选择时打开应给出提示；
5. 打开不存在或被占用端口，程序保持可操作；
6. 重复关闭不崩溃。

### F02 演示完整链路

1. 启用演示；
2. 观察 10 秒；
3. 六地址计数均增长；
4. 完整组率持续更新；
5. 六路 raw、四元数和欧拉角持续变化；
6. 四元数无 NaN/Inf；
7. 切换关闭后停止增长；
8. 重新开启时会话状态按设计重置。

### F03 磁场退化

通过测试接口或演示夹具输入磁场全零：对应 FusionMode 为 SixAxis；恢复有效磁场后自动 NineAxis。不得弹错误框。

### F04 零位标定

1. 六路有效且稳定；
2. 点击零位；
3. 六路标定状态为已标定；
4. relative 四元数接近单位；
5. 继续运动后 relative 变化；
6. 清除后标定状态清空；
7. 设置变更后零位自动清空。

### F05 参数持久化

1. 打开设置；
2. 修改为一组合法非默认值；
3. 确定并退出；
4. 新进程重启；
5. 对话框显示相同值；
6. 恢复默认并确定；
7. 再重启显示默认值。

记录生产 `QSettings` 路径或注册表键、前后值；验收结束可恢复默认。

### F06 异常协议恢复

向 parser 注入合法组 A、错误 CRC、错误 LEN、不完整组、合法组 D。期望 A 显示，错误只计数，D 恢复显示；不完整组不与 D 混合，姿态保持上一同步快照并标陈旧。

## 8. 第五层：性能与稳定性

### 8.1 演示 60 秒

- 演示运行至少 60 秒；
- 六路持续更新；
- GUI 可响应设置 Dialog 开关；
- 无日志风暴；
- parser 缓冲和 pending 数有界；
- 进程内存无明显持续线性增长；
- 无 NaN/Inf。

记录开始/结束内存、有效帧数、完整组数、错误统计和截图。

### 8.2 目标吞吐

演示或夹具输入约 1200 帧/秒、200 完整组/秒，运行 30 秒：

- parser 持续消费；
- pending ≤ 8；
- UI 仍约 30 Hz；
- 不要求 UI 显示每个样本，但最新快照不可持续落后；
- GUI 连续无响应超过 100 ms 需记录为性能缺陷。

## 9. 第六层：真实硬件测试

### 9.1 前置条件

- 六 IMU 手套和 USB 串口可用；
- 串口未被其他程序占用；
- 921600、8N1；
- 演示模式关闭；
- 记录实际 SolverSettings。

### 9.2 60 秒核心路径

1. 打开目标串口；
2. 0–20 秒静止；
3. 20–40 秒依次转动手腕与五指传感器；
4. 40–60 秒恢复静止；
5. 执行六路零位并做小幅动作；
6. 关闭串口和程序；
7. 再次打开程序确认串口可重用。

期望：

- 六地址均持续增长；
- 完整组持续发布；
- 无崩溃、卡死、NaN/Inf；
- 静止时姿态不持续发散；
- 转动对应节点时对应姿态方向变化，无明显串路；
- 磁场异常时显示 SixAxis，不崩溃；
- 零位后 relative 接近单位；
- 关闭后串口释放。

### 9.3 证据

- 串口名、USB 芯片、手套/固件信息；
- 实际参数；
- 起始、中间、结束截图或录屏；
- 60 秒统计：输入字节、有效帧、CRC/LEN、完整/不完整组、重复、每地址计数、帧率、组率；
- 操作时间线；
- 完整应用日志；
- 异常说明。

### 9.4 硬件阻塞

若无硬件、端口不可用或协议固件不匹配：

- 真实硬件项状态必须为“阻塞”，不能写“通过”；
- 在阶段问题清单置顶区追加阻塞原因；
- 写明责任资源与解除条件；
- 演示模式不得替代真实硬件结论。

## 10. 范围完整性检查

必须存在：串口、协议、分组、六路 Madgwick、磁场退化、原始/姿态 UI、统计、零位、设置 Dialog、QSettings、演示、测试、README。

必须不存在：关节角、三维手模、曲线、录制、网络输出、设备写配置、自动重连、多手套并发、每路不同轴映射。

## 11. 缺陷归属

- CRC/切帧/大端：SubStage 1；
- SEQ/重复/淘汰：SubStage 1；
- 换算/Madgwick/零位/设置模型：SubStage 2；
- 串口/demo：SubStage 3；
- Dialog/面板/完整链路：SubStage 4；
- CMake/CTest/README/启动脚本：SubStage 5。

失败后由 MainAgent 分派对应 SubStage 修复，最多重试 3 次；仍失败则暂停并重规划。

## 12. 放行规则

全部满足才可标记 v0.1.0 完成：

- 编译通过；
- 所有自动测试通过；
- 演示启动测试通过；
- 功能完整性通过；
- 60 秒稳定性通过；
- 真实硬件通过，或明确阻塞且用户接受不完成硬件验收；

- 验收证据可复核；
