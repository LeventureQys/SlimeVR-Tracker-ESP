# IMU Example Qt v0.1.0 设计文档

## 1. 背景与目标

本项目将 WIT BLE 5.0 Android 示例改写为独立的 Qt 6 桌面程序。程序负责发现名称以 `WT` 开头的 BLE 姿态传感器，连接目标设备，解析真实通知数据，并以标准 Qt Widgets 实时显示数值；不实现三维模型、曲线、动画或设备配置写操作。

## 2. 范围

### 2.1 包含

- BLE Low Energy 设备扫描、去重和 `WT` 前缀筛选。
- 单设备连接、服务发现、通知订阅和主动断开。
- `0x55 0x61` 姿态帧解析。
- `0x55 0x71` 磁场、电量、温度和版本寄存器返回解析。
- 周期读取磁场、电量、温度和版本。
- 实时数值、连接状态、最近更新时间和帧计数展示。
- 显式演示模式，用于无硬件启动与 UI 数据链路测试。
- QtTest 单元测试和应用启动测试入口。

### 2.2 不包含

- 恢复出厂、回传率、带宽、角度归零和磁场校准。
- 多设备同时连接、跨设备时间同步和数据融合。
- 三维姿态、图表、自定义绘制、数据记录和回放。
- Android、移动端权限或原 Android SDK 的复用。
- 对仓库根应用或根 `CMakeLists.txt` 的修改。

## 5. 总体架构

```text
QBluetoothDeviceDiscoveryAgent
              |
              v
        WitBleManager
  扫描/连接/服务/通知/写队列
              |
       notificationReceived
              v
       WitProtocolParser
  缓存/同步/解析/最新快照
              |
          dataUpdated
              v
```

所有对象运行在 GUI 主线程的 Qt 事件循环中。不得创建阻塞 BLE 线程；Qt Bluetooth 的异步信号负责生命周期推进。

## 7. 数据契约

### 7.1 `ImuData`

定义于 `src/imu_data.h`：

```cpp
struct ImuData {
    double accelerationX = 0.0;
    double accelerationY = 0.0;
    double accelerationZ = 0.0;
    double angularVelocityX = 0.0;
    double angularVelocityY = 0.0;
    double angularVelocityZ = 0.0;
    double angleX = 0.0;
    double angleY = 0.0;
    double angleZ = 0.0;
    double magneticX = 0.0;
    double magneticY = 0.0;
    double magneticZ = 0.0;
    double batteryPercent = 0.0;
    double temperatureCelsius = 0.0;
    QString firmwareVersion;
    QDateTime lastUpdated;
    quint64 frameCount = 0;
};
```

`ImuData` 是最新值快照。不同类型帧只更新自己携带的字段；其他字段保留前值。每成功解析一个支持的帧，`frameCount` 加一并更新 `lastUpdated`。

### 7.2 显示精度和单位

| 字段 | 显示精度 | 单位 |
| --- | --- | --- |
| acceleration | 3 位小数 | g |
| angularVelocity | 3 位小数 | °/s |
| angle | 2 位小数 | ° |
| magnetic | 3 位小数 | 协议值 |
| batteryPercent | 0 位小数 | % |
| temperatureCelsius | 2 位小数 | ℃ |
| firmwareVersion | 原字符串 | - |

## 8. 协议契约

### 8.1 UUID

```text
Service: 0000ffe5-0000-1000-8000-00805f9a34fb
Notify : 0000ffe4-0000-1000-8000-00805f9a34fb
Write  : 0000ffe9-0000-1000-8000-00805f9a34fb
CCCD   : 00002902-0000-1000-8000-00805f9b34fb
```

### 8.2 字节序与有符号值

所有 16 位字段为小端有符号值：

```text
signed16 = int16((high << 8) | low)
```

### 8.3 姿态帧 `55 61`

固定 20 字节：

| 偏移 | 内容 | 换算 |
| --- | --- | --- |
| 0..1 | `55 61` | 帧头 |
| 2..7 | Acc X/Y/Z | `raw / 32768.0 * 16.0` |
| 8..13 | Angular velocity X/Y/Z | `raw / 32768.0 * 2000.0` |
| 14..19 | Angle X/Y/Z | `raw / 32768.0 * 180.0` |

解析器保留完整双精度计算结果，UI 层负责格式化，不在协议层提前四舍五入。

### 8.4 寄存器帧 `55 71`

固定 20 字节，寄存器号位于偏移 2，数据从偏移 4 开始：

- `0x3A`：`HX/HY/HZ = signed16 / 120.0`，分别使用偏移 `4..5`、`6..7`、`8..9`。
- `0x64`：电压 `signed16(4..5) / 100.0`，再按 8.5 节映射百分比。
- `0x40`：温度 `signed16(4..5) / 100.0` ℃。
- `0x2E`：`raw32 = uint16(reg2e) | (uint16(reg2f) << 16)`；最高位为 1 时，版本为位段 `[30:14].[13:8].[7:0]`，否则保持原版本字符串不变。
- 其他寄存器：消费该 20 字节帧但不改变 `ImuData`，不增加 `frameCount`。

### 8.5 电量映射

按原 Android 严格大于阈值的顺序映射：

```text
>3.96:100, >3.93:90, >3.87:75, >3.82:60,
>3.79:50, >3.77:40, >3.73:30, >3.70:20,
>3.68:15, >3.50:10, >3.40:5, else:0
```

### 8.6 流缓存与同步

`WitProtocolParser::appendBytes(const QByteArray &bytes)` 将通知追加到持久缓存：

1. 缓存不足 2 字节时等待后续通知。
2. 从头搜索 `55 61` 或 `55 71`；头部噪声全部删除。
3. 找到候选帧但不足 20 字节时保留缓存并返回。
4. 满 20 字节时提取并解析一帧，再继续处理剩余数据。
5. 缓存仅剩末尾单字节 `55` 时必须保留，供下一通知拼接。
6. `reset()` 清空缓存和数据快照；连接新设备和断开时调用。

## 9. 核心接口契约

### 9.1 `WitProtocolParser`

```cpp
class WitProtocolParser final : public QObject {
    Q_OBJECT
public:
    explicit WitProtocolParser(QObject *parent = nullptr);
    void appendBytes(const QByteArray &bytes);
    void reset();
    const ImuData &data() const;
    static double batteryPercentForVoltage(double voltage);
signals:
    void dataUpdated(const ImuData &data);
};
```

- 正常输出：每成功解析一个支持帧发出一次 `dataUpdated`。
- 空输入、不完整帧、噪声和未知寄存器：不抛异常、不发错误对话框。
- 内部错误处理：协议无异常机制；保持缓存可继续同步。

### 9.2 `WitBleManager`

```cpp
enum class BleConnectionState {
    Idle,
    Scanning,
    Connecting,
    DiscoveringServices,
    Subscribing,
    Connected,
    Disconnecting,
    Error
};

struct DiscoveredDevice {
    QString name;
    QString address;
    QBluetoothDeviceInfo info;
};

class WitBleManager final : public QObject {
    Q_OBJECT
public:
    explicit WitBleManager(QObject *parent = nullptr);
    void startScan();
    void stopScan();
    void connectToDevice(const QBluetoothDeviceInfo &device);
    void disconnectDevice();
    BleConnectionState state() const;
signals:
    void scanReset();
    void deviceDiscovered(const DiscoveredDevice &device);
    void stateChanged(BleConnectionState state, const QString &message);
    void notificationReceived(const QByteArray &bytes);
    void errorOccurred(const QString &message);
};
```

生命周期：

- `startScan()` 先停止旧扫描并清空地址去重集合，再进入 `Scanning`，默认 10 秒后停止。
- 仅发布名称以 `WT` 开头且地址/设备 UUID 尚未出现的设备。
- `connectToDevice()` 先释放旧 controller/service，再创建 Central controller。
- Controller 连接成功后发现服务；找到目标 Service 后创建 service object 并发现详情。
- 服务详情完成后验证 Notify、Write 和 CCCD，写入 `0100` 开启通知。
- CCCD 写成功后进入 `Connected`，启动 500 ms 轮询。
- 通知特征变化只接受目标 Notify UUID，并发出 `notificationReceived`。
- 任意错误进入 `Error`，停止轮询并发送可展示的中文错误信息。
- 断开或析构时停止扫描、停止定时器、清空命令队列并安全释放 service/controller。

轮询命令依次循环：

```text
FF AA 27 3A 00
FF AA 27 64 00
FF AA 27 40 00
FF AA 27 2E 00
```

使用 `QLowEnergyService::WriteWithoutResponse` 写入。若写特征不支持该模式，则使用 `WriteWithResponse`。未连接时不发送。

## 10. UI 行为

- 初始状态：显示“未连接”，允许扫描和演示模式。
- 扫描：清空旧设备列表并显示扫描中；10 秒自动停止后保留结果。
- 选择设备后允许连接；连接期间禁用重复连接和扫描。
- 收到协议快照后先保存为 `pendingData`，100 ms UI 定时器读取最新值并刷新。
- 超过 2 秒未收到新支持帧时状态附加“数据等待中”，但不主动断开。
- 演示模式开启时状态必须包含“演示模式”，设备列表和真实连接操作禁用。
- 关闭窗口时自动停止演示、扫描和 BLE 连接。

## 11. 错误处理

- 蓝牙适配器不可用、扫描失败、连接失败、目标服务缺失、特征缺失和通知订阅失败：状态栏显示错误，`errorOccurred` 保留完整原因，不崩溃。
- 用户未选择设备点击连接：保持当前状态并显示“请先选择设备”。
- 重复扫描或断开：操作幂等，不崩溃。
- 协议噪声和分包：由缓存恢复，不弹窗。
- 真实 BLE 错误不会自动切换到演示模式。
