# 可活动骨架手模 Demo 设计文档

## 1. 背景与目标

本项目在 `Document/Update/Research/可活动骨架的分析/` 内建立一个完全独立的 Qt 6 + C++ 原型，用于加载、显示和调试 `3D带骨架手模.fbx`。Demo 提供相机控制、骨骼可视化与选取、受人体工程学约束的关节旋转，以及面向“掌心一个 IMU、五指各一个 IMU”的六路姿态输入接口和模拟器。

首版不连接真实 IMU，不提供医学级生物力学模型，不允许任意平移子骨骼，不修改仓库主工程。

## 2. 决策依据与当前资产

- 原始需求：`archived/REQ_20260729_可活动骨架手模Demo.md`。
- 已回复问题：`archived/QL_202 60729_可活动骨架手模Demo_已回复.md`。
- 源模型：仓库只读路径 `Document/3D Model/3D带骨架手模.fbx`，Git 对象大小 48,904,668 字节。
- 诊断方法：Qt 6.8.3 `balsam.exe` 在 `outputs/model_probe/` 内成功转换模型，退出码为 0。
- 诊断结论：模型含 20 个蒙皮关节、5 条从公共根骨骼分出的手指链、5 个末端节点、多个蒙皮网格、无内置动画。
- 骨骼名称为通用 `Bone`、`Bone.001` 至 `Bone.019`，不能只靠名称判断手指语义，必须使用显式映射配置。
- 已确认五条候选手指链为：`Bone.001 -> Bone.011 -> Bone.012 -> Bone.013`、`Bone.002 -> Bone.008 -> Bone.009 -> Bone.010`、`Bone.003 -> Bone.005 -> Bone.006 -> Bone.007`、`Bone.004 -> Bone.014 -> Bone.015 -> Bone.016`、`Bone.017 -> Bone.018 -> Bone.019`。前四条包含一个从掌部延伸的基部骨骼和三个指节控制骨骼，最后一条为三骨骼链；具体对应拇指、食指、中指、无名指、小指仍需结合渲染位置确认。
- FBX 引用的外部纹理缺失，原路径指向其他机器；首版使用可配置纯色材质和基础光照，不把缺失纹理视为加载失败。

## 3. 技术栈与隔离

- 平台：Windows，MSVC 2022，Qt 6.8.3。
- 构建：研究目录内独立 CMake 工程。
- UI：Qt Widgets。
- 渲染：`QOpenGLWidget`、OpenGL 3.3 Core、GLSL 330。
- 模型导入：Assimp；CMake `FetchContent` 固定版本，源码和构建缓存只能位于研究目录。
- 数学类型：Qt 的 `QVector3D`、`QQuaternion`、`QMatrix4x4`。
- 配置：Qt JSON。
- 测试：Qt Test；约束、姿态输入和骨架映射不依赖 OpenGL 上下文。

禁止修改根目录 `CMakeLists.txt`、`src/`、`tests/` 或其他研究项目。所有构建命令必须显式使用 `-S` 和 `-B`，其中 `-B` 指向本项目内的 `build/`。

## 5. 核心数据契约

### 5.1 导入数据

```cpp
struct VertexInfluence {
    std::array<int, 4> boneIndices{-1, -1, -1, -1};
    std::array<float, 4> weights{0, 0, 0, 0};
};

struct MeshData {
    QVector<Vertex> vertices;
    QVector<quint32> indices;
    int materialIndex{-1};
};

struct BoneData {
    QString name;
    int parentIndex{-1};
    QMatrix4x4 bindLocal;
    QMatrix4x4 inverseBind;
};

struct RiggedModel {
    QVector<MeshData> meshes;
    QVector<BoneData> bones;
    QMatrix4x4 globalInverse;
    QVector<MaterialData> materials;
};
```

每个顶点最多保留权重最大的四个骨骼影响，归一化后权重和必须在 `1 ± 1e-5` 内。零权重顶点绑定到根骨骼。导入器以 `Result<RiggedModel, ModelLoadError>` 形式返回，不抛出跨 UI 边界异常。

### 5.2 骨架运行状态

```cpp
struct JointLimit {
    QVector3D minDegrees;
    QVector3D maxDegrees;
};

struct JointPose {
    QVector3D eulerDegrees;
};

struct SkeletonPose {
    QVector<JointPose> localPoses;
};
```

运行时保留导入的绑定局部矩阵，仅将配置指定的局部解剖旋转叠加到绑定旋转。最终蒙皮矩阵为：

`skinMatrix[i] = globalInverse * globalPose[i] * inverseBind[i]`

其中 `globalPose` 按父节点优先顺序计算。子骨骼局部平移与缩放固定为绑定值，从结构上保证骨长不被拖动破坏。

### 5.3 六路姿态输入

```cpp
enum class ImuSlot { Palm, Thumb, Index, Middle, Ring, Little };

struct ImuSample {
    ImuSlot slot;
    QQuaternion orientation;
    qint64 timestampUsec{0};
    bool valid{false};
};

struct HandImuFrame {
    std::array<ImuSample, 6> samples;
};

class IHandPoseSource {
public:
    virtual ~IHandPoseSource() = default;
    virtual std::optional<HandImuFrame> poll() = 0;
};
```

四元数约定为右手坐标系中从传感器局部坐标到世界坐标的单位四元数，存储顺序使用 Qt `QQuaternion(scalar, x, y, z)`。首版模拟源按固定 60 Hz 产生单调时间戳数据。

掌心样本定义公共参考；手指观测使用：

`qRelativeFinger = inverse(qPalm) * qFinger`

真实设备阶段还需在两侧乘标定四元数，将传感器坐标映射到模型解剖坐标。首版以配置的恒等或固定轴修正矩阵模拟该步骤。

重要限制：单个手指只有远端一个 IMU，无法唯一恢复 MCP/PIP/DIP 三个关节角。Demo 从每个手指相对掌心的姿态中提取两个主要分量：屈伸和张合；绕手指纵轴的扭转暂时锁定。屈伸通过约束耦合分配到整条手指链，张合只施加到掌指基部。该结果是符合约束的近似姿态，不得声称重建了真实关节角。

## 6. 模型映射配置

`config/hand_rig.json` 至少包含：

```json
{
  "rootBone": "Bone",
  "palmBone": "Bone",
  "fingers": {
    "thumb":  { "bones": ["待可视化确认的候选链"] },
    "index":  { "bones": ["待可视化确认的候选链"] },
    "middle": { "bones": ["待可视化确认的候选链"] },
    "ring":   { "bones": ["待可视化确认的候选链"] },
    "little": { "bones": ["待可视化确认的候选链"] }
  }
}
```

开发阶段必须从第 2 节列出的五条候选链中，通过模型空间位置和逐链高亮逐一确认手指语义，不能仅按编号猜测。确认结果写入配置和开发完成报告；不得增加、遗漏或复用候选链。配置还应为每个关节记录：屈伸轴、外展轴、角度上下限、是否允许直接编辑、耦合系数和显示名称。配置引用不存在骨骼、重复骨骼或非父子连续链时，加载失败并显示具体字段路径。

## 7. 人体工程学约束

### 7.1 三级约束

1. **层级约束**：骨长、父子关系、绑定平移和缩放保持不变，只允许配置声明的局部旋转。
2. **关节限位**：每个可控关节对屈伸和允许的外展/内收轴执行角度截断；扭转默认锁定。角度值是工程近似、可配置，并在 UI 标注“非医学用途”。
3. **手指耦合**：六路模式下，每个手指远端相对掌心的主要屈曲分量映射成归一化 `curl ∈ [0,1]`，再按配置曲线分配给该链各关节；张合分量只作用于该链基部。普通四指可采用 MCP/PIP/DIP 最大屈曲比例约 `1.0/1.0/0.67`，拇指使用独立曲线。最终每个角仍再次经过关节限位。

关节手动编辑模式允许直接调整单关节，但仍经过层级和限位约束。六路模拟模式使用耦合约束，不使用自由 IK。

### 7.2 初始角度范围策略

设计不将某一组角度宣称为普遍人体真值。开发时提供保守默认值：普通手指 MCP 屈曲 `0°..90°`、PIP `0°..110°`、DIP `0°..80°`；MCP 外展按手指配置窄范围；拇指使用单独的掌指/指间范围。所有值存放在 JSON，不写死在渲染代码中，并在后续研究文档中补充公开资料来源。

### 7.3 输入异常

- 非单位四元数：模长可归一化时归一化；模长小于 `1e-6` 时判无效。
- 手指样本无效：保持该手指上一有效姿态，UI 标红；启动后从未有效则保持绑定姿态。
- 掌心样本无效：暂停全部 IMU 映射，保留上一有效姿态。
- 时间戳倒退：丢弃该帧并记录一次可诊断警告。
- 超限姿态：截断到约束边界，UI 显示受限状态，不允许矩阵产生 NaN。

## 8. 渲染设计

### 8.1 GPU 蒙皮

- 顶点属性：位置、法线、UV、4 个骨骼索引、4 个权重。
- 首版骨骼数 20，使用统一数组 `mat4 uBones[128]`，加载超过 128 个蒙皮骨骼时明确报错。
- 片元着色采用基础方向光、环境光和纯色材质；缺失纹理只产生警告。
- 深度测试、背面剔除、多重采样由 OpenGL 状态初始化统一配置。

### 8.2 骨架与选取

- 骨骼叠加层绘制关节点和父子连线，选中骨骼使用高亮色。
- 拾取采用 CPU 射线与关节球/骨骼胶囊相交，避免为选取增加离屏颜色缓冲。
- 只允许选取配置中标记为可编辑的骨骼。
- 旋转操纵器围绕所选关节显示允许轴；鼠标拖动转换为局部角度增量，再交给约束求解器。

### 8.3 相机

- 左键拖动空白区域：轨道旋转。
- 中键或 Shift+左键：平移。
- 滚轮：缩放。
- `F` 或工具栏按钮：模型适配并重置视角。
- 操纵器命中优先于相机手势。

## 9. UI 设计

主窗口由中央渲染视图、左侧骨骼树、右侧属性/约束面板和顶部工具栏组成。

- 骨骼树显示名称、父子关系、可编辑状态和当前选择。
- 属性面板显示绑定信息、三个局部角度、限位、是否触发截断。
- 模式选择：`手动关节`、`六路 IMU 模拟`。
- 模拟面板提供掌心及五指姿态控制、播放/暂停、重置和无效样本开关。
- 状态栏显示模型加载、缺失纹理、当前 FPS 和最近输入错误。
- 模型加载失败时窗口仍可启动，并显示错误对话框与状态信息。

## 10. 模块边界

- `import`：只负责 Assimp 到 `RiggedModel` 的转换与诊断。
- `motion`：骨架姿态、配置解析、约束、六路输入映射和模拟源；不得依赖 Widgets/OpenGL。
- `render`：GPU 资源、蒙皮、骨架叠加、拾取、相机。
- `ui`：窗口、面板、信号槽与用户反馈；不得实现约束公式。
- `app`：启动参数、模型路径解析和对象装配。

核心调用方向：`app -> ui -> render`，`ui -> motion`，`render -> import/core`。`motion` 不反向依赖 UI。

## 11. 开发顺序

- 工作包 A：独立工程、Assimp 导入、模型副本和诊断测试。
- 工作包 B：骨架配置、姿态状态、约束与六路输入核心。
- 工作包 A 与 B 在接口冻结后可并行，契约是第 5 节数据结构。
- 工作包 C：OpenGL 蒙皮、相机、骨架叠加、拾取和操纵器；依赖 A 的模型数据与 B 的姿态输出。
- 工作包 D：主窗口、骨骼树、属性面板、模拟器、错误展示和启动测试；依赖 A、B、C。

## 12. 错误处理

错误分为 `ModelLoadError`、`RigConfigError`、`RenderError` 和 `PoseInputError`。每个错误至少包含稳定错误码、面向用户的中文信息和技术详情。可恢复输入错误进入状态栏；模型、配置或着色器初始化失败时禁用编辑但保持窗口存活。任何错误不得静默回退到与配置不一致的骨骼映射。

## 13. 测试策略

- 单元测试：权重截断归一化、骨架拓扑、配置校验、角度截断、手指耦合、四元数归一化、相对姿态、无效/乱序输入。
- 导入测试：加载研究模型副本，断言存在网格、20 个蒙皮关节、有效父索引和归一化权重。
- OpenGL 冒烟：离屏或窗口上下文编译着色器并上传模型；若 CI 无图形环境则本机启动测试为强制证据。
- 启动测试：真实启动 Demo，执行模型显示、相机、选骨、关节拖动、六路模拟、重置和错误文件路径流程。

## 14. 设计限制与后续方向

- 六个单点 IMU 提供六路姿态，不等于能够唯一观测手部全部机械自由度。
- 模型骨骼仅有通用名称，首次映射需要人工可视化确认。
- 源纹理缺失，首版不恢复原外观。
- 真实 IMU 阶段需要协议适配、安装方向标定、时间同步、滤波、磁干扰处理和质量指标。
- 若后续要求拖动指尖或精确拟合六路姿态，应另行设计受约束 IK/优化求解器。
