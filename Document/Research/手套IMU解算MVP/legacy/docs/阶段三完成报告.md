## 7. 真实硬件测试（COM12，921600）

- 状态：**核心路径已通过（60 秒实测）**；静止姿态验证通过；转动/零位标定等需人工操作步骤留待阶段四由用户配合完成。
- 硬件：COM12（USB 串口，921600/8N1）。
- 测试方式：新增无头探针 `tools/serial_hardware_probe.cpp`（复用 `SerialDataSource → FrameStreamParser → SequenceGrouper → SixImuSolver` 真实链路），`--port COM12 --baud 921600 --duration 60`。
- 60 秒结果（EXIT_CODE=0，运行 60.2 s）：
  - 输入字节 1,797,504；有效帧 71,899；**CRC 错误 0**、长度错误 0、未知地址 0、丢弃字节 13（仅开头跨帧同步丢弃）。
  - 完整组 11,982、不完整组 0、重复地址帧 0。
  - 有效帧率 1198.1/s（≈200 Hz×6）、完整组率 199.7/s（≈200 Hz），与协议文档一致。
  - 六地址计数均衡：0x50–0x55 各 ≈11,983。
  - 六路姿态全部 valid=1、mode=NineAxis、四元数有限且单位化；端口正常关闭。
- 观察项（符合设计 §11.3 预期）：六路 status 均显示「时间步异常已修正为 0.005 s」——真实串口经 USB 突发投递，组到达时间戳无法反映真实 200 Hz 采样间隔，dt 依设计回退到标称 0.005 s；对 200 Hz 设备而言该标称值即为正确采样周期。
- 遗留：转动各传感器验证对应姿态方向变化、静止→转动→静止 60 秒动作序列、零位标定与小幅度动作，均需用户物理操作手套，留待阶段四配合完成。

## 8. 阶段三决策记录（MainAgent）

以下为阶段三执行中由 MainAgent 自行决策或跨 SubStage 固化的契约，供阶段四验收追溯：

1. **沙箱 AUTOMOC 阻断的工程化规避**：DSH 沙箱禁止 CMake AUTOMOC 在深层（MSBuild 子进程链）用 libuv 派生 `moc.exe`（报 `libuv process spawn failed: operation not permitted`）。方案：`CMakeLists.txt` 设 `CMAKE_AUTOMOC OFF`，改为 configure 阶段直接调用 `moc.exe` 生成 `moc_*.cpp` 与测试 `*.moc`（浅层派生可用），再正常编译。所有 SubStage 与最终统一构建均据此通过。README 已记录该环境限制。
2. **跨 SubStage CRC 契约**：固定 `namespace SixImuProtocol { quint16 crc16Modbus(QByteArrayView bytes); }`（初值 0xFFFF、多项式 0xA001、前 23 字节、低字节在前）。SubStage 3 的 `DemoDataSource` 复用该函数生成合法 CRC。
3. **全零帧语义澄清**：全零帧为「逐传感器软条件」——该路不更新滤波器、保留上一四元数并标记 `valid=false`/`sourceAllZero=true`，其余五路照常更新并整组提交；「硬错误」（非法 dt、gyro/acc 非有限、四元数不可归一）才触发六路原子回滚。据此实现，符合需求 §5.1.5 与设计 §11.3。
4. **测试隔离**：UI 测试的临时 `QSettings` 使用工程/build 目录内 INI（沙箱禁止写系统临时目录），不污染生产 `SlimeVRResearch/SixImuSolverQt` 设置。
