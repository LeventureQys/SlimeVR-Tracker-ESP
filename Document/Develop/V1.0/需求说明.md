# 需求说明

## 1. 背景

`Document\Research\手套IMU解算MVP` 已提供一套 Windows Qt 六 IMU 实时解算方案。该方案通过 `921600/8N1` 串口接收手腕、拇指、食指、中指、无名指和小指六路九轴原始数据，完成帧同步、CRC16、同 `SEQ` 分组、Madgwick 六轴/九轴融合以及单位四元数输出。

当前需要评估并实施：将该模组解算后的六路姿态数据接入本 SlimeVR 开源项目，作为手套传感器输入，并重点改善设备静置时的航向漂移。

## 2. 评审结论

### 2.1 接入可行性

接入可行，现有工程与六 IMU 模组在数据模型上高度匹配：

- 六 IMU 模组能够稳定提供约 `200 Hz × 6` 的原始数据；
- MVP 已能够输出六路独立单位四元数；
- 当前工程支持一个设备注册多个传感器；
- 当前工程支持手腕及左右手各手指骨骼位置；
- 当前工程可通过 `Sensor::setFusedRotation()` 和既有 SlimeVR UDP 协议上报姿态；
- 当前 Windows 链路已经跑通，适合先在 Windows 端完成接入与算法验证。

首版推荐在 Windows 端复用现有串口、协议解析和六路分组链路，增加 SlimeVR 网络输出适配器。待姿态、坐标系、节点映射及漂移指标验证通过后，再决定是否移植到 ESP 固件。

### 2.2 当前算法限制

当前 MVP 已使用磁场参与 Madgwick 九轴融合，但尚未实现真正的磁力计校准。

当前已经具备：

- 磁场有效时运行九轴融合；
- 磁场无效时退化为六轴融合；
- 磁场比例和模长阈值配置；
- 六路姿态零位标定。

当前尚不具备：

- 每颗 IMU 独立的硬铁偏置校准；
- 每颗 IMU 独立的软铁缩放和椭球校准；
- 三轴非正交修正；
- 静止陀螺仪零偏估计；
- 陀螺仪温漂补偿；
- 磁场方向突变、磁倾角和动态磁干扰拒绝；
- 六套校准参数的持久化管理。

“六路零位标定”只记录当前姿态参考，不属于磁场校准，也不能从根本上消除后续航向漂移。

## 3. 开发目标

### 3.1 必须目标

1. 在 Windows 下保持现有六 IMU 串口链路正常工作；
2. 将六路姿态作为一个 SlimeVR 手套设备的六个传感器输入；
3. 支持左手和右手配置；
4. 明确定义六路地址、SlimeVR Sensor ID 和骨骼位置映射；
5. 完成四元数顺序、坐标轴、旋转方向及左右手系转换；
6. 增加可量化的静置漂移测试和数据记录；
7. 增加每路陀螺仪静止零偏估计；
8. 增加每路磁力计硬铁和软铁校准；
9. 磁场异常时自动拒绝磁场修正，避免错误航向跳变；
10. 对比 Madgwick 与当前项目 VQF 的实际漂移表现；
11. 选择并固化稳定性更好的最终融合路径；
12. 提供自动化测试、真实设备测试和可复核的验收报告。

### 3.2 期望目标

- 支持保存和加载六路独立校准参数；
- 显示每路融合模式、磁场健康状态、陀螺零偏和数据频率；
- 支持原始数据及姿态数据录制，便于离线回放和算法对比；
- 支持不连接真实硬件时使用录制文件重复验证；
- 为后续 ESP 嵌入式移植提供无 Qt 依赖的纯 C++ 算法核心。

### 3.3 首版范围外

- 根据单个指尖 IMU 推算 MCP、PIP、DIP 三段完整手指关节角；
- 三维手模渲染；
- 多副手套同时接入；
- 修改六 IMU 模组内部固件；
- 在 Windows 版本验证完成前直接进行完整 ESP 固件移植。

## 4. 数据与节点映射

首版六路地址固定为：

| 模组地址 | 语义 | SlimeVR 建议位置 |
| --- | --- | --- |
| `0x50` | Wrist 手腕 | `LEFT_HAND` 或 `RIGHT_HAND` |
| `0x51` | Thumb 拇指 | `THUMB_DISTAL`，最终以实际安装段为准 |
| `0x52` | Index 食指 | `INDEX_DISTAL`，最终以实际安装段为准 |
| `0x53` | Middle 中指 | `MIDDLE_DISTAL`，最终以实际安装段为准 |
| `0x54` | Ring 无名指 | `RING_DISTAL`，最终以实际安装段为准 |
| `0x55` | Pinky 小指 | `LITTLE_DISTAL`，最终以实际安装段为准 |

六路传感器只能直接表示六个安装节点。不得在没有骨骼约束模型的情况下，将一个指尖 IMU 伪装成同一手指的多个独立关节传感器。

## 5. 漂移问题说明

航向漂移不是由“显示或使用航向角”本身造成的。

- 加速度计能够利用重力长期约束 Roll 和 Pitch；
- 重力无法观测水平面方向；
- 六轴融合的 Yaw 依赖陀螺积分，因此会受到零偏累积影响；
- 九轴融合使用磁场提供航向参考，理论上能够抑制长期漂移；
- 未校准或受干扰的磁场可能造成航向缓慢偏移、抖动或跳变。

因此，本版本必须同时处理陀螺仪零偏和磁场质量，不能只通过调整 Madgwick `beta` 或执行姿态零位来掩盖问题。

## 6. 总体技术方案

```text
六 IMU 模组串口
    ↓
SerialDataSource
    ↓
FrameStreamParser：AA55、长度、CRC16、九轴解析
    ↓
SequenceGrouper：同 SEQ 六路原子快照
    ↓
每路传感器校准
    ├─ 陀螺静止零偏
    ├─ 加速度基础检查
    └─ 磁场硬铁/软铁矩阵
    ↓
Fusion Backend
    ├─ Madgwick 作为基线
    └─ VQF 作为重点候选
    ↓
坐标系与安装旋转转换
    ↓
SlimeVR Windows 输出适配器
    ↓
SlimeVR Server
```

融合算法与 SlimeVR 输出层必须解耦，以便使用同一份录制数据对不同算法进行离线对比。

## 8. 初始验收指标

以下指标作为开发初始门槛，最终可根据首轮真实数据调整，但调整必须记录原因。

### 8.1 链路指标

- 串口：`921600/8N1`；
- 六路完整组率：目标约 200 组/秒；
- 连续运行 30 分钟无崩溃；
- 正常链路下 CRC 错误率接近 0；
- pending 分组和串口缓存保持有界；
- SlimeVR 网络发送建议 50–100 Hz，可配置。

### 8.2 数值稳定性

- 所有输出四元数均为有限值；
- 四元数范数误差不超过 `1e-4`；
- 静止时不得持续出现明显姿态跳变；
- 磁场拒绝与恢复过程中不得产生不可接受的瞬时旋转。

### 8.3 漂移指标

分别记录每颗 IMU，不只记录六路平均值：

- 基线：记录当前算法 10 分钟静置总 Yaw 漂移；
- 优化目标：最终方案的 10 分钟静置 Yaw 漂移至少比当前基线降低 70%；
- 九轴正常磁场目标：10 分钟绝对 Yaw 漂移优先控制在 `3°` 以内；
- 若现场磁环境无法满足绝对指标，必须报告六轴、九轴、校准前后及干扰状态的独立结果；
- 不允许通过周期性强制归零隐藏漂移。

## 10. 主要风险与应对

### 10.1 硬件量程不明确

风险：默认 `±16g`、`±2000°/s` 和磁场 `/120` 可能与真实寄存器配置不一致。

应对：取得模组芯片型号和寄存器配置；在无法取得时，通过静止重力、已知角速度动作和原厂资料交叉验证。

### 10.2 磁环境复杂

风险：手套周围电子设备和金属结构会污染磁场，九轴算法可能得到错误航向。

应对：每路独立校准、磁场健康检测、迟滞退化和受限恢复；保留六轴安全路径。

### 10.3 六路安装差异

风险：即使 PCB 宣称同向，实际装配仍可能存在旋转、镜像或轴符号差异。

应对：逐路执行固定动作验证，允许配置每路固定安装旋转，但不使用任意经验修正掩盖错误。

### 10.4 算法过度依赖参数调节

风险：只调整 `beta` 可能对一组数据有效，却在其他运动或磁环境失效。

应对：使用录制回放、统一指标和多场景测试选择参数，不以单次人工观感作为结论。

### 10.5 Windows 与固件结果不一致

风险：后续移植可能因浮点精度、时间步或四元数顺序不同产生差异。

应对：先拆分纯 C++ 核心，使用相同固定数据集做逐帧或最终角误差对照。

## 11. 开发原则

- 先测量、再优化，不以主观观感代替漂移数据；
- 磁场校准、姿态零位和 SlimeVR 校准必须明确区分；
- 所有六路校准状态必须相互独立；
- 算法失败不得输出 NaN 或未归一化四元数；
- 磁场异常属于可退化条件，不应导致程序崩溃；
- 协议解析、传感器校准、姿态融合和网络输出保持模块化；
- Windows 版本通过验收前，不开始完整嵌入式移植；
- 所有性能和漂移结论必须保留原始数据与可复核报告。
