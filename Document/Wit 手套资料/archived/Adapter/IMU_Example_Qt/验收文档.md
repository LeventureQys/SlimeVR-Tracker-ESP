# IMU Example Qt v0.1.0 验收文档

## 1. 验收范围

### 覆盖

- 独立 CMake 工程配置和全量构建。
- WIT 数据流解析的正常、边界和异常输入。
- Qt Widgets 数值展示和演示模式。
- BLE 扫描、单设备连接、通知订阅和周期寄存器读取。
- 文档、目录和范围约束。

### 不覆盖

- Android 原项目回归。
- 多设备并发连接和时间同步。
- 设备配置、校准、三维显示、图表和数据记录。
- 非 WIT 或非指定 UUID 的传感器兼容性。

## 2. 验收环境

- 操作系统：Windows 10/11 x64。
- 编译器：支持 C++17 的 MSVC。
- CMake：3.20 或以上。
- Qt：Qt 6，已安装 `Core`、`Widgets`、`Bluetooth`、`Test`。
- 自动测试：无需 BLE 硬件，使用 QtTest 和演示模式。
- 硬件测试：需要可用 BLE 适配器及名称以 `WT` 开头、提供设计文档 UUID 和帧协议的 WIT 设备。

## 3. 前置条件

- 当前目录为 `Document/Update/Research/可活动骨架的分析/Adapter/IMU_Example_Qt`。
- Qt 的 CMake 包可被 `CMAKE_PREFIX_PATH` 或 Qt 命令行环境发现。
- 构建目录使用 `build`，不得复用仓库根构建目录。
- 真实硬件测试前确认设备已开机、未被其他主机连接且 Windows 蓝牙已开启。

## 4. 证据要求

- 配置、构建和测试保存完整命令、退出码及摘要。
- 启动测试记录可执行文件路径、启动时间、操作步骤、进程退出方式和标准错误中的 Qt warning/critical。
- 真实硬件测试记录设备显示名、地址或 UUID、状态变化和至少两组不同时间的实时值；可附截图。
- 无硬件时，硬件相关项标记“阻塞”，写明缺少的硬件条件，不得标记通过。

## 5. 验收项

### A1. 独立配置
- 目的：确认项目不依赖仓库根构建。
- 前置条件：Qt 6 环境可用。
- 操作步骤：执行 `cmake -S . -B build -DBUILD_TESTING=ON`。
- 期望结果：配置成功，找到 Qt Core、Widgets、Bluetooth 和 Test，生成 `IMUExampleQt` 与两个测试目标。
- 通过标准：命令退出码为 0，无缺失源文件或目标重名错误。
- 失败标准：配置失败或要求修改仓库根 CMake。
- 证据要求：配置命令及末尾摘要。

### A2. 全量编译
- 目的：确认所有交付代码可编译。
- 前置条件：A1 通过。
- 操作步骤：执行 `cmake --build build --config Debug -j8`。
- 期望结果：应用和测试目标全部生成。
- 通过标准：退出码为 0，无编译错误。
- 失败标准：任一目标未生成或编译失败。
- 证据要求：构建摘要和目标文件路径。

### A3. 协议单元测试
- 目的：验证真实数据换算和流恢复。
- 前置条件：A2 通过。
- 操作步骤：执行 `ctest --test-dir build -C Debug --output-on-failure -R wit_protocol`。
- 期望结果：正常帧、正负值、分包、粘包、噪声、电量边界、版本和 reset 测试全部通过。
- 通过标准：测试退出码为 0，失败数为 0。
- 失败标准：任一断言失败、崩溃或超时。
- 证据要求：CTest 完整摘要；失败时附具体用例。

### A4. UI 单元测试
- 目的：验证实时快照能按格式展示。
- 前置条件：A2 通过。
- 操作步骤：设置 `QT_QPA_PLATFORM=offscreen` 后执行 `ctest --test-dir build -C Debug --output-on-failure -R main_window`。
- 期望结果：控件对象名、15 行数据表、只读属性、数值单位和演示状态测试通过。
- 通过标准：测试退出码为 0，失败数为 0。
- 失败标准：控件缺失、格式错误、状态矛盾或崩溃。
- 证据要求：CTest 摘要。

### A5. 应用启动
- 目的：验证程序可正常进入事件循环并退出。
- 前置条件：A2 通过。
- 操作步骤：启动 Debug 输出目录中的 `IMUExampleQt.exe`，等待主窗口显示，保持 2 秒后正常关闭。
- 期望结果：窗口显示设备操作区、状态和 15 行数据表；无崩溃。
- 通过标准：进程正常启动和退出，无 Qt fatal/critical。
- 失败标准：窗口不出现、立即退出、卡死或崩溃。
- 证据要求：可执行文件路径、操作记录和日志片段。

### A6. 演示模式核心路径
- 目的：在无硬件时验证实时展示数据链路。
- 前置条件：A5 窗口已启动。
- 操作步骤：开启“演示模式”，观察至少 2 秒，记录两次相隔至少 500 ms 的数据，然后关闭演示模式。
- 期望结果：状态明确包含“演示模式”；帧计数持续增加；加速度、角度等至少一个值发生变化；真实扫描和连接操作禁用。
- 通过标准：全部期望可观察且关闭演示后操作恢复。
- 失败标准：数值不变、演示标识缺失、真实连接仍可触发或程序异常。
- 证据要求：两次数据记录或截图、操作记录。

### A7. BLE 扫描筛选
- 目的：验证真实 BLE 发现流程。
- 前置条件：兼容设备和 BLE 适配器可用。
- 操作步骤：点击扫描，观察 10 秒。
- 期望结果：列表仅出现名称以 `WT` 开头的设备，同一设备不重复；扫描到时可在 10 秒内手动停止或自动停止。
- 通过标准：筛选、去重和停止行为全部符合预期。
- 失败标准：兼容设备可被其他工具发现但本程序无结果，或列表包含非 `WT` 设备、重复设备。
- 证据要求：设备名称、地址/UUID、列表截图或记录。无设备时标记阻塞。

### A8. BLE 连接与订阅
- 目的：验证指定 GATT 服务和通知订阅。
- 前置条件：A7 发现兼容设备。
- 操作步骤：选择设备并连接，观察状态直到“已连接”。
- 期望结果：依次完成连接、服务发现、通知订阅；不出现服务或特征缺失错误。
- 通过标准：进入 Connected 状态，断开按钮可用。
- 失败标准：目标设备协议兼容但连接、发现或 CCCD 订阅失败。
- 证据要求：状态变化记录和错误日志。无设备时标记阻塞。

### A9. 真实实时数值
- 目的：验证真实通知解析和寄存器读取。
- 前置条件：A8 通过。
- 操作步骤：保持连接至少 5 秒并轻微转动设备，记录两组数值。
- 期望结果：帧计数增加；姿态字段随运动变化；磁场、电量、温度或版本在轮询后显示；更新时间持续刷新。
- 通过标准：至少姿态帧持续更新，且四类轮询字段中至少一类收到有效返回；未返回字段需结合设备型号记录。
- 失败标准：通知已订阅但 5 秒内无任何支持帧，或解析值为非有限数。
- 证据要求：两组时间、数值、帧计数和设备信息。无设备时标记阻塞。

### A10. 断开与资源清理
- 目的：验证生命周期稳定性。
- 前置条件：A8 通过或处于扫描/演示状态。
- 操作步骤：分别测试停止扫描、关闭演示、断开设备并关闭窗口。
- 期望结果：所有状态停止，应用正常退出，无退出崩溃或后台残留进程。
- 通过标准：每个停止操作幂等，重复点击不崩溃。
- 失败标准：退出崩溃、仍在轮询、残留进程或悬空对象错误。
- 证据要求：操作记录和进程退出结果。

### A11. 范围与交付物
- 目的：确认实现没有扩边界且文档齐全。
- 前置条件：代码开发完成。
- 操作步骤：检查目录、界面和 Git diff。
- 期望结果：存在设计规定的代码、测试和 README；无三维、图表、动画、恢复出厂、校准或配置控件；仓库根工程和 Android 原项目未修改。
- 通过标准：交付物齐全且所有禁止项未发生。
- 失败标准：缺文档/测试，或存在范围外功能和非目标文件修改。
- 证据要求：文件列表和 diff 摘要。

## 6. 回归范围

- Android 参考项目保持字节级未修改，仅作为协议依据。
- 仓库根主应用不接入本工具，执行 `git diff` 确认没有根 CMake 和 `src/` 变更即可完成隔离回归。
- 不要求运行仓库根应用全量测试，因为独立工程没有链接或修改其代码。

## 7. 失败与阻塞处理

- 配置或编译失败：退回阶段三对应 SubStage，最多修复重试 3 次。
- 单元测试失败：不得进入启动测试结论，先修复协议或 UI。
- 启动失败：退回界面与集成 SubStage。
- 有兼容硬件但真实 BLE 失败：记录 Qt/系统错误、设备信息和失败状态后退回 BLE SubStage。
- 没有硬件或 BLE 适配器：A7 至 A10 中依赖硬件的部分标记“阻塞”，追加阶段三问题清单；不得视作通过。
