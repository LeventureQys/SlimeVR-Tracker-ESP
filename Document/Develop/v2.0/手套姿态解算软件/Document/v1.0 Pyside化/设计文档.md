# 设计文档 —— v1.0 PySide 桌面化

- 版本：v1.0（目录 `Document/v1.0 C++化/`，命名历史遗留，本版实际为 PySide 化）
- 需求：`Document/v1.0 C++化/需求说明.md`
- 阶段：阶段二·设计（已通过阶段一门禁：Q1 按 Python+PySide6、Q2 按 QOpenGLWidget 自绘渲染）

## 1. 背景与目标

当前上位机 = Python HTTP 服务（`tools/serve_app.py` + `tools/processed_pipeline.py`）+ Three.js 网页前端（`web/`）。本版目标：

1. **去掉 web 端**：浏览器界面替换为 PySide6 桌面应用；HTTP/SSE 服务从运行路径上移除。
2. **显示效果与 web 端保持一致**：三维人手（真实蒙皮左手模型 + 骨骼覆盖层 + 网格 + 光照/雾/色调）、五指 bend/sway 读数条、选中手指角度曲线、串口交互、状态徽章全部 1:1 复刻。
3. **串口数据链路不变**：主控 MCU 31 字节×6 姿态帧协议、CRC16-Modbus、按 sequence 聚合、重新标定命令原样保留；`tools/processed_pipeline.py` 零改动。
4. 3D 渲染技术：**PySide6 6.10.3 + QOpenGLWidget 自绘 OpenGL**（选型证据与验证记录见问题清单 Q2）。

## 3. 技术选型（已定）

- **UI 框架**：PySide6 ==6.10.3（锁定；6.11 已移除 Qt3D 绑定且是后续版本风险源）。Python 3.9+（开发机实测 3.14.4，cp39-abi3 正常）。
- **3D 渲染**：`QOpenGLWidget` + 自写 OpenGL（GLSL 1.50 core）：自写 glTF2 解析（资产固定且简单）+ GPU 蒙皮 + Blinn-Phong 多光源 + 指数雾 + ACES 近似 + 轨道相机。**禁用 Qt3D/QtQuick3D**（实测阻断性缺陷，见问题清单 Q2 证据）。
- **曲线**：QtCharts（PySide6 6.10.3 内置，已验证）。
- **测试**：pytest；渲染层由启动测试覆盖（GL 无法 headless）。
- 第三方依赖仅 `pyserial==3.5`、`PySide6==6.10.3`、`pytest`。

### 线程模型

- 串口/模拟数据线程（daemon）：读字节 → 解析 → 入队（同现网逻辑，`serve_app.py` 205–227 行）。
- Qt 主线程：QTimer(33ms) `drain_frames()` 批量取帧 → 曲线逐帧追加（400 帧窗口）→ 最后一帧驱动 3D 手 + 读数面板；QTimer(250ms) 轮询 `status_dict()` 更新状态 UI。
- 无信号跨线程：会话层保持纯线程 + 队列（与现网一致），UI 侧只做轮询式拉取。

## 5. 关键算法移植规格（与 web 端逐行对应）

### 5.1 基变换（`hand-model.js` 22–43 行）

- `C = Rz(-90°)`（轴 (0,0,1)、角 -π/2）。
- 显示四元数 `q_h = C ⊗ q_a ⊗ C⁻¹`，其中 `q_a = QQuaternion(x,y,z,w)`（输入 Hamilton [w,x,y,z] 重排为 Three.js 构造序），结果归一化。
- 效果：算法 +X → 模型 -Y、算法 +Y → 模型 +X、Z 不变。

### 5.2 模型根变换（`hand-model.js` 153–169 行）

- 旋转 `R = fingersUp ⊗ faceCamera`，`fingersUp = Rz(π)`，`faceCamera = Ry(-π/2)`（three multiply 语义：`fingersUp.multiply(faceCamera)`）。
- 缩放 `s = 7.05 / max(dim(R·bbox))`，`bbox` = 蒙皮网格顶点（bind 姿态）经 R 旋转后的 AABB。
- 平移 `t = -center(S·R·bbox) + (0, 0.35, 0)`。
- 根矩阵 `M = T(t) ⊗ R ⊗ S(s)`（均匀缩放与旋转可交换，等价 web 的 position/rotation/scale 组合）。

### 5.3 关节链与握拳映射（`hand-model.js` 18–19、29、197–303 行）

- `FINGER_ORDER = (thumb, index, middle, ring, little)`；
- 关节名前缀 `MODEL_PREFIX = {thumb:'thumb', index:'index-finger', middle:'middle-finger', ring:'ring-finger', little:'pinky-finger'}`；
- 必需关节 25 个：`wrist` + 每指 `-metacarpal`、`-phalanx-proximal`、`-phalanx-intermediate`（拇指无）、`-phalanx-distal`、`-tip`；
- 满握拳完成度参考值 `FULL_FIST_BEND_DEG = {thumb:85, index:155, middle:160, ring:120, little:145}`；
- 链：拇指 `[metacarpal, proximal, distal, tip]`，pivotIndex=0；长指 `[metacarpal, proximal, intermediate, distal, tip]`，pivotIndex=1；链方向 = rest(pivot+1) − rest(pivot) 归一化；
- `palmNormal = acrossPalm × alongPalm`，`acrossPalm = littleMeta−indexMeta` 归一化，`alongPalm = middleProximal−middleMeta` 归一化（rest 位置）；
- `bendCompletion = clamp(bendDeg / FULL_FIST[finger], 0, 1)`；`sway = degToRad(clamp(swayDeg, -30, 30))`；
- 每关节弯曲角（负号，左手向掌心弯）：拇指 `[38, 52, 62]°`，长指 `[75, 100, 55]°`，各自 × bendCompletion；
- 轴：长指 bend 轴 = `direction × palmNormal`，sway 轴 = `palmNormal`；拇指交换（bend 轴 = palmNormal，sway 轴 = direction × palmNormal）；
- 姿态递推（与 JS 260–303 行逐语句对应）：
  ```
  swayRotation = Q(swayAxis, sway)
  firstBend = Q(swayRotation·bendAxis, jointBends[0])
  accumulated = firstBend ⊗ swayRotation
  pivot.localQuat = accumulated ⊗ rest(pivot)
  prevPos = rest(pivot)
  for i in pivot+1 .. len-1:
      restVector = rest(name_i) − rest(name_{i−1})
      joint.position = prevPos + accumulated.rotate(restVector)
      joint.localQuat = accumulated ⊗ rest(name_i)
      prevPos = joint.position
      if i−pivot < len(jointBends):
          accumulated = Q(accumulated·bendAxis, jointBends[i−pivot]) ⊗ accumulated
  ```
- `applyPose`：先恢复全部 rest 局部 TRS，再逐指 apply，最后根四元数 = 5.1 的 `q_h`；所有关节 world 矩阵由节点父子链（含 Armature 局部 TRS）递推。
- 输出 `HandPoseResult`（见 6.2）。

### 5.4 蒙皮公式（正确性核心）

- `skinMatrix_j = jointWorld_j × invBind_j`（glTF 规范式；invBind 为 GLB skin 中原始数据）。
- 顶点 `skinnedPos = Σ_j w_j · skinMatrix_j · v`（法线用 3×3 旋转部分，按权重归一化）。
- **bind 姿态不变性测试（硬门禁）**：bind 姿态下 `Σ w_j·jointWorldBind_j·invBind_j = M_bind·T_armature`，即蒙皮顶点必须精确还原为原始顶点经根变换后的位置（逐顶点数值断言，误差 < 1e-4）。若该测试失败，改用 three.js 等价式 `jointWorld_j × (jointWorldBind_j)⁻¹ × meshWorldBind`（任务书已给出备选式）。
- 网格节点 `l_handMeshNode` 局部 TRS 应为单位（测试断言）；非单位时公式中 `v ← meshNodeLocal·v`。

### 5.5 骨骼覆盖层（`hand-model.js` 218–244、323–337 行）

- 19 段骨（拇指链 3 段 + 4 长指各 4 段）：单位圆柱（半径上 0.075/下 0.06、高 1、14 段）→ 位置 = 两端点中点，旋转 = +Y 到方向的最短弧，缩放 (1, len, 1)。
- 25 个关节球：腕 0.13、其余 0.095（16×12 段）。
- 端点 = 各关节 scene 空间 world 位置（含根变换与当前姿态）。
- 软组织开关只隐藏蒙皮，覆盖层始终可见。

### 5.6 场景参数（`viewer.js` 36–74、218–223、400–420 行）

- 相机：fov 34、near 0.1、far 100、默认位置 (-4.2, 0.7, 12.2)、目标 (0, 0.3, 0)、min 距离 7.2、max 18、阻尼系数 0.07（指数趋近）、pixelRatio = min(devicePixelRatio, 2)。
- 轨道交互：左键旋转、滚轮缩放、右键平移；重置视角 = 恢复默认位置/目标。
- 灯光：半球 (sky 0xc8e1ff / ground 0x17202b, 2.0) + 主方向光 (0xfff2dd, 4.4, 位置 (-4.5,3.5,7.5)) + 轮廓光 (0x79aaff, 3.0, (5.5,-1.5,4.5)) + 点补光 (0x49d9d0, 1.7, (-3,-3,3), 距离 12)。
- 雾：FogExp2 颜色 0x080d15、密度 0.035，所有材质生效。
- 色调映射：ACES（Narkowicz 近似）+ 曝光 1.12，sRGB 输出。
- 网格：10×10、20 分割，绕 X 转 90° 平放于 z=-1.2，颜色 0x29435b/0x172537，opacity 0.34，混合。
- 材质：皮肤 baseColor 0xd9bca4、roughness 0.58、opacity 0.43、双面、depthWrite off；骨骼 0xf0dfbd（roughness 0.62）；关节球 0xcdb28a（roughness 0.72）。

### 6.1 GltfAsset（SS1 产出 `app/gltf/loader.py`，SS2 消费）

```python
@dataclass
class GltfNode:
    name: str
    children: list[int]                # 节点索引
    translation: tuple[float, float, float]   # 缺省 (0,0,0)
    rotation: tuple[float, float, float, float]  # Hamilton (w,x,y,z)，缺省 (1,0,0,0)
    scale: tuple[float, float, float]         # 缺省 (1,1,1)
    matrix: tuple[float, ...] | None          # 若节点用 matrix 表达（16 项行主序），否则 None

@dataclass
class GltfBufferAccessor:
    data: bytes                       # 顶点数据原始字节（含 byteOffset 截取后）
    component_type: int               # 5120/5121/5122/5123/5126
    count: int
    type: str                         # 'SCALAR'|'VEC2'|'VEC3'|'VEC4'|'MAT4'
    byte_stride: int                  # 0 表示紧凑

@dataclass
class GltfPrimitive:
    attributes: dict[str, GltfBufferAccessor]   # POSITION/NORMAL/TEXCOORD_0/JOINTS_0/WEIGHTS_0
    indices: GltfBufferAccessor
    mode: int

@dataclass
class GltfAsset:
    nodes: dict[str, GltfNode]        # 按名称索引（30 个全量）
    node_indices: dict[str, int]      # name → 节点索引
    scene_roots: list[int]
    mesh: GltfPrimitive               # 唯一 primitive
    skin_joint_names: list[str]       # 25 个关节名（skin.joints 索引顺序）
    skin_inverse_bind_matrices: list[tuple[float, ...]]  # 25×16 行主序，原始数据
    material_base_color: tuple[float, float, float, float]
    version: str                      # '2.0'
```

### 6.3 SerialLiveSession（SS1 产出 `tools/serial_live.py`，SS3/SS4 消费）

```python
class SerialLiveSession:
    def __init__(self) -> None
    def list_ports(self) -> list[dict]        # [{'device','description','hwid'}]（无 pyserial 抛 RuntimeError）
    def start(self, port: str, baud: int = 921600) -> None
    def start_demo(self) -> None              # 模拟数据源线程（见 6.4）
    def stop(self) -> None
    def request_calibrate(self) -> None       # 未连接抛 RuntimeError；demo 模式抛 RuntimeError('模拟数据源不支持标定')
    def status_dict(self) -> dict             # 同 serve_app.py 77–93 行 payload（phase/message/sample_count/output_frame_count/port/baud/hand_hz）
    def latest_frame(self) -> dict | None
    def drain_frames(self) -> list[dict]      # 非阻塞清空内部队列，返回帧列表（FIFO）
    @property
    def running(self) -> bool
```

行为与原版一致：`start()` 前先 `stop()`；标定命令 `AA 55 C0 01 00 00 + CRC16`（`build_recalibrate_command()`）；0.4s 标定窗口丢弃帧（`CALIBRATE_STALE_S` 模块常量）；串口异常 → phase='error' 并关闭串口。

### 6.4 DemoFrameSource（SS3 产出 `app/demo_source.py`）

- `def demo_frames(now_s: float, sequence: int) -> bytes`：按 AA55 协议产出 6 节点完整字节（31×6），CRC 正确。
- 脚本（t 为相对起始秒，确定性函数，可单测）：
  - 腕四元数：绕 +X 旋转 `a = 25°·sin(0.5t)` → `q = (cos(a/2), sin(a/2), 0, 0)`，time_s = 单调时钟；
  - 每指 bend_deg = `FULL_FIST_BEND_DEG[f] × (0.5 + 0.5·sin(0.8t + φ_f))`（φ 拇指 0、依次 +0.7），sway_deg = `20·sin(0.3t + φ_f + 1.1)`；
  - 手指四元数：绕 +X 旋转 `bend_rad` 的 wxyz（相对掌心）。
- 会话 `start_demo()` 以 200Hz 循环产出字节并送入 `_pose_assembler.push()`（与真实串口路径完全一致）。

- 视口叠加层（透明，不拦截鼠标，按钮除外）：左上"灵巧手上位机"标题区 + 状态徽章（状态点/场景状态/分隔线/FPS）；工具按钮行（重置视角/软组织/网格，后两者 checkable 默认开）；左下 X/Y/Z 轴图例（红 #ff7685/绿 #67dda0/蓝 #73aaff 圆标）。
- 右栏四节：有线串口（端口下拉含"模拟数据"项、波特率 115200/460800/921600/3000000、刷新端口/连接串口(primary 青底)/断开/重新标定、状态行）、当前帧（帧计数 + 2×2：时间/采样间隔/最大弯曲/最大侧摆）、五指角度（5 行可点选：名称 + bend 条 0~90° + sway 条 ±30° 居中双向 + 数值）、曲线（标题"X指曲线"、bend/sway 图例、-30~90 刻度、400 帧窗口、当前帧竖线）。
- 文案与 web 端一致（"等待数据""主控姿态控制""串口标定中""未连接/连接中/标定中/处理实时/错误"等）。
- 状态点：live/calibrating 时亮青色。
- 启动即刷新端口；仅一个真实端口时自动连接（复刻 `viewer.js` 303 行 autoConnect；有"模拟数据"项时不触发）。

## 9. 测试策略

- **单元测试（pytest，SS1–3 各自完成）**：
  - glTF 解析：30 节点、25 必需关节、skin 关节序、网格节点 TRS 为单位、数据字节数与 stride；
  - 四元数基变换：轴映射 X→-Y/Y→X/Z→Z、单位性、恒等；
  - 姿态映射：满握拳完成度、sway ±30° 钳制、关节角数值（拇指 [38,52,62] 等）、bind 姿态下皮肤矩阵不变性（5.4 硬门禁）、重复 apply 确定性；
  - 串口会话：合成 AA55 六节点流 → 恰 1 帧且字段正确；坏 CRC 跳过计数；标定命令字节精确；0.4s 窗口丢弃（`CALIBRATE_STALE_S` 注入）；stop 幂等；
  - CRC16 已知向量回归；
  - 模拟数据源：产出字节经 `ProcessedPoseAssembler` 解析后与脚本函数在 t 处逐值一致；
  - 面板纯函数：displaySwayDeg 符号、相位文案映射、frame_summary 数值。
- **启动测试（SS4 + 验收）**：真实窗口启动走核心路径（--demo 自动连模拟源 → 3D 手动起来 → 读数/曲线更新），截图证据（`--screenshot` 参数）；单实例 QLockFile 验证。
- **数值一致校验（验收）**：同源模拟帧下 web 端与桌面端读数/曲线逐帧比对（同一套公式移植，误差 < 1e-6）。

## 10. 风险与回退

| 风险 | 等级 | 缓解/回退 |
| --- | --- | --- |
| 蒙皮公式与 three.js 行为不一致 | 高 | 5.4 bind 不变性硬门禁测试；失败时按任务书备选式切换 |
| 目标机 OpenGL 驱动缺失 | 低 | 现代 Windows 均带；极端情况回退 QWebEngineView（验收降级选项） |
| QtCharts 渲染性能 | 低 | 400 点窗口 + 33ms 批量追加，量级远低于 QtCharts 能力 |
| 200Hz 帧率 UI 卡顿 | 低 | 批量 drain + 只渲染最新姿态；曲线保留全量索引语义 |
