# 单蓝牙 IMU 指尖联动验收文档

## 1. 验收范围

覆盖 WIT BLE 单设备扫描连接、协议实时解析、五指绑定选择、指尖临时零姿态校准、整链受约束映射、状态门禁、异常恢复、旧模式回归、单元测试和启动测试。

不覆盖多个真实 IMU、掌心参考、真实关节角恢复、医学精度、自动安装识别、滤波算法、自动重连、Linux/macOS 和主工程接入。

## 2. 验收环境

- Windows 10/11 x64，MSVC 2022。
- Qt 6.8.3：Core、Gui、Widgets、Bluetooth、OpenGL、OpenGLWidgets、Test。
- CMake 3.24 或兼容版本。
- 支持 OpenGL 3.3 Core 的桌面图形环境。
- 真实硬件项使用 `WT901BLE67` 或具有相同 WIT Service/Notify/Write UUID 与 `55 61`/`55 71` 协议的设备。
- 所有构建、日志、截图和输出位于研究项目内。

## 3. 前置条件

1. 完成工作包 E 与 F。
2. `config/hand_rig.json` 的五指映射已经可视化确认。
3. Windows 蓝牙开启，测试设备未被其他终端占用。
4. 测试者知道 IMU 在目标指尖上的朝向并能保持安装不滑动。

## 4. 验收项

### N01 - 目录隔离与独立构建

- 目的：证明功能未污染主工程。
- 操作步骤：检查 Git 变更；在研究目录执行 CMake configure 和 Debug build。
- 期望结果：所有本次文件和生成物位于研究项目内；生成应用和测试目标。
- 通过标准：命令退出码 0，研究目录外无本功能造成的变更。
- 失败标准：修改根工程或输出缓存到研究目录外。
- 证据要求：`git status --short`、构建命令和 `outputs/` 内日志。

### N02 - WIT 协议回归

- 目的：验证迁移后的解析能力不退化。
- 操作步骤：运行协议单元测试。
- 期望结果：正负姿态、分包、粘包、噪声、寄存器响应和帧计数测试通过。
- 通过标准：全部断言通过，无跳过。
- 失败标准：换算比例、帧同步或寄存器解析与 Adapter 参考实现不一致。
- 证据要求：CTest 输出。

### N03 - 状态门禁

- 目的：防止未准备数据驱动模型。
- 操作步骤：依次检查未连接、已连接未选手指、已选手指未校准、已校准、驱动中状态。
- 期望结果：仅校准成功后允许启用驱动；每个状态控件启用情况符合设计。
- 通过标准：不能绕过连接、绑定或校准前置条件。
- 失败标准：未校准即可驱动，或错误状态无法恢复。
- 证据要求：自动测试和各状态截图。

### N04 - 临时零姿态校准

- 目的：验证任意绝对安装朝向可归零。
- 操作步骤：连接设备，选择手指，在自然舒展姿态点击校准并观察首帧。
- 期望结果：保存当前姿态为 `qZeroRaw`，模型回到绑定姿态，启用驱动后首帧无明显跳变。
- 通过标准：数学测试输出接近单位相对旋转；人工观察无突然屈曲。
- 失败标准：校准后首帧产生明显非零动作或出现 NaN。
- 证据要求：单元测试、校准前后角度和截图。

### N05 - 五指绑定路由

- 目的：验证单设备可选择任意手指且不串位。
- 操作步骤：自动测试五个 fingerIndex；人工至少验证一根普通手指和拇指。
- 期望结果：只有目标链改变，其他链保持绑定姿态；换手指后校准失效。
- 通过标准：五个自动路由测试通过，人工两类手指无串位。
- 失败标准：同时修改多指、绑定错指或复用上一手指校准。
- 证据要求：测试输出、目标手指与模型截图。

### N06 - 指尖姿态整链耦合

- 目的：验证末端 IMU 的累计姿态按工程约束分配到整条链。
- 操作步骤：校准后执行目标手指屈伸与小范围张合。
- 期望结果：屈伸作用于整条链，张合只作用于基部；扭转不驱动；骨长和平移保持绑定值。
- 通过标准：动作连续、矩阵有限、约束测试通过，UI 标注近似性质。
- 失败标准：仅末节异常折动、任意平移、骨长变化或声称真实关节角。
- 证据要求：耦合角度、约束状态、前后截图和单元测试。

### N07 - 超限与异常姿态

- 目的：验证不可信输入不会破坏模型。
- 操作步骤：测试超范围旋转、零模、非有限值、倒退时间戳和超过 500 ms 无新帧。
- 期望结果：超范围被截断；无效帧被丢弃；超时停止驱动并要求重新校准。
- 通过标准：无崩溃、无 NaN，错误可诊断。
- 失败标准：模型爆炸、静默接受无效值或超时后自动恢复驱动。
- 证据要求：测试输出和状态日志。

### N08 - 断开、换指与重置

- 目的：验证安装关系变化时不会复用旧基准。
- 操作步骤：驱动中分别断开设备、切换手指和点击重置姿态。
- 期望结果：立即停止驱动并清除校准；模型回到绑定姿态；再次驱动必须重新校准。
- 通过标准：三条路径行为一致。
- 失败标准：保留旧校准、自动恢复或模型保持未知姿态。
- 证据要求：自动测试与操作记录。

### N09 - 实时数据分析面板

- 目的：保留 IMU Demo 的诊断能力。
- 操作步骤：连接设备并观察各字段更新。
- 期望结果：加速度、角速度、欧拉角、帧数、更新时间持续刷新；轮询后显示电量、温度和版本。
- 通过标准：数值有限且帧数递增，字段单位明确。
- 失败标准：模型能动但无原始数据诊断，或演示数据冒充真实数据。
- 证据要求：截图、设备名称和至少 5 秒帧数变化记录。

### N10 - BLE 错误恢复

- 目的：验证无设备和快速重连场景可诊断。
- 操作步骤：无设备时扫描；连接后关闭设备；立即重连一次，再等待数秒重试。
- 期望结果：窗口保持存活，断开后停止驱动；错误信息提示检查设备占用或等待后重试。
- 通过标准：无崩溃、无无限自动重连，后续手动重试可执行。
- 失败标准：错误后 UI 锁死、模型继续驱动或后台无限连接。
- 证据要求：状态日志和操作记录。

### N11 - 自动测试与旧功能回归

- 目的：验证新增数据流及历史功能。
- 操作步骤：执行全部 CTest 和 `--smoke-test`。
- 期望结果：导入、运动、协议、单 IMU 状态机测试全部通过；原手动和六路模拟 smoke 通过。
- 通过标准：退出码均为 0，无关键测试跳过。
- 失败标准：只验证新模式或只编译不启动。
- 证据要求：完整命令、汇总、smoke 日志和截图。

### N12 - 真实设备完整路径

- 目的：证明真实硬件可完成核心业务流程。
- 操作步骤：扫描设备、连接、选择手指、自然伸直校准、启用驱动、执行屈伸/张合、重新校准、断开。
- 期望结果：每步状态明确；模型仅响应目标手指；重新校准后新姿态成为零姿态。
- 通过标准：完整路径无崩溃，至少收到 100 个真实姿态帧，人工确认动作方向合理。
- 失败标准：仅使用演示数据、缺少校准或未实际驱动模型。
- 证据要求：设备型号和名称、绑定手指、安装朝向、帧数、截图、日志和逐步记录。

## 5. 阻塞与失败处理

- 无真实硬件：N12 标记阻塞，不能默认通过；其余自动和无硬件启动项继续执行。
- 轴向错误：记录动作、设备朝向和当前配置，只调整集中安装修正后重测，不改 BLE 换算比例。
- OpenGL 环境不可用：启动和渲染项标记阻塞，不能以编译代替。
- 编译、测试或启动失败：修复后最多三轮重试；仍失败则追加问题清单。
