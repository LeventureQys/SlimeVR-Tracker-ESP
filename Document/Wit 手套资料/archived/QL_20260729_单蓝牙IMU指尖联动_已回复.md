# 问题清单 - 单蓝牙 IMU 指尖联动 - 2026-07-29

## 需求解读

- 目标：把现有 WIT BLE IMU 扫描、连接和实时解析能力集成到可活动骨架手模 Demo。
- 核心交互：选择蓝牙 IMU，选择绑定的手指，观察实时传感器数据，执行零姿态校准，再用后续姿态驱动所选手指。
- 当前基础：手模 Demo 已有五指骨骼映射、关节限位、耦合求解和六路模拟姿态；IMU Demo 已通过真实 `WT901BLE67` 的扫描、连接、通知解析和数据刷新测试。
- 主要变化：旧版验收明确排除真实 IMU，本需求将真实单 IMU 通信、安装标定和手指绑定纳入新工作范围。
- 技术边界：单个指尖 IMU 只能提供指尖段相对零姿态的方向变化，无法唯一恢复 MCP/PIP/DIP 三个关节的真实独立角度。

## 不能自决问题

### Q001 - 单个指尖 IMU 如何驱动手指骨架

- 问题描述：“修饰这个手指的指尖姿态”存在两种本质不同的实现语义：只旋转所选手指的最远端骨骼，或根据指尖相对零姿态估计屈伸/张合并受约束地耦合整条手指链。
- 影响：该决定会改变姿态算法、UI 文案、配置结构、测试基线和最终视觉效果；选错后需要重写核心运动映射。
- 推荐方案：采用“整条手指受约束耦合”。校准时把当前 IMU 姿态记为零姿态；运行时计算 `qRelative = inverse(qZero) * qCurrent`，提取屈伸与张合，映射到所选手指整条链，并继续执行现有关节限位。界面明确标注这是根据指尖方向得到的工程近似，不是真实关节角。
- 推荐理由：只转末节只能改变指尖表面的朝向，不能合理改变指尖位置，视觉上容易出现末节折动；整链耦合与现有手模求解器兼容，也更符合“手掌舒展朝上为默认姿态”的整体动作预期。
- 备选方案：仅驱动最远端骨骼。优点是传感器与骨骼一一对应、算法假设较少；缺点是动作不自然，不能表达整根手指弯曲，且指尖位置变化很小。
- 风险预警：无论选择哪种方案，单 IMU 都不能证明恢复了真实 MCP/PIP/DIP 角度；需要真实佩戴测试确认 WIT 欧拉角坐标方向与模型局部轴的符号。
- 置信度：80%
- 请用户回复：`同意推荐方案（整条手指耦合）`，或 `选择备选方案（仅末节旋转）`。
- 用户回复：同意推荐方案（整条手指耦合），但是你需要注意的是，这个imu是绑在指尖这个指节上，所以相关的姿态关系可能需要提前设计一下

## 可以自决问题

### Q002 - 单 IMU 缺少掌心参考

- 问题描述：现有六路算法使用掌心 IMU 作为公共参考，但新需求只选择一个安装在指尖的 IMU。
- 影响：不能继续要求实时掌心四元数，否则单设备需求无法成立。
- 自决方案：使用校准时刻的 IMU 姿态作为固定参考，掌心在本版本视为模型绑定姿态；每次重新校准都会重置模型到舒展姿态并更新 `qZero`。
- 自决理由：该方案直接满足单设备与一键归零要求，并且不阻碍未来增加掌心 IMU 后切换为动态相对姿态。
- 风险预警：校准后若手掌整体转动，系统会把手掌运动误认为手指运动；界面需明确提示校准后保持掌心参考方向。
- 置信度：95%
- 用户修订：暂时不考虑掌心，你只用限制好它的控制约束就行，暂不考虑指尖，每次临时校准就行，这个只是个演示demo，你可以保留6of的所有控制位，但是暂时目前是只有一个imu设备控制

### Q003 - WIT 欧拉角到四元数的首版转换

- 问题描述：当前 BLE 协议输出 X/Y/Z 欧拉角，没有直接输出四元数；设备坐标系和模型局部轴还需实物确认。
- 影响：轴序或符号不匹配会导致手指运动方向错误，但不会改变总体架构。
- 自决方案：首版将解析后的角度通过 Qt 欧拉角接口转换为单位四元数，在零姿态相对化后交给独立的轴映射层；轴交换、符号和安装修正保留为集中配置，并用真实设备诊断与 UI 实时角度共同校验。
- 自决理由：现有设备已证实稳定输出有限角度值；把坐标修正隔离后，可在不改 BLE 和骨骼求解器的前提下修正实物方向。
- 风险预警：自动测试只能验证数学一致性，最终轴方向必须使用真实 IMU 人工确认。
- 置信度：90%
- 用户修订：按照推荐方案来进行吧

### Q004 - 集成后的界面流程

- 问题描述：两个 Demo 当前各自拥有主窗口，需要确定融合后的操作顺序和状态门禁。
- 影响：决定 UI 分组和错误反馈，但不构成技术路线分歧。
- 自决方案：在手模主窗口新增“真实 IMU”模式，按“扫描设备 → 选择并连接 → 选择绑定手指 → 手掌舒展朝上并点击校准 → 启用驱动 → 断开或重新校准”的顺序操作；未连接、未选手指或未校准时禁止启用驱动；保留实时加速度、角速度、欧拉角、帧数和连接状态摘要。
- 自决理由：顺序与依赖关系明确，可以防止未校准数据直接驱动模型，并保留 IMU Demo 的可诊断性。
- 风险预警：Windows BLE 断开后可能需要数秒才能重新连接，界面需要显示可恢复错误而不是自动反复重连。
- 置信度：95%
- 用户修订：按照自决方案进行吧
