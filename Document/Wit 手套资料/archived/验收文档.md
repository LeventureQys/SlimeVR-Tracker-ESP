# 可活动骨架手模 Demo 验收文档

## 1. 验收范围

覆盖独立构建、指定 FBX 导入、蒙皮显示、骨架层级、相机操作、骨骼选取、受约束关节旋转、六路模拟姿态输入、异常反馈、单元测试和启动测试。

不覆盖真实 IMU 通信、真实安装标定、医学级关节角精度、肌腱/受力模型、指尖拖动 IK、原始缺失纹理恢复、Linux/macOS。

## 2. 验收环境

- Windows，MSVC 2022 x64。
- Qt 6.8.3，路径以本机 CMake 可发现配置为准。
- CMake 4.x 或兼容版本。
- 支持 OpenGL 3.3 Core 的图形环境。
- 模型副本：`models/3D带骨架手模.fbx`。
- 构建与日志目录必须位于本研究项目内。

## 3. 前置条件

1. 已完成设计文档中的四个开发工作包。
2. Assimp 依赖可在研究目录内获得；不得使用会向仓库其他目录写缓存的配置。
3. `config/hand_rig.json` 已经可视化确认五条手指映射。
4. 默认模型副本与 `models/SOURCE.md` 存在。

## 4. 验收项

### A01 - 目录隔离

- 目的：确保预研不污染主工程。
- 操作步骤：检查 Git 变更和研究目录外文件状态；检查构建、依赖和日志路径。
- 期望结果：本功能所有新增/修改/生成物均在 `Document/Update/Research/可活动骨架的分析/`。
- 通过标准：没有由本功能造成的目录外变更。
- 失败标准：根 CMake、主工程源码、公共文档或源 FBX被修改，或缓存写出研究目录。
- 证据要求：`git status --short` 与构建命令记录。

### A02 - 独立配置与编译

- 目的：证明 Demo 不依赖主工程接入。
- 操作步骤：在研究目录执行 CMake configure 和 Debug build。
- 期望结果：生成 Demo 和测试目标，无编译错误。
- 通过标准：命令退出码 0，目标文件位于研究目录的 `build/`。
- 失败标准：依赖根工程才能构建，或产生目录外构建物。
- 证据要求：完整命令、退出码、构建日志路径。

### A03 - 模型导入契约

- 目的：验证指定 FBX 的骨骼蒙皮数据可用。
- 操作步骤：运行导入测试并输出统计。
- 期望结果：网格非空、20 个蒙皮关节、父索引有效、每顶点最多 4 权重且归一化。
- 通过标准：所有断言通过。
- 失败标准：退化为静态网格、骨骼缺失、权重越界或模型解析失败。
- 证据要求：测试输出和模型统计日志。

### A04 - 模型与骨架显示

- 目的：确认首帧渲染和骨架层级。
- 操作步骤：启动 Demo，启用/关闭骨架叠加，展开骨骼树。
- 期望结果：手模完整可见，无爆炸顶点；20 个蒙皮关节按层级显示；缺失纹理以警告和默认材质处理。
- 通过标准：显示稳定且警告可诊断。
- 失败标准：黑屏、严重网格破坏、骨骼树扁平或因纹理缺失拒绝加载。
- 证据要求：截图、日志片段、人工观察记录。

### A05 - 相机控制

- 目的：验证基础视角移动。
- 操作步骤：依次执行轨道旋转、平移、滚轮缩放、重置视角。
- 期望结果：四项操作符合设计，重置后模型适配视口。
- 通过标准：每项可重复且无跳变/翻转失控。
- 失败标准：操作冲突、模型丢失、产生 NaN 或无法重置。
- 证据要求：操作记录，必要时截图。

### A06 - 骨骼选取与手动旋转

- 目的：验证骨骼调试主路径。
- 操作步骤：从树和 3D 视图分别选中骨骼，拖动允许轴操纵器，编辑数值角度。
- 期望结果：选择双向同步；相应网格实时蒙皮变形；子骨骼平移和骨长保持绑定值。
- 通过标准：普通手指和拇指各至少验证一条链。
- 失败标准：任意平移、断链、选择错误或修改其他无关手指。
- 证据要求：选中与变形截图、操作记录。

### A07 - 人体工程学三级约束

- 目的：验证层级、关节限位和手指耦合。
- 操作步骤：对允许轴输入边界内、低于下限、高于上限值；在六路模式设置 `curl=0/0.5/1`。
- 期望结果：边界内保持，越界截断并提示；锁定轴不变；链内关节按配置比例联动并再次受限。
- 通过标准：自动测试与 UI 行为一致，无 NaN，骨长不变。
- 失败标准：越界未限制、限制方向错误、耦合超限或宣称医学精度。
- 证据要求：单元测试输出、UI 角度值与约束状态截图。

### A08 - 六路姿态模拟

- 目的：验证未来 IMU 接口的六安装点语义。
- 操作步骤：启动模拟源，改变掌心姿态，再分别改变五个手指姿态。
- 期望结果：掌心作为公共参考；每根手指根据相对掌心姿态独立产生受限耦合动作；UI 标注近似性质。
- 通过标准：六个槽位均可识别且互不串位。
- 失败标准：将六路误作六个标量自由度、手指串位、直接声称恢复真实 MCP/PIP/DIP 角。
- 证据要求：模拟参数、响应记录和截图。

### A09 - 输入异常

- 目的：验证无效和乱序姿态不会破坏模型。
- 操作步骤：测试非单位、零模、无效掌心、无效单指和倒退时间戳。
- 期望结果：按设计归一化、保持、暂停或丢弃，状态栏显示槽位与原因。
- 通过标准：无崩溃、无 NaN，后续有效帧可恢复。
- 失败标准：模型爆炸、静默接受零模、错误影响其他手指。
- 证据要求：单元测试与日志。

### A10 - 错误模型路径

- 目的：验证模型加载失败可诊断。
- 操作步骤：使用 `--model` 指向不存在文件启动。
- 期望结果：主窗口保持存活，编辑禁用，显示中文摘要和技术详情。
- 通过标准：无崩溃且错误码明确。
- 失败标准：程序直接异常退出或静默显示空白。
- 证据要求：命令、退出行为、错误截图和日志。

### A11 - 单元测试

- 目的：验证核心逻辑回归能力。
- 操作步骤：执行 CTest 或项目规定的全部测试命令。
- 期望结果：导入、配置、约束、耦合、四元数和异常路径测试全部通过。
- 通过标准：测试退出码 0，无跳过关键测试。
- 失败标准：任何核心测试失败或未实际执行。
- 证据要求：测试命令、汇总与日志路径。

### A12 - 启动冒烟与完整路径

- 目的：满足新 UI/OpenGL 功能启动门禁。
- 操作步骤：执行 `--smoke-test`，再人工完成工作包 D 的九步启动测试路径。
- 期望结果：冒烟退出码 0；人工路径无崩溃和相关 Critical/OpenGL 错误。
- 通过标准：两类启动测试都有证据。
- 失败标准：只编译不启动，或核心交互未实际操作。
- 证据要求：命令、退出码、日志、截图和逐步记录。

## 5. 失败与阻塞处理

- 编译、测试或启动失败：退回对应工作包修复，最多三轮后重新评估设计。
- 模型实际导入结果与 Balsam 诊断矛盾：暂停依赖项，追加问题清单并保存导入证据。
- 无 OpenGL 3.3 环境：记录阻塞，不得默认通过渲染和启动项。
- 真实 IMU 相关要求：记录为后续需求，不纳入本版通过条件。

## 6. 回归与交付物

本项目不接入主工程，因此主工程只需确认无文件变更，不要求执行其全量功能回归。交付必须包含独立源码、CMake、配置、模型来源说明、测试、设计文档、开发任务书、验收报告和启动证据。
