# V2.0.0 六路 IMU 手部骨骼闭环验收文档

## 1. 文档信息

- 所属 Version：V2.0.0 六路 IMU 手部骨骼闭环
- 所属阶段：阶段二·设计
- 验收对象：纯 C++20/Qt6 产品 `HandSkeletonStudio`
- 工程根：`Document/Research/手套IMU解算MVP/`
- 需求：`Document/Update/v2.0.0 - 六路IMU手部骨骼闭环/需求文档.md`
- 设计：`Document/Update/v2.0.0 - 六路IMU手部骨骼闭环/设计文档.md`
- 目标模型：`generic-hand-left.glb`

本文件供无对话上下文的验收 Agent 使用。必须按“编译测试→单元测试→启动测试→功能完整性测试→整体测试”顺序执行；前层阻断失败时不得宣称后层通过。

## 2. 验收环境记录

验收报告必须记录：

- Windows 版本、CPU、GPU、内存。
- CMake、编译器、Qt、Assimp 版本。
- Git revision 或工作树状态。
- EXE 与模型/配置路径。
- 六路设备型号、固件、串口、波特率、量程、采样率和安装说明。
- 真实数据集目录、配置哈希和模型哈希。
- 开始/结束时间和验收人。

## 3. 阻断条件

出现任一项即阻断 Version 完成：

- 产品构建、运行或测试依赖 Python/PySide6。
- `HandSkeletonStudio` 链接或运行 SlimeVR 网络模块。
- 置顶问题未关闭。
- 核心契约、模型映射或验收标准不明确。
- 任一核心单元测试失败。
- 目标 GLB 无法加载、25 关节映射不完整或 bind pose 误差超限。
- 输出出现 NaN、Inf、零范数四元数或无界缓存增长。
- 未执行真实硬件启动测试，且无经用户批准的明确阻塞记录。
- 未提供日志、操作记录、截图或统计证据。

## 4. 第一层：编译测试

### 4.1 配置与构建

在工程根执行等价命令：

```powershell
cmake -S . -B build-v2 -DBUILD_TESTING=ON -DHAND_SKELETON_FETCH_ASSIMP=ON
cmake --build build-v2 --config Release
```

检查：

- 生成 `HandSkeletonStudio.exe`。
- 无 Python 检测、Python include/lib、PySide6 或 pip 步骤。
- 产品依赖不含 `six_imu_network`。
- Qt/Assimp/资产部署完整。
- 编译无新增 warning-as-error 失败；重要警告记录在报告。

### 4.2 通过标准

- CMake configure 返回 0。
- Release build 返回 0。
- EXE、GLB 和默认 JSON 配置均存在。

## 5. 第二层：单元测试

执行：

```powershell
ctest --test-dir build-v2 -C Release --output-on-failure
```

报告每个测试目标、耗时、通过/失败和日志路径。

### 5.1 核心契约与配置

- 地址与 `SensorId` 双向映射。
- Qt 元类型跨线程可用。
- schema 校验、非法字段和非有限值拒绝。
- 安装四元数单位化或拒绝策略明确。

### 5.2 协议和分组

- 任意分包、粘包、噪声、CRC 错误后重同步。
- 未知地址隔离。
- sequence 交错、重复、回绕。
- 只发布六路完整组。
- pending 不超过上限，淘汰和统计正确。

### 5.3 录制与回放

- idle/recording/paused 状态机。
- raw 字节 1:1 保真，包括坏帧。
- metadata 字段和 schema 完整。
- 文件初始化失败可回滚。
- 写队列有界，溢出可统计。
- 同一 raw 数据两次回放结果确定一致。

### 5.4 校准和融合

- 量程、单位、轴映射和每路独立配置。
- 静止零偏与运动冻结。
- Madgwick/VQF 统一接口。
- dt 异常回退。
- 四元数有限、范数误差≤`1e-4`、符号连续。
- 磁干扰迟滞、SixD 退化和恢复限速。

### 5.5 手部观测

- `inverse(palm) × finger` 抵消公共手掌旋转。
- `mount × relative × inverse(mount)` 顺序正确。
- 五指不串路。
- 拇指与长指参数独立。
- flexion/abduction/twist 边界与奇异输入安全。

### 5.6 骨骼求解

- 每帧从 bind pose 求解。
- 虚拟解剖层级与 GLB palette 分离且映射 25/25。
- 关节不越限，锁轴保持。
- 骨长变化≤`1e-4` 模型单位。
- 单指 Held/Recovered 不影响其他指。
- 手腕失效冻结整手。
- 输出来源与 `coupledApproximation` 正确。

### 5.7 GLB 和渲染

- 目标 GLB：30 节点、25 joints、1360 顶点、6942 indices。
- POSITION/NORMAL/TEXCOORD_0/JOINTS_0/WEIGHTS_0/indices 完整。
- joint 名唯一，palette 顺序稳定。
- bind pose CPU 蒙皮最大误差≤`1e-4`。
- 离屏 OpenGL context、shader 和一帧渲染无 GL error。

### 5.8 UI 和线程

- 离屏主窗口创建/关闭。
- 数据源切换、录制关闭和线程退出。
- 队列满时丢旧保新且有统计。
- 相机重置不修改算法状态。

## 6. 第三层：启动测试

### 6.1 固定回放启动

使用固定录制会话：

```powershell
HandSkeletonStudio.exe --source replay --replay <session-dir> --screenshot <png> --auto-exit-ms 10000
```

验证：

- 进程正常启动和退出，退出码 0。
- GLB、配置和 shader 加载成功。
- 25 关节、19 骨段和蒙皮可见。
- 日志无崩溃、未处理异常、GL error、NaN/Inf。
- 截图路径存在并写入验收报告。

### 6.2 真实硬件启动

```powershell
HandSkeletonStudio.exe --source serial --port <COMx>
```

操作：

1. 连接六路硬件并等待全部有效。
2. 执行启动零偏。
3. 佩戴后执行中立/安装校准。
4. 手掌绕三个轴旋转。
5. 五指依次屈伸和张合。
6. 执行拇指对掌。
7. 录制至少 60 秒并停止。
8. 断开并重连串口。
9. 关闭应用。

证据：串口、六路帧率、完整组率、CRC、截图、录制目录、日志和操作时间线。

### 6.3 通过标准

- 无崩溃、卡死或线程退出警告。
- 六路持续更新且地址不串路。
- 手掌整体旋转不会被明显解释为手指屈伸。
- 每指动作主要驱动对应骨链。
- 录制文件可立即回放。

## 8. 第五层：整体测试

### 8.1 30 分钟连续运行

- 使用真实硬件，包含静置和周期动作。
- 每分钟采样进程内存、CPU、完整组率、pending 水位、各队列水位、算法延迟和 FPS。
- 缓存和队列不得随时间单调无界增长。
- 无崩溃、死锁、GL error、文件句柄持续增长。

### 8.2 性能指标

- 原始解析和融合目标约 200 Hz，以真实硬件采样率为准。
- 骨骼求解≥100 Hz。
- UI 30–60 FPS。
- 完整组六路输入到骨骼帧生成处理延迟目标<10 ms，不含硬件串口缓冲。
- UI 不阻塞串口和算法 worker。

未达目标时必须给出实测值、瓶颈证据和是否阻断核心使用的结论，不得仅写“看起来流畅”。

### 8.3 姿态质量

分别报告六颗 IMU：

- 静置抖动 RMS/峰峰值。
- SixD 和 NineD 10 分钟航向漂移。
- Madgwick 与 VQF 对比。
- 磁干扰进入/恢复时间。
- 零偏校准前后结果。

优化方案相对 Madgwick 初始基线的静置漂移目标降低≥70%；正常磁环境 NineD 10 分钟绝对 Yaw 漂移优先≤3°。硬件不满足时记录事实和边界，不允许强制归零掩盖。

## 9. Python 与网络依赖审计

必须检查：

- CMake、源代码、启动脚本、发布目录和运行日志中无 Python/PySide6 调用。
- EXE 导入表无 Python DLL。
- 产品目标不链接 `six_imu_network`，UI 无 SlimeVR 菜单。
- 仓库中保留的历史 Python/SlimeVR 文件不参与产品构建即可，不要求删除。

## 10. 验收报告格式

最终 `验收报告.md` 至少包含：

1. 环境与版本。
2. 构建命令、退出码和产物。
3. 全部测试清单与结果。
4. 固定回放启动证据。
5. 真实硬件启动操作记录。
6. 功能矩阵逐项结论。
7. 30 分钟统计表。
8. 六路姿态质量表。
9. 截图、日志和数据集路径。
10. Python/网络依赖审计。
11. 失败项、风险、豁免与责任人。
12. 最终结论：通过、限条件通过或不通过。

## 11. 验收结论规则

- **通过**：所有阻断项通过，核心功能和整体测试满足门槛。
- **限条件通过**：不得用于缺少真实硬件测试、核心测试失败或数值非法；只可用于非阻断性能目标轻微偏差，并须用户明确批准。
- **不通过**：任一阻断条件成立。
