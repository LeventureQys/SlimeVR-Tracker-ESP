# 手套六 IMU 实时解算 Qt 工具 MVP 需求文档

## 1. 文档信息

- 项目名称：手套六 IMU 实时解算 Qt 工具 MVP
- 文档版本：v0.3
- 阶段：阶段一·需求定义
- 工作目录：`Document/Research/手套IMU解算MVP/`
- 目标版本：v0.1.0
- 目标平台：Windows 桌面端
- 文档状态：待用户确认

## 2. 背景

当前六 IMU 手套设备通过串口持续输出手腕、拇指、食指、中指、无名指和小指共六个传感器的九轴原始数据。现有资料已提供：

1. 单设备 Qt 实时数据显示程序，可复用其 Qt Widgets 工程组织、实时刷新、演示模式和测试方式；
2. Python 六 IMU 串口解析工具，已实现连续字节流切帧、CRC16 校验、六地址识别及按采样序号分组；
3. 六 IMU 串口协议文档，定义了串口参数、帧结构、字节序、地址、CRC 和异常数据行为。

本项目需要在独立目录中制作一个 Qt 桌面 MVP，通过串口实时接收六 IMU 数据，稳定完成协议解析、同采样分组、六路独立姿态融合和实时界面展示。首版同时保留协议级 MVP 的全部诊断能力；手指关节角与三维手模驱动仍作为后续扩展。

## 3. 参考依据

### 3.1 单设备 Qt 参考程序

目录：`Document/Wit 手套资料/archived/Adapter/IMU_Example_Qt/`

可复用的产品与工程模式：

- Qt 6、C++17、Qt Widgets、CMake 的独立桌面工程；
- 数据采集层、协议解析层、数据模型层与界面层解耦；
- 实时数据先进入最新快照，再以固定 UI 刷新周期显示；
- 演示数据源用于无硬件启动验证；
- QtTest 单元测试和自动退出启动测试；
- 明确显示连接状态、更新时间和有效帧计数。

不得直接沿用的部分：

- 原程序使用 BLE，本项目的数据入口是串口；
- 原程序协议是单设备 `55 61`/`55 71`，本项目协议是六地址 `AA 55` 固定 25 字节帧；
- 原程序直接提供姿态角，本项目当前协议只提供六路加速度、角速度和磁场原始整数值。

### 3.2 六 IMU Python 解析参考

文件：`Document/Wit 手套资料/parse_six_imu.py`

已验证的核心行为：

- 帧头为 `AA 55`；
- 固定帧长 25 字节，长度字段固定为 `0x12`；
- 前 23 字节执行 Modbus CRC16；
- 九轴字段按大端有符号 `int16` 解析；
- 地址 `0x50` 至 `0x55` 分别对应手腕和五指；
- 同一 `SEQ` 的六地址帧归为一组；
- 支持串口分包、粘包、前导噪声、CRC 错帧和残帧恢复；
- 支持完整组、过期不完整组、重复地址帧和统计信息。

### 3.3 串口协议参考

文件：`Document/Wit 手套资料/串口输出解析协议文档.md`

确定的通信参数：

- 串口：用户在界面中选择；
- 默认波特率：921600；
- 数据位：8；
- 校验位：无；
- 停止位：1；
- 输出格式：连续二进制字节流；
- 设备输出频率：约 200 Hz；
- 单帧：25 字节；
- 一次完整采样：同一 `SEQ` 下的六个地址帧，共 150 字节。

## 4. 产品目标

制作一个可独立构建和运行的 Qt 6 桌面工具，使开发者或测试人员能够：

1. 在界面中选择串口和通信参数并打开设备；
2. 实时接收连续二进制字节流；
3. 稳健解析六个 IMU 的九轴数据；
4. 按 `SEQ` 聚合为同一采样时刻的六传感器快照；
5. 在界面中同时观察六路传感器的最新数据、有效性和更新状态；
6. 观察帧率、完整组率、CRC 错误、丢弃字节和缺失传感器等诊断指标；
7. 对每个 IMU 的九轴数据独立执行实时姿态融合，输出单位四元数与欧拉角；
8. 提供姿态零位标定、融合状态和数据有效性观察；
9. 在没有真实硬件时使用明确标识的演示模式验证程序启动、融合与 UI 数据链路；
10. 为后续加入手指关节角和三维手模驱动提供稳定的数据接口。

## 5. MVP 范围

### 5.1 必须包含

#### 5.1.1 串口管理

- 枚举当前系统可用串口；
- 支持刷新串口列表；
- 默认波特率为 921600；
- 支持打开和关闭串口；
- 显示未连接、连接中、已连接、关闭和错误状态；
- 串口读取采用 Qt 异步事件，不在 GUI 线程中阻塞等待；
- 关闭窗口时安全关闭串口并释放资源。

#### 5.1.2 连续流协议解析

- 在任意边界输入的字节流中搜索 `AA 55` 帧头；
- 处理通知块或串口读取块造成的分包、粘包与前导噪声；
- 候选帧必须满足固定 25 字节长度；
- 长度字段必须为 `0x12`；
- 按 Modbus CRC16 校验前 23 字节；
- CRC 字节按低字节、高字节顺序读取；
- 九轴字段按大端有符号 16 位整数解析；
- 错误帧不得更新有效数据快照；
- 出现错误后解析器必须继续搜索下一有效帧，不得要求用户重连。

#### 5.1.3 六设备识别与采样分组

- 地址映射固定为：
  - `0x50`：wrist / 手腕；
  - `0x51`：thumb / 拇指；
  - `0x52`：index / 食指；
  - `0x53`：middle / 中指；
  - `0x54`：ring / 无名指；
  - `0x55`：pinky / 小指；
- 同一 `SEQ` 的帧归为同一次采样；
- 集齐六个已知地址后发布一组完整快照；
- 对重复地址帧进行计数，组内相同地址使用最新到达帧；
- 对长期未完整的采样组进行有界淘汰，避免内存增长；
- 保留完整组、不完整组、缺失地址和重复帧统计；
- `SEQ` 为 8 位循环计数，必须正确处理 `0xFF` 到 `0x00` 的回绕，不按普通整数大小判断新旧。

#### 5.1.4 姿态参数配置与持久化

- 主界面必须提供“姿态参数设置”入口，打开独立模态 `QDialog`；
- 对话框至少允许配置：加速度满量程、陀螺仪满量程、磁力计比例系数、Madgwick 增益、磁场启用状态及磁场有效阈值；
- 默认加速度换算沿用单设备参考：`acceleration = raw / 32768.0 * 16.0 g`，即满量程 `±16 g`；
- 默认陀螺仪换算沿用单设备参考：`angularVelocity = raw / 32768.0 * 2000.0 °/s`，即满量程 `±2000 °/s`；
- 默认磁场换算沿用单设备参考：`magnetic = raw / 120.0`，单位保持为参考协议值，不宣称为 `µT`；
- 六路默认共用同一套量程和融合参数；
- 参数必须使用 `QSettings` 长期保存，关闭程序和电脑重启后仍保留；
- 程序首次启动或配置缺失时使用上述默认值；
- 对话框必须提供“恢复默认值”“确定”“取消”；取消不得修改当前运行参数或持久化数据；
- 参数必须进行有限值与合理范围校验，非法值不得保存并显示明确原因；
- 应用新参数时重置六路融合器，避免使用不同单位参数的历史状态继续积分；
- 配置存储失败时必须提示用户，不得虚假显示保存成功；
- 配置存储位置和 `QSettings` organization/application 名称在阶段二固定，并在 README 中说明。

#### 5.1.5 六路姿态融合与零位标定

- 对手腕和五指六个 IMU 分别维护独立姿态融合状态；
- 只在完整且通过协议校验的输入上更新对应传感器状态；
- 将原始加速度、角速度和磁场按已确认量程转换为融合算法所需物理量；
- 姿态输出至少包含单位四元数 `w/x/y/z` 和便于观察的欧拉角；
- 输出必须带传感器地址、`SEQ`、时间戳、有效标志和融合状态；
- 支持六路同时执行静止零位标定，并保存各路零位参考四元数；
- 标定后同时提供世界姿态与相对零位姿态；
- 全零、缺失、超时或非有限输入不得覆盖上一有效姿态；
- 磁场不可用或明显异常时允许退化为六轴融合，但必须在界面显示当前模式；
- 默认采用支持九轴与六轴退化的 Madgwick 姿态融合；
- 磁场有效时使用九轴融合，磁场全零、非有限或不满足配置阈值时自动退化为六轴融合；
- 六个 IMU 的安装轴向完全相同，分别固定于手腕手背和五指指尖手背侧，首版不为六路设置不同的轴交换；
- 首版统一使用传感器原始右手坐标系进行融合，零位标定消除佩戴初始朝向；
- 融合算法、参数、坐标系、量程与异常判据须在阶段二设计文档中明确，不得散落在 UI 代码中。

#### 5.1.6 实时数据展示

- 界面同时展示六个传感器；
- 每个传感器至少展示：
  - 加速度 `AX`、`AY`、`AZ`；
  - 角速度 `GX`、`GY`、`GZ`；
  - 磁场 `MX`、`MY`、`MZ`；
  - 姿态四元数 `W`、`X`、`Y`、`Z`；
  - 姿态欧拉角 `Roll`、`Pitch`、`Yaw`；
  - 融合模式与姿态有效状态；
  - 地址；
  - 最新 `SEQ`；
  - 本组是否有效；
  - 最近更新时间；
- 支持在单一界面快速识别某一路是否缺失、全零或停止更新；
- UI 刷新与串口接收解耦，界面按固定周期显示最新快照，避免约 1200 帧/秒的单帧事件直接驱动重绘；
- 显示当前最新完整组的序号和完整组六路数据。

#### 5.1.7 诊断统计

至少显示以下累计统计：

- 输入字节数；
- 帧头候选数；
- 有效帧数；
- CRC 错误数；
- 长度错误数；
- 丢弃字节数；
- 完整采样组数；
- 不完整采样组数；
- 重复地址帧数；
- 六个地址各自的有效帧数；
- 当前有效帧率和完整组率。

统计在重新打开串口、进入演示模式或用户执行“清空统计”时重置；具体重置交互在设计阶段确定。

#### 5.1.8 演示与测试模式

- 提供明确标识为“演示模式 / 非真实设备数据”的数据源；
- 演示数据必须生成六地址、共同 `SEQ`、连续变化的九轴数据；
- 演示模式和真实串口模式互斥；
- 支持命令行自动进入演示模式并在指定时间后退出，用于启动测试；
- 演示模式不得作为真实硬件验收通过的证据。

#### 5.1.9 测试

- 协议解析器必须有自动化单元测试；
- 分组器必须有自动化单元测试；
- 姿态融合器必须有自动化单元测试，覆盖静止、已知轴旋转、时间步异常、磁场退化和无效输入；
- 零位标定和相对姿态必须有自动化单元测试；
- 参数默认值、校验、保存、重新加载、取消和恢复默认值必须有自动化测试；
- 核心界面数据链路与配置对话框必须有 QtTest；
- 必须执行应用启动测试；
- 有真实六 IMU 串口硬件时，必须执行实际打开串口、接收数据、六路更新和异常日志检查；
- 无硬件时必须在验收报告中记录硬件阻塞，不得将演示模式等同于真实设备测试。

### 5.2 MVP 暂不包含

以下功能除非用户在阶段一确认纳入，否则不属于 v0.1.0：

- 三维手模或骨骼动画；
- 曲线图、频谱图和历史数据回放；
- 原始数据文件录制与导出；
- 传感器配置写入、校准命令或固件升级；
- 自动串口重连；
- 网络转发、OSC、UDP、WebSocket 或 SlimeVR 协议输出；
- 多只手套并发连接；
- 根据人体骨骼约束计算手指关节角；
- 六路姿态到骨骼关节的约束求解；
- 三维姿态渲染；
- 未经明确参数依据的量程换算、安装轴修正或漂移补偿；
- 修改仓库根固件工程或现有单设备 Qt 参考程序。

## 6. “实时解算”的需求定义

### 6.1 已确定的第一层解算

本 MVP 必须完成协议级实时解算：

```text
串口字节流
→ 帧同步
→ 长度与 CRC 校验
→ 九轴 int16 解码
→ 地址映射
→ 同 SEQ 六路聚合
→ 完整性与异常诊断
→ 六路实时快照展示
```

该层能力完全由现有 Python 工具和协议文档支撑，不需要猜测传感器量程、安装方向或融合算法。

### 6.2 已确认的第二层解算

用户已确认 v0.1.0 必须在保留第一层协议级 MVP 全部能力的基础上，加入六路独立姿态解算：

```text
六路同步九轴原始值
→ 物理量换算
→ 每路独立姿态融合
→ 单位四元数
→ 欧拉角观察值
→ 六路零位标定与相对姿态
→ 融合模式及有效状态展示
```

姿态输出定义为每个传感器独立的空间方向，不在本版本中把六个姿态进一步约束为手指 MCP/PIP/DIP 关节角。

### 6.3 已确认的默认解算参数

用户已确认采用单设备 Qt 参考程序的换算作为可编辑默认值：

- 加速度：`raw / 32768.0 * 16.0 g`；
- 角速度：`raw / 32768.0 * 2000.0 °/s`；
- 磁场：`raw / 120.0`，单位标记为“参考协议值”；
- 六个 IMU 安装轴向完全相同，分别固定于手腕手背及五指指尖手背侧；
- 融合算法：Madgwick；
- 磁场有效时使用九轴模式，磁场异常时自动退化为六轴模式。

默认参数仅表示用户授权采用的首版配置，不代表六 IMU 硬件量程已由芯片资料独立验证。界面必须通过持久化配置对话框允许用户修正，验收报告必须记录实际测试所用参数。

### 6.4 配置对话框用户流程

1. 用户在主界面打开“姿态参数设置”；
2. 对话框读取当前生效参数；
3. 用户修改量程、磁场比例或融合参数；
4. 点击“确定”后执行校验；
5. 校验通过则写入 `QSettings`、更新当前参数并重置六路融合器；
6. 校验失败则保持对话框打开并指出字段；
7. 点击“取消”则丢弃本次编辑；
8. 点击“恢复默认值”只把编辑控件恢复为默认值，仍需点击“确定”才保存；
9. 下次启动自动加载上次成功保存的参数。

## 7. 用户流程

### 7.1 真实串口流程

1. 用户启动程序；
2. 程序展示可用串口，默认选择 921600、8N1；
3. 用户刷新并选择目标串口；
4. 用户点击“打开串口”；
5. 程序清空旧缓存和统计，开始异步读取；
6. 界面持续显示六路最新数据及采样组完整性；
7. 用户可观察错误统计判断链路质量；
8. 用户点击“关闭串口”或关闭窗口；
9. 程序停止读取并安全释放串口。

### 7.2 演示模式流程

1. 用户未连接真实串口；
2. 用户启用演示模式；
3. 程序明确显示“演示模式 / 非真实设备数据”；
4. 六路数据和统计按确定性规则持续变化；
5. 用户关闭演示模式后回到未连接状态。

### 7.3 错误恢复流程

- 串口打开失败：显示可理解的错误原因，程序保持可操作；
- 串口运行中断开或读取失败：停止当前会话并显示错误，不崩溃；
- 接收到噪声或错误 CRC：累计统计并自动继续同步；
- 单个传感器输出全零：保留该有效协议帧，同时将该路标记为全零数据；
- 某个传感器缺失：完整组不发布或按所选策略标记为不完整，界面明确显示缺失地址；
- 数据超过阈值时间未更新：对应传感器显示超时状态。

## 8. 数据与接口需求

### 8.1 单帧数据

单个已解析传感器帧至少包含：

- `address: uint8`；
- `sensorId: enum`；
- `sequence: uint8`；
- `ax, ay, az: int16`；
- `gx, gy, gz: int16`；
- `mx, my, mz: int16`；
- `isAllZero: bool`；
- `receivedAt: timestamp`。

### 8.2 六路采样快照

一次采样快照至少包含：

- `sequence: uint8`；
- 六地址到单帧数据的固定映射；
- `presentMask` 或等价的六路存在标记；
- `complete: bool`；
- 缺失传感器集合；
- 快照完成或淘汰时间。

### 8.3 六路姿态快照

每个传感器的姿态快照至少包含：

- 世界姿态单位四元数；
- 相对零位单位四元数；
- `Roll`、`Pitch`、`Yaw` 观察值；
- 姿态时间戳与对应 `SEQ`；
- 姿态有效标志；
- 当前为九轴融合或六轴退化模式；
- 是否已完成零位标定；
- 最近一次有效更新和错误原因。

### 8.4 统计快照

统计对象至少包含第 5.1.7 节列出的累计值，以及计算帧率和完整组率所需的时间窗口状态。

## 9. 非功能需求

### 9.1 性能

- 面向约 200 Hz 的六 IMU 采样，即约 1200 个设备帧/秒；
- 串口解析不得因 UI 重绘阻塞而持续积压；
- UI 推荐以 20 至 30 Hz 刷新最新快照，实际周期在设计阶段确定；
- 待分组采样数量必须有固定上限；
- 连续运行 30 分钟不得出现由缓存或待分组队列导致的持续内存增长。

### 9.2 稳定性

- 任意字节切分输入不得导致越界访问或崩溃；
- 错误长度、错误 CRC、未知地址、重复地址和残帧不得导致崩溃；
- 重复打开、关闭、刷新和切换演示模式操作必须安全；
- 应用退出时不得遗留串口占用。

### 9.3 可维护性

- 串口层、协议解析层、分组层、演示数据层和 UI 层分离；
- 核心协议和分组逻辑可在不启动 GUI 的情况下测试；
- 不把协议常量散落在界面代码中；
- 持久化参数由独立配置模型管理，不允许 UI 直接读写融合器内部状态；
- 姿态融合模块不得与串口解析器或 UI 耦合；
- 对外姿态数据结构应能在后续接入手指关节约束模块而无需重写融合器。

### 9.4 可观察性

- 状态文字必须区分真实串口与演示模式；
- 错误统计必须可见；
- 六个传感器必须有独立在线、缺失、全零或超时状态；
- 测试和启动过程应输出足以定位失败原因的日志。

## 10. 技术约束

- Qt 版本：Qt 6；
- 语言：C++17 或更高，默认 C++17；
- UI：Qt Widgets；
- 串口：Qt SerialPort；
- 构建：CMake 3.20 及以上；
- 测试：QtTest；
- 目标工程在 `Document/Research/手套IMU解算MVP/` 内独立构建；
- 不修改 `Document/Wit 手套资料/archived/Adapter/IMU_Example_Qt/`；
- 不修改仓库根固件工程和根构建文件；
- 源代码与测试文件的最终目录、类名和接口由阶段二设计文档定义。

## 11. 验收口径

阶段四至少按照以下层级验收：

### 11.1 编译测试

- CMake 配置成功；
- Debug 构建成功；
- 所有目标无编译和链接错误。

### 11.2 单元测试

- 正常有效帧解析；
- 正数、负数和边界 `int16`；
- CRC 正确与错误；
- 长度字段错误；
- 任意分包、粘包和前导噪声；
- 末尾半个帧头和残帧保留；
- 六地址映射；
- 同 `SEQ` 完整组；
- 缺失地址导致不完整组；
- 重复地址覆盖与计数；
- `SEQ` 从 `0xFF` 回绕到 `0x00`；
- 待分组队列有界淘汰；
- 全零帧识别；
- 重置后缓存、快照和统计清空；
- 静止输入下姿态稳定且四元数保持单位长度；
- 已知单轴角速度积分方向正确；
- 零位标定后相对姿态为单位旋转；
- 非法时间步、全零、缺失和非有限输入不覆盖上一有效姿态；
- 磁场异常时按设计退化并报告模式；
- 默认参数与参考程序换算一致；
- 修改参数后可保存并在新进程重新加载；
- 取消对话框不改变参数，恢复默认值后确认可持久化；
- UI 注入六路原始与姿态快照后数据和状态正确显示。

### 11.3 启动测试

- 实际启动桌面程序并显示主窗口；
- 自动进入演示模式后六路原始数据和姿态持续变化；
- 至少运行 3 秒；
- 到时正常退出；
- 无 Qt fatal、未处理异常或崩溃日志。

### 11.4 功能完整性测试

- 串口列表可刷新；
- 连接状态切换正确；
- 六路原始数据、四元数、欧拉角、序号、更新时间和融合状态显示完整；
- 六路零位标定后相对姿态正确更新；
- 姿态参数对话框可修改、校验、取消、恢复默认并长期保存；
- 参数应用后六路融合器安全重置；
- 统计项完整且能重置；
- 演示模式与真实串口互斥；
- 错误输入不破坏后续有效帧解析。

### 11.5 真实硬件测试

有硬件时：

- 使用 921600、8N1 打开目标串口；
- 连续接收有效帧；
- 六个地址均有计数增长；
- 完整组持续更新；
- 观察至少 60 秒无崩溃、无持续积压；
- 记录有效帧率、完整组率、CRC 错误及缺失情况；
- 关闭程序后串口可被再次打开。

无硬件时：

- 将真实硬件测试标记为阻塞；
- 记录缺少的设备或串口条件；
- 不以演示模式替代真实硬件测试结论。
