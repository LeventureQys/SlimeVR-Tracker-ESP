# V1.0-S2.3 坐标系设计

## 1. 目的

固定从六 IMU 融合姿态到 SlimeVR 节点姿态的坐标与四元数语义，作为 `slimevr_coordinate_transform` 实现的规格依据。任何与本文不一致的轴交换、符号或乘法顺序都必须先修改本文并通过测试。

## 2. 源坐标：MVP Madgwick 输出

### 2.1 原始轴

- 串口帧九轴 int16 大端直接解析为 `(x, y, z)`，MVP 不做任何轴重映射（`six_imu_solver.cpp` `convertAxes`）。
- 加速度换算 `raw/32768×量程`，角速度 `raw/32768×量程→rad/s`，磁场 `raw/120`。

### 2.2 融合四元数语义

- 实现采用 Madgwick 2011 原版公式（`madgwick_filter.cpp`）。
- `q` 表示参考系到当前传感器系的主动旋转：静止水平放置时为近似单位四元数。
- 已由 `test_madgwick_filter::A03` 验证：传感器绕自身 `+Z` 匀速正向旋转 θ 后，`q = fromAxisAndAngle(+Z, θ)` 且 `q.z() > 0`。
- 坐标系为右手系；重力参考为世界 `+Z`（加速度计反作用力方向）；九轴融合的航向参考为磁北（原版磁参考公式）。
- 输出：
  - `worldOrientation`：融合原始姿态；
  - `relativeOrientation = zero⁻¹ · worldOrientation`：仅本地显示用（工具零位）。

## 3. 目标坐标：SlimeVR 节点

### 3.1 节点轴

依据固件 `src/sensors/sensor.h` 注释与官方约定：

```text
X = 左（left）
Y = 上（top）
Z = 前（front）
```

右手系（`left × up = front`）。

### 3.2 四元数语义

- 节点四元数表示节点相对其 rest 参考姿态的主动旋转。
- Server 的 mounting calibration 建立 rest 参考：校准后节点静止即为单位四元数。
- 网络载荷固定 `x, y, z, w` 顺序，大端 float（`RotationData` 类型 17）。

## 4. 转换公式

### 4.1 无安装偏置

源与目标同为右手系主动旋转，且绝对姿态差异由 Server 挂载校准吸收，因此：

```text
q_node = q_source          （mounting = identity 时）
```

### 4.2 固定安装旋转

`q_mount`：从节点参考系到传感器系的固定旋转（物理安装方向）。

节点当前姿态为链条 `节点参考 → 传感器参考 → 传感器当前 → 节点当前` 的合成：

```text
q_node = conj(q_mount) · q_source · q_mount
```

（Hamilton 乘积，QQuaternion `operator*`。）

- `mounting = identity` 时退化为 4.1；
- 测试 `test_slimevr_coordinate_transform::C02` 锁定该公式。

### 4.3 左右手

- 同一物理旋转在左右手节点模型中语义不同，但由 Server 端左右手 body part 模型承担；
- 桥接端不做轴取反、不做镜像，左右手只改变：
  - 握手的 tracker type（左 `1`、右 `2`）；
  - SensorInfo 的 position 枚举（`S2.3/需求.md` 映射表）。
- 测试 `C03` 锁定“手侧不改变公式”。

## 5. 禁止事项

- 禁止欧拉角中转四元数转换；
- 禁止用姿态零位代替安装旋转；
- 禁止凭观察交换分量或取反轴而不修改本文；
- 禁止把 `relativeOrientation` 与挂载校准叠加（双重抵消）。
