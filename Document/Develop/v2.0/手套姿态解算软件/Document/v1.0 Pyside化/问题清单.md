## 置顶区（需用户决策，阻塞阶段）

### Q1. 语言/框架确认：Python+PySide 还是 C++？

- **问题描述**：`Document/v1.0 C++化/需求说明.md` 第 3 行写明"使用 python + pyside 来实现界面功能"，但版本目录名是"v1.0 C++化"（仓库 `archived/` 中还有一套早期 Qt/C++ 原型）。两者矛盾，语言栈选错将导致全部返工。
- **建议方案**：以需求说明.md 正文为准，按 **Python + PySide6** 执行；目录名"v1.0 C++化"不改动（仅命名历史遗留）。
- **备选方案**：若你的真实意图是 C++/Qt 重写（延续 archived 的 Qt/C++ 路线），请明确告知并改写需求说明，我重新规划。
- **风险预警**：误判 = 整个版本返工；Python 方案的性能对 200Hz 数据刷新与 60fps 渲染绰绰有余，无技术风险。
- **置信度**：85%（正文权威、目录名疑似旧名）。
- **分区归属**：置顶区。

### Q2. 3D 渲染技术选型（本机已实测验证，证据见下）

- **问题描述**：`需求说明.md` 第 3 行授权自选 3D 渲染技术，目标"显示效果和 web 端保持一致"。web 端为 Three.js r160：`web/assets/generic-hand-left.glb`（glTF2，1 个蒙皮网格 + 1 套皮肤 + 25 个 WebXR 标准关节，BIN 仅 86KB，无 Draco）+ 半透明 PBR 皮肤 + 骨骼覆盖层（圆柱+关节球）+ 网格 + 4 盏灯 + 指数雾 + ACES 色调映射 + 轨道相机（`web/js/hand-model.js`、`web/js/viewer.js`）。
- **候选与已验证事实**（本机 .venv Python 3.14.4，2026-08 实测）：
  1. **Qt3D（PySide6 内置）**：PySide6 6.11.1 已移除 Qt3D Python 绑定（模块为空壳）；6.10.3 仍有绑定，但实测 `QSceneLoader` 无法导入 .glb（"no suitable importer plugin"：glTF 导入器只注册 `gltf` 扩展名，assimp 导入器硬编码格式列表不含 gltf/glb）；Qt3D 6.10 自带 glTF 导入器源码明确"skin 不解析"（qt3d `gltfio.cpp` 限制注释）——**蒙皮通道基本不存在，已实测否决**。
  2. **Qt Quick 3D**：PySide6 6.10.3 有 QML 运行时，但运行时 glTF 加载依赖 6.8+ 实验性 RuntimeLoader，PySide6 下无成熟先例，Widgets 混排成本高。
  3. **QOpenGLWidget 自绘**：PySide6 6.10.3 下 `QOpenGLWidget`/`QtCharts`/`QtGraphs` 全部可用（已导入验证）；资产格式简单且完全已知（1 网格、25 关节、单材质），自写 glTF2 解析 + GPU 蒙皮 shader 完全可控，无任何运行时插件依赖。
  4. **QWebEngineView 内嵌现有网页**：效果 100% 一致，但本质保留 web 技术栈，违背"去掉 web 端"的需求，仅作兜底。
- **建议方案**：**PySide6 6.10.3 + QOpenGLWidget 自绘渲染**。开发包：Python 侧自写 glTF2 解析器（struct/json，约 200 行）→ GPU 蒙皮（GLSL 顶点 shader）→ Blinn-Phong/PBR 近似光照按 web 端 4 灯+半球光+雾逐项对齐 → 骨骼覆盖层与关节球 → 自写轨道相机（web 端 OrbitControls 同参数：fov 34、min 7.2/max 18、阻尼 0.07）→ ACES 色调映射。UI 全部 Qt Widgets + QtCharts 曲线。
- **备选方案**：Qt Quick 3D RuntimeLoader（不确定性高）；QWebEngineView（违背需求，仅兜底）。
- **风险预警**：自绘方案开发量约 1000~1500 行（工作包 A/C）；"观感一致"允许细微光照差异，读数/曲线/姿态数值一致为硬标准；若目标机器缺 OpenGL 驱动（现代 Windows 均自带，风险极低）需回退 QWebEngine。
- **置信度**：90%（Qt3D 阻断性缺陷已实证，自绘路线为标准成熟方案）。
- **分区归属**：置顶区（技术路线重大，虽已授权自选，仍请你确认）。

## 自决区（已决策，理由如下；不同意请指出）

### Q3. web 端与 HTTP 服务的处置时序

- 需求定位：`需求说明.md` 第 3 行"将 web 端去掉"。
- 决策：开发与验收期间 **保留** `web/` 与 `tools/serve_app.py`（作为显示效果对照基准与回退），桌面应用验收通过后整体移入 `archived/`；新应用运行路径上 **不含** HTTP/SSE（串口会话直接嵌入 Qt 应用）。README 与 bat 同步改写。
- 理由：对照基准对"显示效果一致"的验收必不可少；提前删除会失去参照物。置信度 90%。

### Q4. 无硬件验收途径：模拟数据源模式

- 决策：新增"模拟数据源"（下拉项，与真实串口并列）：按 AA55 协议合成 6 节点姿态帧（预设手势：张手/握拳/侧摆序列），走真实解析管线驱动 UI。同时保留"自动连接唯一串口"行为（web 端 `viewer.js` 第 303 行 autoConnect）。
- 理由：启动测试门禁要求实际走通核心路径，无硬件时模拟源是唯一可测途径，且对演示有长期价值。置信度 95%。

### Q5. 运行方式与打包

- 决策：沿用 `启动上位机.bat` + `.venv` 模式（bat 改写：安装 pyserial + PySide6、直接启动桌面应用、不再开浏览器）；**不包含** PyInstaller 单文件 exe 打包（列为后续版本）。
- 理由：需求未提分发方式，与现状一致、改动最小。置信度 90%。

### Q6. 环境基线

- 决策：`requirements.txt` 更新为 `pyserial==3.5` + `PySide6==6.10.3`（已实测 Python 3.14.4 可装可用；6.11 移除 Qt3D 绑定且后续版本风险未知，故锁定 6.10.3）；bat 提示最低 Python 3.9（cp39-abi3）。
- 理由：版本锁定保证可复现。置信度 95%。

### Q7. UI 复刻范围（显示效果一致的具体口径）

- 决策：按 `web/index.html` + `web/style.css` 1:1 复刻：左侧 3D 视口（标题"灵巧手上位机"、状态徽章、FPS、重置视角/软组织/网格按钮、X/Y/Z 轴图例）+ 右侧 390px 面板（有线串口：端口/波特率下拉、刷新/连接/断开/重新标定、状态行；当前帧：时间/采样间隔/最大弯曲/最大侧摆/帧计数；五指角度：bend 0~90° 青色条 #49d9d0、sway ±30° 琥珀色条 #ffbd66、可点击选指；曲线：QtCharts 复刻 bend/sway 双线、-30~90° 刻度、当前帧竖线、400 帧滚动窗）；深色主题配色逐项沿用。食指/无名指 sway 显示符号翻转（`viewer.js` 第 22 行）与满握拳完成度映射（`hand-model.js` 第 29 行）一并移植。
- 理由：需求原话"显示效果和 web 端保持一致"。置信度 95%。

### Q8. 验收基准

- 决策：验收阶段在同机先运行现有 web 端对默认视角/皮肤半透明/骨骼覆盖层/手势动画截图存档，再对桌面应用同机截图逐项对比；读数与曲线数值一致性用同源模拟数据逐帧比对。
- 理由：客观、可复现、零猜测。置信度 95%。

### Q9. 代码结构

- 决策：新增 `app/` 包（`main.py` 入口、`main_window.py`、`hand_view.py`（QOpenGLWidget 渲染）、`gltf/`（解析器）、`hand_pose.py`（bend/sway→25 关节姿态映射，移植 `hand-model.js` 的 `#poseFinger` 与基变换 `C=Rz(-90°)`）、`quaternion.py`、`serial_panel.py`、`readout_panel.py`、`chart_panel.py`）；`tools/serve_app.py` 中的 `SerialLiveSession` 提取为 `tools/serial_live.py`（去 HTTP，线程 + 队列不变）；`tools/processed_pipeline.py` **零改动**（字节码恢复产物，直接 import）；`tests/` 用 pytest。
- 理由：协议解析已验证且被恢复说明背书，不动为妙；会话逻辑复用避免重写。置信度 95%。

### Q10. 单元测试

- 决策：pytest 覆盖新增核心逻辑：glTF 解析（节点/关节/蒙皮数据）、四元数基变换（X→-Y、Y→X 等方向断言）、bend/sway→关节角映射（满握拳完成度、sway ±30° 钳制、拇指/长指关节角）、串口会话（伪造 AA55 流 → 帧输出、标定命令字节、0.4s 标定窗口）、CRC16 回归。渲染层不做单测（GUI/GL），由启动测试覆盖。
- 理由：新功能强制单元测试门禁。置信度 95%。

### Q11. 单实例运行

- 决策：桌面应用用 `QLockFile` 保证单实例（原"端口占用检测"逻辑随 HTTP 一起废弃）。
- 理由：桌面应用惯例，避免双开串口冲突。置信度 95%。

### Q12. 版本标记

- 决策：验收通过后打 tag `v1.0.0`；产出物目录沿用 `Document/v1.0 C++化/`。
- 理由：与目录命名保持一致。置信度 95%。
