# 模块审查 04：掌指相对姿态与方向分解

## 1. 审查范围

主要文件：

- `src/hand/hand_observation_solver.*`
- `src/hand/orientation_decomposition.*`
- `src/hand/mount_calibration.*`
- `src/core/hand_observation_types.h`
- `src/fusion/quaternion_util.h`
- `tests/test_hand_observation.cpp`
- `assets/hand_rig_generic_left.json`

## 2. 模块结论

**结论：不通过。**

掌指相对四元数公式本身正确，但后续方向分解不是合法的三自由度分解，传感器观测 basis 没有进入运行时，mount 和 neutral 的 frame 语义也没有冻结。

这是巨大 twist、屈伸/张合串轴和事实性错误角度的最直接根因之一。

## 3. 可保留部分

### 3.1 掌指相对公式

在 `worldFromSensor` 主动 Hamilton 契约下：

```text
qRelative = inverse(qWristWorld) * qFingerWorld
```

公式正确。共同世界左乘会被消除：

```text
inverse(qCommon*qWrist) * (qCommon*qFinger)
= inverse(qWrist) * qFinger
```

不应为了修符号而改成 `finger * inverse(wrist)`。

### 3.2 六路同 sequence 检查

finger 和 wrist 必须属于同一 sequence 才生成观测，这一门禁合理。

### 3.3 无效姿态拒绝

零模、非有限、stale 和 invalid 姿态不会直接进入 decomposition，方向正确。

### 3.4 中立姿态作为独立状态

中立校准与融合 reset 分离是合理分层，失败时保持旧 neutral 也比半更新安全。

## 4. 已证实缺陷

## H01：`decomposeOrientation()` 不是三轴分解

当前对同一单位四元数 `q=(w,v)` 和每根轴 a 计算：

```text
angle(a) = 2 * atan2(dot(v,a), w)
```

然后把三次结果分别命名为 flexion、abduction、twist。

问题：

- 每个结果都来自完整 q；
- 没有先去除 twist；
- 没有固定 intrinsic/extrinsic 旋转顺序；
- 三个结果彼此不独立；
- 不能与骨骼 compose 顺序往返；
- 接近 180° 时 w 接近 0，所有非零投影都趋近大角度。

严重度：**Critical**。

## H02：实际样本证明三个角无法回构姿态

仓库真实录制末帧中，Middle 输出约：

```text
flexion  = -162.0°
abduction = -153.0°
twist     = -175.6°
```

原始相对四元数的最短总旋转约 175.8°。使用当前骨骼顺序组合这三个输出，重构结果与原姿态相差约 175.6°。

这证明当前字段不是可组合的姿态参数。

严重度：**Critical**。

## H03：对 `q` 与 `-q` 不等价

单位四元数 q 与 -q 表示同一旋转。当前公式直接使用 w：

```text
q = Rz(10°)  → 约 10°
-q           → 可能得到约 -350°
```

PoseGuard 的时间符号连续能降低部分运行时翻转，但 decomposition 作为数学函数仍必须满足符号等价。

旧 archived 实现至少使用 `abs(w)` 限制到最短角，而当前主线丢掉了这项保护。

严重度：**High**。

## H04：观测 basis 固定为所有手指共用 XYZ

`FingerObservationConfig` 默认：

```text
flexionAxis  = +X
abductionAxis = +Y
twistAxis     = +Z
```

RuntimeController 只填 sensorId 和 mount，没有从配置传入每指 basis。

后果：

- Thumb 与长指使用同一 basis；
- 五根手指物理安装差异无法表达；
- 传感器轴与模型关节轴没有端到端对应；
- 一个真实屈曲可能被输出为 abduction 或 twist。

严重度：**Critical**。

## H05：mount 共轭方向没有 frame 契约

当前：

```text
qCorrected = mount * qRelative * inverse(mount)
```

共轭作为 basis change 是合理形式，但 mount 到底表示：

- anatomicalFromSensor；还是
- sensorFromAnatomical；

代码、JSON 字段和测试都没有定义。

现有测试把同一表达式复制为 expected，只能证明实现和自己相等，不能证明物理方向正确。

严重度：**High**。

## H06：neutral 顺序的输出 frame 未定义

当前：

```text
qDelta = inverse(qNeutral) * qCurrent
```

如果 axes 定义在 neutral finger local frame，该公式可能正确；如果 axes 定义在 palm frame，则应使用另一顺序。

当前测试 neutral/current 始终绕同一个 X 轴，可交换，因此没有冻结非交换情况下的 frame 语义。

严重度：**High，语义未冻结；不能直接通过交换顺序修复。**

## H07：HandSide 只作为元数据

解算过程没有右手 basis 或镜像处理。镜像不是普通四元数旋转，不能简单对全部角度乘 -1。

严重度：**Medium/High**。

## H08：输出没有可观测性状态

`twistDegrees` 总是一个 float，没有表示：

- 6D 下长期不可观测；
- 磁场未标定；
- 接近分解奇异区；
- 轴 basis 不可信；
- 当前值来自短时 gyro 还是稳定 9D。

UI 因而容易把低置信 twist 展示成事实角度。

严重度：**High**。

## 5. 现有测试缺口

`test_hand_observation` 主要覆盖：

- common palm rotation cancels；
- 纯 X 单轴；
- mount 表达式自我复制；
- invalid freeze；
- 同轴 neutral。

缺少：

- compose/decompose 往返；
- 混合轴；
- q/-q 等价；
- 接近 180°；
- non-commutative neutral；
- 90° mount 物理轴 oracle；
- 每指独立 basis；
- 右手；
- twist 不可观测状态；
- actual rig 端到端方向。

## 6. 对用户症状的影响

| 症状 | 本模块解释 |
| --- | --- |
| twist 特别大 | w≈0 时三次投影同时给出大角；basis/mount 错误又把屈伸投进 twist |
| 屈伸和张合不对 | 所有手指固定 XYZ，没有真实解剖 basis |
| 同一姿态角度事实性错误 | 三个角无法重构原四元数 |
| 偶发接近整圈 | q/-q 不等价和缺少最短弧规范 |
| 调零后复合动作仍错轴 | neutral 输出 frame 没有契约，测试只覆盖同轴 |

## 7. V2.1 修复要求

1. 采用 `q_A_B` 命名冻结每个四元数 frame；
2. 在绝对解剖姿态阶段应用 wrist/finger 各自安装外参；
3. 明确 neutral delta 输出在 neutral anatomical frame；
4. 为每指定义正交右手 basis；
5. 使用真正 swing/twist：
   - 提取 longitudinal twist；
   - 从完整 q 去除 twist；
   - 用 swing 后的指向量计算 flex/abd；
6. 或实现与唯一 compose 顺序严格互逆的序列分解；
7. q/-q 结果一致；
8. 奇异区返回 Invalid/低置信，不伪造精确角；
9. 长指 6D twist 默认低置信或锁定；
10. Thumb 使用独立 basis；
11. HandObservation 增加 component observability/confidence。

## 8. 验收门禁

- `decompose(compose(f,a,t))` 在限位内恢复输入；
- `compose(decompose(q))` 与 q 角误差小于阈值；
- q 与 -q 输出一致；
- 纯 flex 不产生显著 abd/twist；
- 纯 abd 不产生显著 flex/twist；
- 170°+20° 输入不产生未约束假角；
- neutral Z90° 后的局部动作方向由 oracle 冻结；
- mount Z90° 能把 sensor +X 正确映射到指定 anatomical 轴；
- Thumb/Index 使用不同 basis 的测试通过；
- 6D twist 被标记为低置信；
- 实际 rig 和 GLB 端到端正屈曲方向正确。

## 9. 最终判断

该模块必须重写，不能通过给输出角乘负号或增加 clamp 修复。应保留掌指相对四元数公式，重新定义安装、中立和分解的 frame 语义，并建立严格数学往返测试。
