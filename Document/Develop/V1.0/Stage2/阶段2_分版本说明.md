# 阶段 2：SlimeVR Windows 接入 PoC 分版本说明

## 1. 文档目的

本文将 `Document/Develop/V1.0/需求说明.md` 中“阶段 2：SlimeVR Windows 接入 PoC”拆分为四个可独立验收的小版本，作为后续设计、开发、问题跟踪和验收的范围基线。

阶段 2 的目标是：在不改变现有六 IMU 串口、协议解析、同 `SEQ` 分组和姿态融合行为的前提下，由 Windows Qt 工具将一个手套设备的六路姿态稳定发送到 SlimeVR Server。

本阶段只完成接入 PoC，不提前实施陀螺零偏、磁力计校准、磁干扰拒绝、VQF 选型或 ESP 移植。

## 2. 拆分原则

- 每个小版本都必须有可观察、可测试、可回退的交付结果；
- 先固定协议和数据契约，再接入真实姿态，最后处理坐标和长稳；
- 网络输出层不得反向侵入协议解析器、分组器或融合算法；
- 六路 Sensor ID 在阶段 2 内保持稳定，不因左右手切换而改变；
- 左右手只改变设备类型、骨骼位置和必要的坐标配置；
- 自动测试优先使用本地 UDP 假服务器，不依赖真实 SlimeVR Server；
- 真实 Server 和真实硬件测试作为集成验收，不替代单元测试；
- 所有高频队列、缓存和统计必须有界。

## 3. 小版本总览

| 小版本 | 名称 | 核心产出 | 前置依赖 | 退出条件 |
| --- | --- | --- | --- | --- |
| `V1.0-S2.1` | UDP 协议与会话基座 | 可测试的 SlimeVR UDP 编解码、发现、握手、心跳和会话状态 | 阶段 1 基线可运行 | 假服务器可稳定建立、保持和重建会话 |
| `V1.0-S2.2` | 六传感器注册与姿态发送 | 一个设备、六个 SensorInfo、六路 RotationData、50–100 Hz 节流 | `S2.1` | Server 可识别六路且无串路 |
| `V1.0-S2.3` | 左右手、映射与坐标转换 | 左右手配置、节点映射、四元数顺序和安装旋转 | `S2.2` | 六路单轴动作方向和节点归属正确 |
| `V1.0-S2.4` | 集成、重连与 PoC 验收 | UI/日志诊断、Server 重启恢复、30 分钟稳定性报告 | `S2.3` | 阶段 2 全部完成标准通过 |

## 4. 固定接口基线

### 4.1 六路逻辑 Sensor ID

阶段 2 固定使用连续 ID，避免沿用十传感器手套固件中的间隔 ID：

| 模组地址 | 语义 | Sensor ID | 左手位置 | 右手位置 |
| --- | --- | ---: | --- | --- |
| `0x50` | Wrist | `0` | `POSITION_LEFT_HAND` | `POSITION_RIGHT_HAND` |
| `0x51` | Thumb | `1` | `POSITION_LEFT_THUMB_DISTAL` | `POSITION_RIGHT_THUMB_DISTAL` |
| `0x52` | Index | `2` | `POSITION_LEFT_INDEX_DISTAL` | `POSITION_RIGHT_INDEX_DISTAL` |
| `0x53` | Middle | `3` | `POSITION_LEFT_MIDDLE_DISTAL` | `POSITION_RIGHT_MIDDLE_DISTAL` |
| `0x54` | Ring | `4` | `POSITION_LEFT_RING_DISTAL` | `POSITION_RIGHT_RING_DISTAL` |
| `0x55` | Pinky | `5` | `POSITION_LEFT_LITTLE_DISTAL` | `POSITION_RIGHT_LITTLE_DISTAL` |

若真实安装段不是 distal，必须以配置和验证记录修正文档；不得将一颗指尖 IMU 复制成多个关节节点。

### 4.2 网络数据契约

- 姿态输入以 Windows MVP 的单位四元数为准；
- 内部姿态类型必须用命名字段或明确类型表示，禁止裸数组隐含顺序；
- SlimeVR `RotationData` 载荷顺序固定为 `x, y, z, w`；
- 网络字节序遵循现有 SlimeVR UDP 协议，不直接发送宿主机结构体内存；
- 每个 UDP 包必须包含协议要求的包类型和递增包号；
- 非有限值、近零范数或归一化失败的四元数不得发送；
- 融合维持原始约 `200 Hz`，网络默认 `75 Hz`，允许配置 `50–100 Hz`；
- 每次网络 tick 最多发送每个传感器最新一帧，不积压历史姿态。

### 4.3 模块边界

建议新增下列职责，具体类名可在设计阶段调整：

```text
SixImuSolver::snapshotReady
    ↓
SlimeVrPoseAdapter
    ├─ Sensor ID / 位置映射
    ├─ 四元数顺序与坐标转换
    └─ 数据有效性检查
    ↓
SlimeVrUdpClient
    ├─ 发现 / 握手 / 心跳
    ├─ SensorInfo
    ├─ RotationData
    └─ 重连与统计
    ↓
QUdpSocket
```

协议编解码应尽量是无 UI 状态的独立模块；UI 只负责配置和展示，不拼包、不做坐标数学运算。

## 5. 版本依赖与冻结点

### 5.1 `S2.1` 完成后冻结

- UDP 数据报头、包号和字节序；
- 发现、握手、心跳和重连状态机；
- 协议编解码测试样例。

### 5.2 `S2.2` 完成后冻结

- 六路 Sensor ID；
- SensorInfo 与 RotationData 的发送接口；
- 发送节流和“最新值覆盖”策略。

### 5.3 `S2.3` 完成后冻结

- 左右手位置映射；
- 四元数输入/输出顺序；
- 每路固定安装旋转的配置表达；
- 逐路动作验证表。

### 5.4 `S2.4` 完成后冻结

- 阶段 2 用户操作流程；
- 网络诊断字段；
- 重连行为和 30 分钟稳定性基线。

## 6. 跨版本非功能要求

- Windows Qt 工具在未启用网络输出时行为必须与阶段 1 一致；
- Server 不可达、关闭或重启不得阻塞串口与融合线程；
- UDP 错误不得弹出高频对话框；
- 关闭窗口必须停止网络定时器并释放 socket；
- 开关网络输出、切换左右手、重复连接和断开必须幂等；
- 网络统计至少包括：会话状态、目标地址、发送包数、发送错误数、最近发送时间、实际发送率、最近接收时间和重连次数；
- 单元测试不得访问公网，不得依赖固定局域网地址；
- 日志不得逐姿态帧默认刷屏；
- 新增设置必须支持默认值、保存、加载和非法值回退。

## 7. 阶段 2 统一完成标准

全部小版本完成后，同时满足：

1. SlimeVR Server 识别一个左手或右手手套设备及六个传感器；
2. 六路地址、Sensor ID 和节点位置一一对应；
3. 四元数顺序正确，单位旋转和三个正向单轴旋转结果可解释；
4. 左右手配置均可用，切换后不会遗留旧会话映射；
5. 融合约 `200 Hz` 时网络发送稳定在配置的 `50–100 Hz`；
6. Server 重启后客户端可自动重新发现、握手和注册；
7. 连续运行 30 分钟无崩溃、断连、NaN、无界内存或队列增长；
8. 自动测试、真实 Server 测试和坐标验证记录齐全；
9. 阶段 2 未夹带阶段 3 及后续算法优化。
