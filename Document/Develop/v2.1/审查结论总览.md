# V2.1 姿态解算审查结论总览

## 1. 审查对象

本次审查针对当前主线：

```text
Document/Research/手套IMU解算MVP/
```

审查范围覆盖：

- 核心数据契约与运行时配置；
- 串口协议、分组、时间戳、录制与回放；
- 原始参数校准、零偏、磁校准和姿态融合；
- 掌指相对姿态、安装修正、中立姿态和方向分解；
- 指尖观测到多关节的约束映射；
- GLB 导入、虚拟骨骼层级、FK、蒙皮和渲染；
- 应用编排、UI 语义、测试、验收报告和文档一致性。

审查方式包括：

- 静态代码追踪；
- 数学公式往返验证；
- 目标 GLB 绑定轴和几何方向分析；
- 仓库现有真实录制数值统计；
- skeleton frame 关节点位移统计；
- 现有目标测试复跑；
- V2.0 需求、设计、完成报告与实现对照。

本次审查只读进行。除本目录下新增 V2.1 文档外，没有修改当前主线源码，也没有覆盖工作区已有未提交改动。

## 2. 总体结论

### 2.1 产品级结论

当前实现已经具备“数据能够从串口流到达模型渲染”的软件闭环，但尚不具备“手指姿态和关节方向正确”的产品闭环。

当前 `flexion/abduction/twist` 不应被视为可信的解剖学分量，当前骨骼结果也不应被视为正确的递归手指运动学结果。

用户观察到的以下现象均能由代码中的确定性问题直接解释：

- 只有反关节或反方向运动；
- 屈伸和张合错轴；
- twist 过大；
- 多个角度同时接近 ±180°；
- 指节看似旋转，但骨链没有正常卷曲；
- 手腕姿态不驱动整手；
- 同一指尖观测被放大为不合理的整链角度。

### 2.2 不是所有模块都错误

以下基础能力总体可保留：

- 帧头、长度、CRC 和大端 int16 解析；
- 地址到 Wrist/Thumb/Index/Middle/Ring/Pinky 的映射；
- 同 sequence 六路分组；
- raw 录制和统一回放入口；
- 四元数有限性、范数和符号连续保护；
- `inverse(wrist) * finger` 掌指相对姿态公式；
- dps 到 rad/s 的单位换算公式；
- GLB 顶点、权重、inverse bind 和 palette 名称导入；
- UI、诊断和录制框架。

主要失败集中在：

```text
配置没有真实生效
+ 坐标契约没有冻结
+ 方向分解数学错误
+ 指尖总姿态到关节角的映射语义错误
+ 骨骼 FK 实现错误
+ 测试缺少物理 oracle
```

## 4. 最高优先级已证实缺陷

## P0-01：方向分解不是合法分解

生产代码对同一四元数 `q=(w,v)` 分别计算：

```text
2 * atan2(dot(v, flexAxis), w)
2 * atan2(dot(v, abductionAxis), w)
2 * atan2(dot(v, twistAxis), w)
```

该结果只在纯单轴输入下表现正确，不能作为同时存在的三个独立角，也不能与骨骼端 `qFlex*qAbduction*qTwist` 往返。

实际仓库样本曾输出：

```text
middle: flexion=-162.0°
abduction=-153.0°
twist=-175.6°
```

使用这三个角重构姿态，与原始相对四元数的角距离约为 `175.6°`。这说明输出不只是噪声大，而是数学语义不成立。

## P0-02：当前 FK 不会移动关节点

生产公式为：

```text
global = root * bindWorld * accumulatedDelta
```

`accumulatedDelta` 是纯旋转，右乘不会改变 `bindWorld` 的平移列。父关节转动不会把子关节位置绕父 pivot 移动。

对仓库现有数据统计：

- 554 帧 demo；
- 3968 帧真实录制；
- 所有关节点最大位移均为 `0`。

当前可见变化主要来自每根 bone 的 skin matrix 在各自绑定点附近扭曲网格，不是正确骨链卷曲。

## P0-03：模型关节正方向与配置相反

目标 GLB 的关节 bind rotation 非单位旋转。对实际食指近节检查：

- 当前配置的 local `+X` 屈曲轴映射到模型空间后接近 `-Z`；
- 由掌面法向和指段方向得到的掌心屈曲轴接近 `+Z`；
- 二者接近 170° 反向。

因此即使上游 flexion 数值本身正确，当前 `+X` 关节配置也会把正屈曲施加到反方向。张合轴也存在类似符号问题。

## P0-04：指尖总角被重复放大

以食指为例，当前屈曲 coupling 合计：

```text
0.35 + 0.55 + 0.75 + 0.90 = 2.55
```

90° 指尖累计姿态可被映射为约 229.5° 的整链累计屈曲。当前实现既没有先换算成归一化 curl，也没有求解“预测指尖姿态应匹配观测”的约束。

## P0-05：配置存在但不生效

当前同时存在：

- `RuntimeOptions::configPath`；
- runtime config parser；
- rig 内 mount；
- calibration params；
- FusionBank 自己的 calibration params。

但产品初始化没有把 runtime config 加载并应用到这些模块。默认 JSON 使用的字段形式又与 parser 要求不一致。结果是用户即使提供正确量程、轴映射和安装四元数，也不会进入生产解算。

## 5. 症状到根因映射

| 用户现象 | 直接原因 | 放大因素 |
| --- | --- | --- |
| 只有反关节运动 | 模型 local flexion 正轴与掌心方向接近相反 | 观测轴未标定、负角限位不对称 |
| twist 很大 | 三次投影分解、接近 180° 时分量同时变大 | mount 未生效、六轴相对 yaw 漂移、twist 逐级累计 |
| 屈伸变成张合 | 观测 basis 固定 XYZ，和模型/传感器 basis 未统一 | 安装四元数为单位值或配置无效 |
| 手指只扭不卷曲 | 非递归 FK，关节点位置不随父节点移动 | renderer 直接消费错误 skin matrix |
| 角度事实性错误 | 指尖总角直接乘 coupling 后施加到多关节 | metacarpal 被驱动、PIP/DIP 允许大 twist |
| 手腕不跟随 | skeleton 只检查 wrist 有效性，没有应用 wrist orientation | 固定 display root 掩盖了缺失 |
| 测试全部通过但视觉错误 | 测试缺少正屈曲、子树位移和混合旋转 oracle | 验收报告把“可运行”解释为“功能通过” |

## 6. 数学上可确认正确或应保留的部分

### 6.1 掌指相对公式

在 `worldFromSensor` 主动 Hamilton 契约下：

```text
qRelative = inverse(qWristWorld) * qFingerWorld
```

公式本身正确，不应为了修方向而随意交换乘法顺序。

### 6.2 四元数分量顺序

当前核心统一使用 `wxyz`，GLB `[x,y,z,w]` 到 Qt `QQuaternion(w,x,y,z)` 的转换方向正确。

### 6.3 单位换算

当前陀螺仪：

```text
raw / 32768 * rangeDps * pi / 180
```

公式正确。真正未关闭的是硬件实际量程是否与默认值一致，以及该配置是否进入产品路径。

### 6.4 串口协议

当前 25 字节帧、`AA55`、长度 `0x12`、九个大端 int16 和 Modbus CRC16 的实现与协议文档一致。

## 7. 需要条件性判断的问题

以下项目存在风险，但不能在缺少真实硬件基线时直接定性为当前巨大 twist 的首要根因：

### 7.1 200 Hz 固定时间步

实测约 198.3 Hz，与 200 Hz 相差不足 1%。固定 5 ms 会产生小比例角度误差，但单独不能解释 100° 以上的错误分量。

V2.1 仍应分离 sample time 与 receive time，以避免采样率变化或丢组时积分错误。

### 7.2 VQF acc/mag 固定系数

当设备真实固定率采样、仅串口批量到达时，acc/mag 使用固定采样周期可能是合理行为。只有设备采样率真实变化时才需要动态重配置，必须用不同采样率轨迹测试后决定。

### 7.3 neutral 乘法顺序

`inverse(neutral) * current` 或 `current * inverse(neutral)` 的正确性取决于输出增量所在 frame。当前主要问题是 frame 未写清且测试只覆盖可交换单轴输入；不能只靠交换顺序修复。

### 7.4 mount 共轭方向

`m*q*inverse(m)` 是否正确取决于 m 表示 sensor→anatomical 还是反向。当前字段没有冻结该语义，且配置没有真正生效。V2.1 必须先命名 frame，再由 90° 安装物理 oracle 冻结方向。

## 8. 自动测试复核结论

复跑以下现有目标：

- `test_runtime_config`
- `test_fusion`
- `test_hand_observation`
- `test_skeleton_solver`

结果为 4/4 通过。

这些测试没有推翻审查结论，原因是：

- 方向分解主要只测纯 X 单轴；
- mount expected 复制生产表达式；
- neutral 测试使用可交换的同轴旋转；
- skeleton 测试不检查活动指尖是否移动；
- 不检查正屈曲是否朝掌心；
- 不检查非目标子树是否保持静止；
- 不检查 wrist 是否驱动整手；
- 不检查默认 runtime asset 是否在产品中真正生效。

## 9. 审查后的优先级

### P0：先修，否则任何视觉调参都不可信

1. 冻结坐标和四元数 frame 契约；
2. 接通唯一 runtime 配置真源；
3. 建立数学和物理红灯测试；
4. 重写方向分解；
5. 重写虚拟层级递归 FK；
6. 修正关节自由度和 coupling 语义；
7. 接入腕部根姿态。

### P1：P0 正确后处理精度和鲁棒性

1. sample time 与 receive time 分离；
2. invalid 样本状态推进顺序；
3. 磁校准生产接线；
4. 6D/9D 置信度和恢复；
5. Madgwick/VQF 同数据轨迹对比；
6. 真实逐指动作和 10 分钟漂移。

### P2：产品扩展

1. 右手镜像 basis；
2. 更完整的拇指优化模型；
3. 温漂模型；
4. 更通用的 glTF scene/mesh/skin 支持；
5. 有界最小二乘关节估计。

## 10. 最终判断

当前项目的主要问题不是“传感器有一点漂移”，而是手部解算层存在结构性错误：

```text
角度定义不成立
+ 关节轴没有统一
+ 指尖总姿态被错误分配
+ FK 没有移动骨链
```

因此，当前结果不适合通过继续调整符号、限位或 UI 参数进入验收。正确路线是执行本目录中的 V2.1 修复计划，从失败测试、坐标契约和递归 FK 开始重建。
