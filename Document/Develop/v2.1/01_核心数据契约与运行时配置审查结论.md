# 模块审查 01：核心数据契约与运行时配置

## 1. 审查范围

主要文件：

- `Document/Research/手套IMU解算MVP/src/core/`
- `Document/Research/手套IMU解算MVP/src/config/runtime_config.*`
- `Document/Research/手套IMU解算MVP/src/calibration/calibration_parameters.*`
- `Document/Research/手套IMU解算MVP/src/app/main.cpp`
- `Document/Research/手套IMU解算MVP/src/app/runtime_controller.*`
- `Document/Research/手套IMU解算MVP/assets/default_runtime.json`
- `Document/Research/手套IMU解算MVP/assets/hand_rig_generic_left.json`
- `Document/Research/手套IMU解算MVP/tests/test_runtime_config.cpp`

## 2. 模块结论

**结论：不通过。**

核心数据类型的分层设计可以保留，但运行时配置没有形成产品闭环。当前存在“配置结构、配置文件、CLI 参数和模块内部参数都存在，但彼此没有真正接通”的情况。

这不是单纯缺少 UI，而是会直接导致以下生产参数不生效：

- 加速度量程；
- 陀螺仪量程；
- acc/gyro/mag 轴重映射；
- 每路 IMU 安装外参；
- 磁校准有效状态；
- FusionBank 使用的校准状态。

## 3. 可保留部分

### 3.1 数据分层

以下类型职责总体合理：

- `RawImuFrame`：原始协议数据；
- `CalibratedImuSample`：物理单位后的校准数据；
- `FusedImuPose`：单路姿态输出；
- `HandObservationFrame`：掌指相对观测；
- `HandSkeletonFrame`：骨骼求解结果。

继续保留“原始输入、融合姿态、手部观测、骨骼结果”四层边界是正确方向。

### 3.2 SensorId 与地址映射

`0x50..0x55` 到 Wrist/Thumb/Index/Middle/Ring/Pinky 的稳定映射清楚，适合继续作为数组槽位和配置索引。

### 3.3 配置 parser 的基本校验思想

parser 已考虑：

- schema version；
- 六路数量；
- 地址唯一；
- 有限数；
- 单位四元数；
- 正量程。

这些校验可保留并扩展为 V2.1 schema。

## 4. 已证实缺陷

## C01：`configPath` 没有被产品初始化消费

`main.cpp` 建立了 `RuntimeOptions::configPath`，但 `RuntimeWorker::initialize()` 只加载模型和 hand rig，没有调用 `loadRuntimeConfigFile()`，也没有向 CalibrationPipeline/FusionBank 应用六路配置。

结果：

```text
--config 参数存在
→ 文件路径进入 RuntimeOptions
→ 生产初始化不读取
→ 用户修改不影响姿态
```

严重度：**Critical**。

## C02：默认 JSON 与 parser schema 不一致

默认 asset 使用：

```json
"mountOrientation": [1, 0, 0, 0]
```

parser 要求：

```json
"mountQuaternion": {
  "w": 1,
  "x": 0,
  "y": 0,
  "z": 0
}
```

因此即使未来直接接上当前 parser，默认配置也会被判无效。

严重度：**Critical**。

## C03：存在多个 mount 真源

当前至少存在：

1. runtime sensor config 中的 `mountOrientation`；
2. hand rig 顶层 `mountOrientations`；
3. `FingerObservationConfig::mountOrientation`；
4. 中立姿态保存的 finger neutral。

但生产实际只把 hand rig 中五个单位四元数复制到 observation solver。runtime 的六路 mount 没有生效，wrist mount 也没有进入掌指链路。

多真源会导致：

- 重复应用；
- 只应用一部分；
- 配置 UI 修改错误对象；
- 无法判断 mount 表示 sensor→anatomical 还是反向。

严重度：**Critical**。

## C04：CalibrationPipeline 与 FusionBank 各自保存参数但不同步

CalibrationPipeline 拥有 `SensorCalibrationParams`，FusionBank 的 Channel 也保存一份 `SensorCalibrationParams`。

产品初始化没有统一向两者注入同一配置。当前工作树中 FusionBank 判断 `magnetometerCalibrated` 后才启用磁场，但生产链没有把已标定状态设置进去，因此会长期保持 6D。

严重度：**High**。

## C05：schema 没有表达完整坐标语义

当前配置只给出一个含义不明的 mount 四元数，没有明确：

- 源 frame；
- 目标 frame；
- 主动/被动旋转；
- 安装四元数在绝对姿态前应用还是对相对旋转做共轭；
- 每指传感器观测轴；
- IMU 对应的是 distal、intermediate 还是其他指段；
- 左右手镜像策略。

严重度：**High**。

## C06：测试只验证 parser，不验证产品消费

`test_runtime_config` 能验证合法/非法 JSON，但没有：

- 用默认 asset 启动产品；
- 验证 `--config` 改变量程后输出变化；
- 验证某一路 mount 只改变对应手指；
- 验证 runtime config 与 rig 不重复应用。

因此配置完全不生效仍能保持测试全绿。

严重度：**High**。

## 5. 对用户症状的影响

| 症状 | 本模块贡献 |
| --- | --- |
| 屈伸方向反了 | 正确轴映射和安装外参无法进入生产链 |
| 动作串到 twist | sensor basis 仍使用默认 XYZ |
| 各指表现不同 | 每块 PCB 的真实安装差异没有被配置修正 |
| 角度幅值可能不对 | 实际量程无法通过 runtime config 生效 |
| 磁场状态不符合预期 | FusionBank 使用的 calibration state 与 CalibrationPipeline 不同步 |

## 6. V2.1 修复要求

1. 升级 runtime schema；
2. 只保留一个传感器配置真源；
3. 明确保存 `sensorFromAnatomical` 或等价带 frame 的字段名；
4. wrist 与五指均保存独立外参；
5. per-sensor 配置包含量程、三组轴映射、零偏、磁校准和采样周期；
6. hand rig 只保存模型关节、解剖 basis、关节限位和耦合参数；
7. `RuntimeWorker::initialize()` 必须加载并验证配置；
8. 同一参数对象或不可变配置快照注入 CalibrationPipeline 与 FusionBank；
9. config hash 写入录制 metadata；
10. 配置变化使旧 neutral/mount calibration 失效。

## 7. 验收门禁

- 默认 runtime JSON 被生产 parser 成功加载；
- `--config` 指定不同量程后，合成 gyro 积分结果按比例变化；
- 单独修改 Thumb mount 只改变 Thumb 解剖输出；
- 配置非法时产品启动失败，不静默使用单位四元数；
- CalibrationPipeline 与 FusionBank 对同一路返回一致 calibration state；
- 录制 metadata 能追溯配置版本和 hash；
- 测试覆盖实际 `RuntimeController` 初始化，而不只调用 parser。

## 8. 最终判断

核心类型不需要推倒重来，但配置链必须在任何姿态算法调参前修复。只要 runtime 参数仍不生效，后续对轴、mount、磁场和量程的所有“修正”都无法形成可验证产品结果。
