# V1.0-S2.1 完成报告

## 1. 版本目标

建立可测试、可重连的 SlimeVR UDP 协议与会话基座：握手、发现响应解析、心跳回复、PingPong 回显、超时退避和统计。

## 2. 协议核查结论

依据官方 SlimeVR Server `v20.1.0`（提交 `81a46c2`）源码与 ESP 固件交叉核查，完整事实表见本目录 `协议核查.md`。要点：

- 普通包头：3 个零字节 + 1 字节包类型 + 8 字节大端包号；
- Server 默认监听 UDP `6969`，客户端本地可用临时端口；
- 发现响应：64 字节，前 13 字节为 `03` + `Hey OVR =D 5`；
- Server 不按 board/mcu/protocol version 拒绝握手，未知枚举映射 UNKNOWN；
- 心跳由 Server 发起（类型 1），tracker 回类型 0；PingPong 原样回显；
- 握手字段顺序与固件 `sendTrackerDiscovery()` 一致。

关键行为覆盖：握手黄金字节、字段布局、长字符串拒绝、发现响应前缀识别、大端整数/浮点、握手连接、心跳回复、超时退避重连、异常来源拒绝、停止后不再发包、端口可复用、广播发现（本机支持全局广播回送，实测通过）、非法设置拒绝。

## 5. 关键决策

- 广播模式重连时同时向“上次已知 Server 地址”单播，兼容丢弃全局广播的网络；
- 退避固定 `1000 ms`，与固件搜索节奏一致；
- 默认端口 `6969`，本地绑定临时端口（同机 Server+客户端可共存）；
- 修复记录：普通包类型为偏移 3 的单字节（3 零字节头），初始实现误读为偏移 3 的 u32 大端，已由假服务器黄金字节测试锁定。

## 6. 遗留问题

- `Q-S2.1-11`（P2）：多网卡定向广播未实现；
- `Q-S2.1-12`（P2）：固定地址暂不支持 DNS 主机名；
- `Q-S2.1-13`（P3）：Server 侧心跳频率未逐一核实（不影响客户端行为）；
- 真实 Server 验证由 S2.4 统一执行。

## 7. 给下一版本的接口

`SlimeVrUdpClient` 提供 `applySettings/setIdentity/start/stop/reset/isConnected/sendNormalPacket` 与 `stateChanged/statisticsChanged/protocolError` 信号；`SlimeVrProtocol` 提供握手、心跳、普通包和浮点编解码，S2.2 直接在其上扩展 SensorInfo 与 RotationData。
