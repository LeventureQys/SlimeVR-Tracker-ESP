## 2. 模块结论

**结论：不通过。**

现有测试框架、CTest 集成和测试数量可以保留，但测试内容没有覆盖姿态正确性的核心物理门禁。部分完成报告与生产实现不一致，验收矩阵把“合成对象能流过链路”解释为“动作功能通过”。

因此当前“18/18 通过”只能证明工程可构建、接口可调用、输出有限和生命周期基本稳定，不能证明手指方向、角度和 FK 正确。

## 4. 已证实测试缺口

## T01：方向分解测试只覆盖纯单轴

纯 X 旋转时，错误的向量投影公式恰好给出正确 X 角，因此测试无法发现混合旋转串轴。

缺少：

- mixed-axis；
- q/-q；
- near-180°；
- round-trip；
- zero-twist composite；
- singularity degradation。

严重度：**Critical**。

## T02：mount 测试复制生产表达式

expected 直接写：

```text
mount * relative * mount.conjugated()
```

这只能冻结当前代码顺序，不能证明 mount 的物理 frame 含义正确。

应使用独立 oracle：例如 Z90° mount 将 sensor +X 映射到明确 anatomical +Y。

严重度：**High**。

## T03：neutral 测试只用可交换同轴旋转

neutral 和 current 都绕 X，无法区分：

```text
inverse(neutral) * current
```

与：

```text
current * inverse(neutral)
```

在不同输出 frame 下的语义。

严重度：**High**。

## T04：skeleton 测试不检查活动关节点位移

测试给出 flexion=200° 后，只检查：

- bone.valid；
- source；
- 同输入 deterministic。

没有断言：

- tip 是否移动；
- tip 是否靠近掌心；
- parent 是否移动 child；
- 骨长是否保持；
- 非目标手指是否不动。

因此“所有 joint displacement=0”的实现仍能通过。

严重度：**Critical**。

## T05：wrist 测试只检查 invalid freeze

没有给一个有效非单位 wrist orientation 并断言整手发生正确刚体旋转，所以生产代码完全忽略 wrist 仍能通过。

严重度：**High**。

## T06：runtime config 测试只测 parser

没有通过 RuntimeController 启动产品，也没有验证配置变化影响实际 calibration/fusion/observation。

严重度：**Critical/High**。

## T07：融合测试缺少真实轨迹误差

现有测试大多验证 valid、norm、mode 和字段统一，缺少：

- 198/200/202 Hz；
- 多轴 ground truth；
- invalid 插入；
- wrist/finger relative；
- 10 分钟漂移；
- 磁干扰恢复轨迹。

严重度：**High**。

## T08：真实录制缺少动作标签和同步视频

现有 hardware session metadata 多数只写 `actionDescription=serial`，axes/ranges/sensorMounts 为空。

无法判断某一时刻：

- 哪根手指在动；
- 动作方向；
- 真实角度大致多少；
- 是否静置；
- 是否已调零；
- 是否有磁干扰。

这些录制适合复核链路和数值范围，不足以作为姿态正确 ground truth。

严重度：**High**。

## 5. 文档与实现不一致

## D01：完成报告声称递归 FK，生产代码不是

SubStage4 完成报告描述：

```text
local = bindLocal * configuredRotation
global = parentGlobal * local
skin = rootTransform * virtualGlobal * inverseBind
```

生产代码实际为：

```text
global = rootTransform * bindWorld * accumulatedDelta
```

两者不是同一算法。

严重度：**Critical**。

## D02：验收报告将握拳标为通过，但测试没有验证握拳几何

验收矩阵把 F08 握拳张开标为合成通过，并引用 skeleton solver 的骨长/确定性。但现有测试没有验证活动姿态下 tip displacement 或 tip-to-palm distance。

严重度：**High**。

## D03：文档同时存在“可用”与“方向未标定”两种容易混淆的结论

README/验收报告强调真实数据闭环、18/18 和限条件通过；用户指南又明确说明方向正确性尚未标定。

需要区分：

- 通信闭环通过；
- 软件生命周期通过；
- 数学姿态通过；
- 真实方向通过；
- 精度指标通过。

严重度：**High**。

## D04：设计要求 swing/twist，生产只做向量投影

V2.0 需求明确要求优先使用 swing/twist 或等价分解、固定顺序和每指局部轴；生产实现不满足。

严重度：**Critical**。

## 7. V2.1 测试体系要求

## 7.1 数学层

- q/-q 等价；
- compose/decompose 往返；
- mixed-axis；
- near-180°；
- mount 物理轴；
- neutral 非交换；
- left/right basis；
- Invalid/low-confidence singularity。

## 7.2 骨骼几何层

- bind invariance；
- parent-child displacement；
- pivot 固定；
- 骨长保持；
- 正屈曲朝掌心；
- tip-to-MCP 单调缩短；
- 非目标子树不动；
- wrist rigid rotation；
- CPU skin 与 overlay 一致。

## 7.3 配置集成层

- 默认 asset 能启动；
- CLI config 真正生效；
- per-sensor isolation；
- 非法配置阻断；
- config/rig hash 记录；
- source switch 清 neutral。

## 7.4 融合轨迹层

- 已知单轴/多轴 ground truth；
- 多采样率；
- 丢组；
- invalid 插入；
- 6D/9D 漂移；
- 磁干扰和恢复；
- Madgwick/VQF 同数据对比。

## 7.5 真实硬件层

- 掌三轴公共旋转；
- 五指逐根屈伸；
- 四长指张合；
- 拇指对掌；
- 握拳重复；
- 10 分钟静置；
- 磁干扰；
- 断连重连；
- raw + 派生流 + 同步视频。

## 8. 验收证据规范

每个真实动作数据集必须包含：

- 唯一 session id；
- 动作名称和执行顺序；
- 操作者和左右手；
- 硬件/固件/量程；
- 轴和 mount 配置；
- calibration/neutral 时间；
- config/rig/model hash；
- raw.bin；
- fused/observation/skeleton/diagnostics；
- 同步或可对齐视频；
- 自动指标报告；
- 人工结论和失败备注。

## 9. 发布结论用语

V2.1 文档必须分别给出：

| 层级 | 允许结论示例 |
| --- | --- |
| 协议 | CRC/分组通过 |
| 软件 | 实时、回放、退出通过 |
| 数学 | 分解/FK 往返和几何门禁通过 |
| 硬件方向 | 逐指正方向和掌旋转通过 |
| 稳定性 | 6D/9D 漂移分别达到指标 |
| 精度 | 只在有 ground truth 时报告 |

禁止再用“真实数据能驱动模型”替代“真实姿态方向正确”。

## 10. 最终判断

测试基础设施可以继续使用，但 V2.1 必须先建立会让当前错误实现失败的红灯测试。验收报告必须引用真实断言和数据证据，而不是以测试数量、无崩溃或画面有变化作为姿态正确证明。
