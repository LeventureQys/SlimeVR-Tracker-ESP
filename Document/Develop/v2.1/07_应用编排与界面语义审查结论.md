# 模块审查 07：应用编排与界面语义

## 1. 审查范围

主要文件：

- `src/app/main.cpp`
- `src/app/runtime_controller.*`
- `src/app/demo_data_source.*`
- `src/ui/main_window.*`
- `src/render/hand_render_widget.*`
- `src/recording/session_recorder.*`
- `tests/test_app_integration.cpp`
- `docs/用户测试指南.md`
- `docs/架构说明.md`

## 2. 模块结论

**结论：条件不通过。**

线程、数据源切换、信号分层和基本 UI 生命周期框架可以保留，但产品编排没有完成配置/校准闭环，source 切换与 neutral 状态也存在风险。界面目前把低置信、未标定、不可观测的角度以普通数值展示，容易造成“算法已经给出真实关节角”的错误印象。

## 3. 可保留部分

### 3.1 worker 线程边界

GUI 与算法 worker 分离，跨线程传递值对象，整体方向合理。

### 3.2 统一数据源入口

serial/replay/demo 从 bytesReady 后走同一 parser→calibration→fusion→observation→skeleton 链路，适合做确定性回归。

### 3.3 数据源生命周期

切换 source 时停止并删除旧 source、重置 parser/grouper/calibration/fusion 的方向正确。

### 3.4 UI 模块化

数据源、校准、六路状态、手指表格、录制和诊断分区清楚，适合 V2.1 增加更明确的状态显示。

## 4. 已证实缺陷

## A01：产品初始化忽略 runtime config

main 正确解析 `--config`，但 RuntimeWorker 初始化只加载 model 和 hand rig，不加载 runtime config。

UI/CLI 即使提供正确参数，也不会影响产品。

严重度：**Critical**。

## A02：校准入口没有完整产品语义

当前 UI 有：

- 启动零偏；
- 调零（中立姿态）；
- 磁场状态；

但缺少完整的：

- 原始量程/轴配置；
- 六路安装外参校准；
- 磁样本采集和求解；
- 参数保存/加载；
- 校准版本和有效状态；
- 配置变化后的 neutral 失效。

严重度：**High**。

## A03：切换数据源只调用 observation reset，不清除 neutral

`HandObservationSolver::reset()` 只清 last frame，没有清 neutral。RuntimeWorker 切换 source 时调用 reset，但没有调用 clearNeutral。

后果：

- 从 demo 切到 serial 可能沿用 demo neutral；
- 从一个 replay 切到另一个 replay 可能沿用旧 neutral；
- 更换设备后仍可能使用旧安装零位。

严重度：**High**。

## A04：切换数据源时 `latestPoses_` 没有清空

source switch 重置 parser/calibration/fusion，但没有显式 `latestPoses_.reset()`。

如果用户在新 source 首个有效组到达前点击“调零”，可能使用旧 source 的六路姿态。

严重度：**High**。

## A05：中立校准没有稳定性门禁

`setNeutral()` 只要求：

- 六路 valid；
- 非 stale；
- 同 sequence。

没有要求：

- 静止持续时间；
- gyro bias 已收敛；
- 当前 source 身份一致；
- mount/config hash 一致；
- 磁/6D 状态已知；
- 手势符合中立动作表。

运动中点击也可能成功并建立错误零位。

严重度：**High**。

## A06：UI 把 aggregate observation 当普通角度展示

手指表格直接显示：

- flexionDegrees；
- abductionDegrees；
- twistDegrees；

没有清楚区分：

- 指尖累计姿态分量；
- 估计关节角；
- 可观测/不可观测；
- 6D/9D；
- saturated/clamped；
- mount/neutral 是否有效。

严重度：**High**。

## A07：twist 没有低置信或不可观测展示

在未标定磁场、长期 6D 或分解奇异时，twist 仍以带一位小数的角度展示，视觉上具有虚假精度。

严重度：**High**。

## A08：demo 只证明链路活动，不证明手部动作

DemoDataSource 生成的是简单原始九轴波形，各路只加小 offset。它没有定义：

- 真实掌旋转；
- 单指屈伸；
- 单指张合；
- 拇指对掌；
- 已知目标四元数；
- 期望骨骼位置。

因此 demo 画面出现变化不能作为姿态正确证据。

严重度：**Medium/High**。

## A09：录制 metadata 缺少算法和校准上下文

当前 metadata 中 axes/ranges/sensorMounts 可能为空，且没有 neutral event、config hash、rig hash 和分解版本。

录制无法回答“这组角度使用了什么安装参数和零位”。

严重度：**High**。

## A10：UI 诊断没有把结构性未标定状态升级为阻断

文档承认轴向和安装方向 unknown，但产品仍继续输出姿态数值。更安全的行为应是：

- 明确显示 Uncalibrated；
- 降 confidence；
- 阻止“验收模式”；
- 不把输出标为方向正确。

严重度：**High**。

## 5. 对用户症状的影响

| 症状 | 本模块贡献 |
| --- | --- |
| 调零后仍错误 | 可能使用未稳定姿态、旧 source 姿态或旧 neutral |
| demo 看似正常，真实手套错误 | demo 没有物理动作 oracle |
| twist 看起来像精确事实 | UI 缺少 observability/低置信语义 |
| 修改配置无效 | RuntimeWorker 不加载 config |
| 切源后突然偏移 | neutral/latestPoses 状态可能跨 source 保留 |

## 6. V2.1 修复要求

1. RuntimeWorker 初始化先加载/验证 config，再创建算法对象；
2. source 切换清除 latest poses、neutral、pending calibration 和 identity；
3. neutral 绑定 source/device/config/rig hash；
4. neutral 前要求六路静止和 bias 状态满足门禁；
5. UI 分开显示：
   - Fused sensor orientation；
   - Distal finger observation；
   - Estimated joint state；
6. 显示每分量 confidence/observable/saturated；
7. 6D 下 twist 显示“低置信/不可长期观测”；
8. 增加完整磁校准和安装校准向导；
9. demo 改成已知目标姿态和已知骨骼动作场景；
10. recording 写入 config/rig/algorithm/neutral 事件；
11. 未完成硬件轴和 mount 时产品显示阻断性 Banner。

## 7. 验收门禁

- `--config` 能端到端改变输出；
- source switch 后 neutral 和 latest poses 为空；
- 新 source 首帧前点击调零明确失败；
- 运动中调零失败或要求确认；
- device/config hash 变化使 neutral 失效；
- UI 不把 distal observation 标成独立 MCP/PIP/DIP 测量；
- twist 不可观测时不显示普通高置信角；
- demo 每个动作有可断言目标输出；
- serial/replay/demo 的同一 raw 输入产生一致派生结果；
- metadata 能完整追溯姿态生成上下文。

## 8. 最终判断

应用和 UI 框架可继续使用，但 V2.1 必须把配置、校准、source 身份和可观测性变成一等状态。否则即使底层数学修正，用户仍可能因为旧 neutral、未标定 mount 或误导性角度显示得到错误结论。
