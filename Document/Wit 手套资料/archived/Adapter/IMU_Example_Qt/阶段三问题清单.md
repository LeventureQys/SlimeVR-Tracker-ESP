### 自决区（不阻塞）

#### Q1. Qt 6.8 的 `QLowEnergyService` 错误文本
- 问题描述：首次编译发现 Qt 6.8.3 的 `QLowEnergyService` 没有 `errorString()`，不能沿用 controller 的错误读取方式。
- 自决方案：根据 `QLowEnergyService::ServiceError` 枚举映射稳定中文错误文本。
- 自决理由：使用 Qt 公开 API，错误类型完整且不依赖平台私有字符串。
- 风险预警：底层平台错误细节少于 controller 的 `errorString()`，但不会影响错误状态和资源清理。
- 置信度：99%。

#### Q2. Windows BLE 快速重连偶发失败
- 问题描述：真实硬件第一次诊断成功断开后，连续两次快速重连出现 `Error occurred trying to connect to remote device.`；再等待 8 秒后连接成功。
- 自决方案：v0.1.0 保持用户手动重连模型，在 README 和完成报告记录设备/Windows 后端可能需要数秒释放连接；不在当前版本引入自动重连状态机。
- 自决理由：阶段一已明确不实现自动重连；第三次连接成功且完整数据链路通过，现象属于设备或 Windows BLE 连接释放时序，而非协议解析失败。
- 风险预警：用户断开后立即连接可能看到一次连接失败，需要等待数秒重新点击连接。
- 备选方案：后续版本加入带指数退避的自动重连，并明确取消、上限和 UI 状态。
- 置信度：94%。

#### Q3. Windows GUI 子系统启动测试等待方式
- 问题描述：PowerShell 直接调用 `WIN32_EXECUTABLE` 时返回控制台控制权早于 GUI 进程退出，首次测得 82 ms，不能作为真实启动持续时间证据。
- 自决方案：改用 `Start-Process -PassThru -Wait` 等待进程，最终记录运行 4062 ms、退出码 0。
- 自决理由：该方式针对 Windows GUI 子系统正确等待进程生命周期，证据有效。
- 风险预警：无。
- 置信度：100%。
