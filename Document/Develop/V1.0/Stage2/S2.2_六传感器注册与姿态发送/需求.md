# V1.0-S2.2：六传感器注册与姿态发送需求

- 所属阶段：V1.0 阶段 2
- 前置依赖：`V1.0-S2.1` 验收通过
- 版本目标：注册一个手套设备的六个传感器并发送真实姿态

## 1. 目标

1. 为 `0x50`–`0x55` 建立稳定 Sensor ID；
2. 会话建立或重建后发送六路 SensorInfo；
3. 按配置频率发送每路最新 RotationData；
4. 隔离约 `200 Hz` 融合和 `50–100 Hz` 网络频率；
5. 禁止历史姿态堆积和无效姿态发送。

## 2. 固定映射

| 地址 | 名称 | Sensor ID | 暂定节点 |
| --- | --- | ---: | --- |
| `0x50` | Wrist | `0` | Hand |
| `0x51` | Thumb | `1` | Thumb Distal |
| `0x52` | Index | `2` | Index Distal |
| `0x53` | Middle | `3` | Middle Distal |
| `0x54` | Ring | `4` | Ring Distal |
| `0x55` | Pinky | `5` | Little Distal |

Sensor ID 不因重连、重启或左右手切换而重排。

## 3. 功能需求

### FR-1 姿态输入

- 输入来自 `SixImuSolver::snapshotReady(const SixImuSnapshot &)`；
- 使用 `SensorPose::relativeOrientation` 还是 `worldOrientation` 必须由 `Q-S2.2-01` 在编码前关闭；
- 网络模块不得读取解析器私有缓存或重新运行融合；
- 每次网络 tick 使用最新一致快照，不维护历史 FIFO。

### FR-2 有效性

每路发送前检查：四分量有限、范数非零、归一化误差不超过 `1e-4`、`valid=true`、数据年龄不超过默认 `500 ms`。失败只跳过该路并分类计数，不影响其他路。

### FR-3 SensorInfo

- 连接后发送恰好六路，重连后重新发送；
- 顺序固定 Wrist、Thumb、Index、Middle、Ring、Pinky；
- 状态使用 `SENSOR_OK=1`；数据类型使用 rotation `0`；
- 传感器类型和 SensorConfigBits 必须由问题清单确认，不得猜测；
- 位置枚举值使用仓库 `src/sensors/sensorposition.h`；
- 不得注册第七路或复制关节。

### FR-4 RotationData

- 包类型 `17`；
- 载荷字段为 Sensor ID、data type、四个大端 float `x,y,z,w`、accuracy；
- data type 默认 normal `1`；
- accuracy 的取值由 `Q-S2.2-03` 确认；
- 本版本坐标转换可暂为单位转换，但必须经过独立适配器。

### FR-5 发送节流

- 默认 `75 Hz`，配置范围 `50–100 Hz`；
- 每个 tick 每路最多发送一次最新姿态；
- 断线不缓存，重连后先 SensorInfo 再恢复姿态；
- 统计每路发送率、无效跳过和过期跳过。

## 4. 测试需求

- 六地址映射到 ID `0–5`；
- SensorInfo 恰好六路且位置正确；
- 六路不同四元数按 ID 可还原；
- NaN、Inf、零范数、invalid、超时被拒绝；
- 200 Hz 输入在 75 Hz 配置下不按 200 Hz 发包；
- 重连顺序为握手、注册、姿态。

## 5. 交付物

- 六路姿态适配器；
- SensorInfo/RotationData 编码和发送；
- 节流器和统计；
- 自动测试及真实 Server 注册记录；
- 问题清单和完成报告。

## 6. 验收标准

1. Server 识别一个设备和恰好六个传感器；
2. ID 稳定且无串路；
3. 有效单位四元数按 `x,y,z,w` 发送；
4. 发送率接近配置值且无历史积压；
5. 单路无效不影响其他路；
6. 重连后自动重新注册并恢复；
7. 连续 10 分钟无崩溃、NaN 发送和无界增长。
