# V1.0-S2.4 用户操作说明

## 1. 运行要求

- Windows 10/11 x64；
- SlimeVR Server（验证基线 `v20.1.0`），默认 UDP 端口 `6969`；
- 六 IMU 手套串口（`921600/8N1`）或演示数据。

## 2. 基本流程

1. 启动 SlimeVR Server；
2. 启动 `SixImuSolverQt.exe`；
3. 选择数据源：
   - 真实硬件：选择串口并点击“打开串口”；
   - 软件验证：勾选“演示模式”；
4. 在“SlimeVR 输出”组选择模式：
   - `自动发现`：广播查找局域网 Server；
   - `固定地址`：填写 Server IP（例如本机 `127.0.0.1`）；
5. 选择手侧（左手/右手）和发送率（50–100 Hz，默认 75）；
6. 勾选“启用”并点击“应用设置”；
7. 观察状态行变为“已连接”，Server 中出现一个设备、六个节点；
8. 如需补偿六颗传感器安装方向，点击“安装旋转”逐路设置单位四元数（默认单位值）；
9. 在 Server 中对设备执行挂载校准；
10. 按 `动作验证记录.md` 逐路做单轴动作验证。

## 3. 校准边界（重要）

- 工具端“六路零位标定”只影响本地显示，不进入 SlimeVR 网络流；
- “安装旋转”补偿传感器物理安装方向；
- SlimeVR Server 的挂载校准由 Server 端完成；
- 三者不是同一件事，不要重复执行同类归零。

## 4. 无界面探针（真实 Server 验证用）

```powershell
.\build\Debug\slimevr_bridge_probe.exe --host 127.0.0.1 --port 6969 --side left --rate 75 --quit-after-ms 60000
```

- `--serial COM7` 使用真实串口；省略则使用演示数据；
- 每秒输出一行 `state/sent/received/sensorInfo/rotations/skipped/errors/reconnects` 统计。

## 5. 排障

| 现象 | 检查 |
| --- | --- |
| 状态停在“握手中/自动发现中” | Server 是否运行；防火墙是否放行；固定地址模式 IP/端口是否正确 |
| 状态“配置错误” | 固定地址模式下地址必须为 IP 字面量（暂不支持主机名） |
| Server 收不到设备 | 确认“启用”已勾选并点击“应用设置”；Server 端口是否为 6969 |
| 六节点显示 Unknown 类型 | 属预期（外部融合，不声明芯片型号），不影响姿态 |
| 节点方向与手指不符 | 用“安装旋转”逐路补偿，并复核动作验证表 |
| Server 重启后失联 | 客户端 3 秒超时后自动重连并重新注册，等待状态恢复“已连接” |
| 配置损坏 | 删除或修复 INI 中 `slimevr/*` 键，工具会按默认值回退 |
| 想完全回退到原工具行为 | 取消勾选“启用”并应用；网络模块不会影响串口与融合 |

## 6. 已知限制

- 多网卡机器自动发现可能只覆盖默认路由网段（问题 `Q-S2.1-11`）；
- 固定地址暂不支持 DNS 主机名（问题 `Q-S2.1-12`）；
- 真实硬件动作验证未完成前，坐标方向结论以软件测试为准。
