# 模块审查 06：骨骼 FK、模型与渲染

## 1. 审查范围

主要文件：

- `src/model/model_data.h`
- `src/model/model_importer.*`
- `src/model/standard_joints.h`
- `src/skeleton/kinematic_skeleton.*`

## 2. 模块结论

**结论：不通过。**

目标 GLB 的专用导入和 palette 映射总体可用，渲染器也能正确消费给定 skin matrices。核心失败在 KinematicSkeleton：当前实现没有递归计算虚拟骨链，父关节旋转不会移动子关节位置，腕部姿态也没有进入模型根变换。

因此当前看到的手指变化不是正确 FK，而是错误 skin matrix 在各绑定点附近造成的网格扭曲。

## 3. 可保留部分

### 3.1 目标 GLB 专用导入

对当前资产，导入器能够读取：

- 单 mesh / primitive；
- POSITION/NORMAL/TEXCOORD；
- JOINTS_0/WEIGHTS_0；
- 25 个 skin joints；
- inverse bind matrices；
- GLB `[x,y,z,w]` 到 Qt `wxyz`；
- joint bind world；
- bone name 到 palette index。

### 3.2 palette 按名称映射

目标 GLB 的 skin.joints 顺序不是解剖顺序，按唯一骨名将 virtual skeleton 映射回 palette 是正确思路。

### 3.3 bind pose 不变性

`root * bindWorld * inverseBind` 能在 bind pose 恢复模型，相关模型导入和基础 skin contract 可保留。

### 3.4 renderer 职责

HandRenderWidget 从 HandSkeletonFrame 读取：

- skin matrices；
- global joint positions；

并上传 GPU。渲染器没有暗中交换四元数分量，是正确分层。

## 4. 目标资产的关键事实

目标 GLB 中：

- 25 个关节都直接平铺在 Armature 下；
- joint node 本身没有 GLB children；
- skin.joints 顺序与解剖链不同；
- 虚拟 Wrist→Metacarpal→Proximal→Intermediate→Distal→Tip 父链来自 hand rig；
- GLB node local 是相对 Armature 的 local，不是相对虚拟解剖 parent 的 local。

因此 V2.1 必须从 bind world 计算虚拟 local bind：

```text
L_i = inverse(B_parent) * B_i
```

不能直接把 GLB node local 放进虚拟 parentGlobal*local。

## 5. 已证实缺陷

## S01：`localMatrix` 被计算但 global 不使用

当前每 bone 计算：

```text
localMatrix = bindLocal * localRotation
```

但 global 随后使用：

```text
globalMatrix = rootTransform * bindWorld * accumulatedDelta
```

这形成两套互不一致的矩阵语义。

严重度：**Critical**。

## S02：当前公式不是递归 FK

祖先 rotation 只被左乘到 `accumulatedDelta`，然后整体右乘在 child bindWorld 后面。

缺失：

- parent animated global；
- parent pivot；
- parent-to-child bind translation；
- 每级 bind frame；
- 子树递归。

严重度：**Critical**。

## S03：所有关节点位置不会随动作移动

纯 rotation matrix 右乘不会改变左侧 affine matrix 的平移列。因此：

```text
translation(bindWorld * accumulatedDelta)
= translation(bindWorld)
```

对现有 skeleton JSONL 聚合验证：

- demo 554 帧：所有 joint displacement = 0；
- real 3968 帧：所有 joint displacement = 0。

这与正常握拳时指尖应明显移动相矛盾。

严重度：**Critical**。

## S04：祖先旋转发生在错误 pivot

对 child 使用：

```text
B_child * R_parent * R_child
```

会让 parent rotation 在 child 自己的绑定原点附近作用，而不是绕 parent joint pivot 带动 child。

表现为：

- 网格局部拧动；
- 指节断裂感；
- 反关节；
- 远端姿态不符合整链几何。

严重度：**Critical**。

## S05：wrist orientation 被忽略

KinematicSkeleton 只检查 `observation.wristWorldOrientation` 是否有效。最终：

```text
frame.rootTransform = computeDisplayRootTransform(model)
```

没有把 wrist orientation 转到模型坐标并作用于整手。

严重度：**Critical/High**。

## S06：关节轴正方向与实际模型几何不一致

所有关节配置统一使用 local +X/+Y/+Z。实际 GLB bind rotation 非单位。

对食指 proximal 分析：

- current local +X 经 bind rotation 后接近 model -Z；
- 几何掌心屈曲轴接近 model +Z；
- 方向接近相反。

当前配置中的正 flexion 会导致反向运动。

严重度：**Critical**。

## S07：root/display/wrist 组合顺序没有 pivot oracle

固定显示根包含旋转、缩放和居中平移。将 wrist delta 加入时必须明确围绕哪个 pivot 旋转，不能简单猜测 `display*wrist` 或 `wrist*display`。

需要以 wrist joint 和 90° 三轴刚体测试冻结。

严重度：**High**。

## S08：renderer 直接消费错误矩阵

renderer 本身没有制造 FK 错误，但没有几何 sanity check。只要 bone.valid 为 true，就会上传 skin matrix。

`valid` 当前主要检查 global translation 有限；由于 translation 始终是 bind 值，错误 FK 也几乎总是 valid。

严重度：**High**。

## S09：导入器对通用 glTF 支持有限

对目标专用资产可接受，但通用风险包括：

- 固定使用 scenes[0]，未读取 default scene index；
- 假设 meshes[0]/skins[0]；
- 没有完整跟踪 skinned mesh node transform；
- 多 mesh、多 skin、不同 scene root 不支持。

这些不是当前目标资产错误的首要根因，应列 P2，不与 P0 FK 修复混在一起。

## 6. 现有测试缺口

`test_skeleton_solver` 当前主要验证：

- bind pose global translation；
- bind skin matrix；
- 大角输入仍 finite；
- 同输入 deterministic；
- Held/Recovered 状态；
- wrist invalid freeze。

没有验证：

- 活动指尖是否移动；
- 父旋转是否移动 child；
- pivot 是否固定；
- 骨长是否在活动姿态保持；
- 正 flexion 是否朝掌心；
- 非目标手指是否不动；
- wrist 是否驱动整手；
- CPU skin 后指尖距离是否缩短。

## 7. V2.1 修复要求

1. 根据 virtual parent 和 bind world 生成 virtual local bind；
2. 每帧从 bind pose 递归计算 animated global；
3. local/global/skin 使用单一一致语义；
4. skin matrix 由 animated global * inverseBind 得到；
5. overlay position 与 renderer 都消费同一 animated global；
6. 从实际几何和 bind frame 冻结每关节正轴；
7. wrist delta 经 modelFromAnatomical 基变换后作用于整手；
8. 显示变换和 wrist 旋转围绕冻结 wrist pivot 组合；
9. bone valid 增加矩阵有限、骨长、父链和 determinant sanity；
10. 暂时保持目标 GLB 专用导入，不在同一阶段扩展通用 glTF。

## 8. 验收门禁

- bind pose CPU skin error < `1e-4`；
- active pose 每段骨长误差 < `1e-4`；
- parent rotation 后所有 descendants 移动；
- joint 自身 pivot 位移 < `1e-5`；
- 非 descendants 不动；
- 正 flexion 使 tip-to-MCP 距离减小；
- 半握拳距离介于 bind 和 full fist；
- wrist 90° 旋转使整手刚体方向正确；
- skeleton overlay 与 skinned mesh 关节位置一致；
- demo/real skeleton frame 的活动 tip displacement > 0；
- 轴符号回归时测试稳定失败。

## 9. 最终判断

该模块的 P0 修复是 V2.1 成败关键。只要递归 FK 没有正确建立，任何上游角度调参都只会改变网格扭曲方式，无法得到真实手指骨链运动。
