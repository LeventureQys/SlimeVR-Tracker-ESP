# V1.0-S2.1：UDP 协议与会话基座需求

- 所属阶段：V1.0 阶段 2
- 版本目标：建立可测试、可重连的 SlimeVR UDP 基础链路
- 前置依赖：阶段 1 Windows MVP 可构建、可运行
- 后续依赖：`V1.0-S2.2`

## 1. 背景

现有 Windows Qt 工具已具备六 IMU 串口、协议解析、同 `SEQ` 分组和姿态融合，但没有 SlimeVR 网络输出。本版本先隔离网络风险，只建立协议编解码和会话状态机，不发送真实六路姿态。

协议行为以当前仓库 `src/network/connection.cpp`、`src/network/packets.h` 及目标 SlimeVR Server 版本为依据。开发开始时必须记录被验证的 Server 版本或提交号；如果 Server 协议与固件实现不同，以抓包和 Server 实测为准并记录差异。

## 2. 目标

1. 提供独立于 UI 和融合算法的 SlimeVR UDP 数据报编解码模块；
2. 支持自动发现或显式 Server 地址两种连接方式；
3. 实现握手、Server 响应处理、心跳、超时和自动重连；
4. 提供确定性的本地假服务器测试；
5. 建立后续 SensorInfo 和 RotationData 可复用的发送入口。

## 3. 范围

### 3.1 包含

- `QUdpSocket` 生命周期管理；
- 目标地址和端口配置；
- SlimeVR 包类型、包号和网络字节序处理；
- 客户端握手发送与 Server 握手响应解析；
- 心跳发送；
- 连接超时、socket 错误和重连；
- 会话状态及统计信号；
- 本地 UDP 假服务器和协议单元测试。

### 3.2 不包含

- 六路 SensorInfo 注册；
- 六路 RotationData；
- 左右手骨骼映射；
- 坐标系和安装旋转；
- 修改融合参数或算法；
- ESP 固件网络代码复用或移植。

## 4. 功能需求

### FR-1 协议编码

- 必须显式按字段编码，不得将含填充风险的 C++ 结构体直接写入 UDP；
- 必须按协议使用大端编码整数和浮点字段；
- 普通包头为 4 字节大端包类型，后接 8 字节大端包号；
- 握手发送包的包号固定为 `0`，其余普通发送包使用递增包号；
- 编码失败不得发送残缺包；
- 编码模块应可在不创建窗口的测试中调用。

### FR-2 连接配置

- 支持“自动发现”和“固定地址”两种模式；
- 固定地址模式至少包含主机/IP 和端口；
- 默认端口必须与目标 SlimeVR Server 协议一致；
- 非法地址、非法端口和空固定地址应拒绝启用并给出一次性可读错误；
- 设置加载失败时使用安全默认值，不得崩溃。

### FR-3 会话状态机

状态至少包括：`Disabled`、`Discovering`、`Handshaking`、`Connected`、`Backoff`、`Error`。

- 启用后进入发现或握手流程；
- 收到有效 Server 握手后进入 `Connected`；
- 非预期来源或格式错误的数据报不得刷新有效会话时间；
- 超时后离开 `Connected`，进入有界退避并重试；
- 重试间隔不得形成无延迟忙循环；
- 禁用后立即停止发现、心跳和重连；
- 重复启用、禁用和 reset 必须幂等。

### FR-4 握手

客户端握手字段顺序必须复刻当前固件 `Connection::sendTrackerDiscovery()`：

1. 4 字节大端包类型 `3`；
2. 8 字节大端包号 `0`；
3. 4 字节大端 board；
4. 4 字节大端 primary sensor type；
5. 4 字节大端 MCU；
6. 三个 4 字节大端兼容保留值 `0`；
7. 4 字节大端 protocol version；
8. 1 字节长度 + firmware version UTF-8；
9. 6 字节稳定设备标识；
10. 1 字节 tracker type；
11. 依次为 vendor name、vendor URL、product name、update address、update name，每项为 1 字节长度 + UTF-8。

Server 发现响应按当前固件兼容格式解析：首字节为 `3`，随后至少 12 字节匹配 `Hey OVR =D 5`。必须先校验长度再比较内容。

### FR-5 心跳与超时

- Server 发来普通 `HeartBeat` 包时回复发送类型 `0` 的心跳包；
- 连接有效期参考当前固件 `3000 ms`，最终值由 `Q-S2.1-04` 决定；
- Server 超时判定使用单调时钟；
- 系统时间调整不得造成错误重连；
- socket 操作不得阻塞主线程。

### FR-6 统计和诊断

至少提供当前状态、Server 地址和端口、收发数据报数、编码/发送/非法接收计数、最近收发时间、握手次数、成功次数、重连次数和当前包号。统计更新应节流。

## 5. 非功能需求

- 网络不可用时串口解析和融合继续运行；
- 收包缓冲和诊断记录有界；
- 非法输入不得导致越界读取、异常或崩溃；
- 默认日志仅记录状态变化和聚合错误；
- Windows 防火墙阻挡时显示可理解状态但不自动提权。

## 6. 测试需求

### 6.1 单元测试

覆盖包类型、包号、整数/浮点大端编码、完整握手字段顺序、握手响应长度校验、截断包、未知包、包号连续递增、reset 和重复启停。

### 6.2 本地集成测试

使用回环地址和动态端口的假服务器验证握手、心跳、超时、退避、恢复、异常来源拒绝和关闭后停止发送。测试不得占用真实 Server 默认端口。

## 7. 交付物

- 协议常量与编解码模块；
- UDP 客户端和会话状态机；
- 网络配置数据结构和持久化；
- 本地假服务器及自动测试；
- 协议字段与目标 Server 版本记录；
- 已更新的问题清单和完成报告。

## 8. 验收标准

1. 无窗口测试完成握手、心跳、超时和重连；
2. 已知字段和字节序测试全部通过；
3. Server 不可达时不阻塞原链路；
4. 连续 10 分钟本地会话无意外断开和资源无界增长；
5. reset 后可重新建立会话；
6. 本版本不包含 SensorInfo 和 RotationData。
