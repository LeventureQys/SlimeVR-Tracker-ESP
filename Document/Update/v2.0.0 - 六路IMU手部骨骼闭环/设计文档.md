## 2. 背景与目标

现有仓库包含三套分散资产：

1. `Document/Research/手套IMU解算MVP/`：C++17/Qt6 六路原始 IMU 协议、同步、Madgwick、串口和测试基线。
2. `Document/Develop/v2.0/手套姿态解算软件/`：Python/PySide6 的 25 关节 GLB 加载、骨架、GPU 蒙皮、UI 与录制实现。
3. `Document/Wit 手套资料/archived/`：C++20/Qt6/Assimp 的模型导入、骨骼约束、掌指相对姿态、前向运动学和 OpenGL 渲染原型。

V2.0.0 将三套资产收敛为一个纯 C++/Qt 产品，在真实六路硬件输入和离线回放输入上执行相同核心链路，生成模型无关的 `HandSkeletonFrame` 并实时驱动现有 GLB 手模。

## 6. 总体架构与线程模型

```text
GUI/Main Thread
  MainWindow ─ HandRenderWidget ─ Diagnostics Panels
      ▲                 ▲
      │ queued signals  │ latest immutable frame
      │                 │
Worker Thread
  IDataSource
    ├─ SerialDataSource
    └─ ReplayDataSource
      → FrameStreamParser
      → SequenceGrouper
      → CalibrationPipeline
      → FusionBank (6 filters)
      → HandObservationSolver
      → HandSkeletonSolver
      → Recorder taps + HandSkeletonFrameReady
```

约束：

- 串口读取、解析、融合、骨骼求解和磁盘写入不得阻塞 GUI 线程。
- 跨线程数据通过 Qt queued signal 或显式有界队列传递；队列容量、丢弃策略和统计必须可观察。
- UI 只消费不可变快照，不直接调用融合器内部状态。
- 实时输入和回放输入从 `IDataSource::bytesReady` 起走完全相同链路。
- 算法每帧从绑定姿态求解，不累积骨骼矩阵。

## 7. 核心接口契约

以下为逻辑契约；具体命名空间统一为 `handstudio`。四元数均使用 Hamilton `w,x,y,z`，单位四元数，矩阵使用 Qt `QMatrix4x4` 约定并通过测试冻结乘法顺序。

### 7.1 RawImuFrame

```cpp
struct RawImuFrame {
    SensorId sensorId;
    quint8 address;
    quint8 sequence;
    qint64 receivedMonotonicNs;
    std::array<qint16, 3> accelerationRaw;
    std::array<qint16, 3> gyroscopeRaw;
    std::array<qint16, 3> magnetometerRaw;
    bool crcValid;
    bool allZero;
};
```

解析器只发送 CRC 正确且地址已知的帧；`crcValid` 保留用于录制和测试序列化，不允许错误帧进入融合。

### 7.2 SixImuSampleGroup

```cpp
struct SixImuSampleGroup {
    quint8 sequence;
    qint64 emittedMonotonicNs;
    std::array<RawImuFrame, 6> samples;
    bool complete;
    quint8 presentMask;
};
```

默认融合入口只接受 `complete == true && presentMask == 0x3f`。重复节点采用“同 sequence 同 sensor 首帧保留、后续计数并丢弃”。pending 上限默认 8；淘汰最旧未完整组并产生诊断。

### 7.3 CalibratedImuSample

```cpp
struct CalibratedImuSample {
    SensorId sensorId;
    quint8 sequence;
    qint64 timestampNs;
    QVector3D accelerationMps2;
    QVector3D gyroscopeRadPerSec;
    QVector3D magneticMicroTesla;
    float temperatureC;
    bool temperatureValid;
    bool valid;
    CalibrationState calibrationState;
};
```

每个传感器独立持有量程、轴置换/符号、零偏、软硬铁矩阵和设备身份。配置非法时 `valid=false`，不得以默认值静默继续生产验收结果。

### 7.4 FusedImuPose

```cpp
enum class FusionMode { Invalid, SixD, NineD };
struct FusedImuPose {
    SensorId sensorId;
    quint8 sequence;
    qint64 timestampNs;
    QQuaternion worldOrientation;
    FusionMode mode;
    bool valid;
    bool stale;
    bool restDetected;
    QVector3D gyroBiasRadPerSec;
    MagneticHealth magneticHealth;
    CalibrationState calibrationState;
    float confidence;
};
```

`IFusionFilter::update(const CalibratedImuSample&, double dtSeconds)` 是算法替换边界。Madgwick 与 VQF 必须输出同一类型；所有输出在发布前执行有限性、范数与符号连续性保护。

### 7.5 HandObservationFrame

```cpp
struct FingerObservation {
    SensorId sensorId;
    QQuaternion worldOrientation;
    QQuaternion palmRelativeOrientation;
    QQuaternion mountCorrectedOrientation;
    float flexionDegrees;
    float abductionDegrees;
    float twistDegrees;
    bool valid;
    float confidence;
};
struct HandObservationFrame {
    quint8 sequence;
    qint64 timestampNs;
    HandSide handSide;
    QQuaternion wristWorldOrientation;
    std::array<FingerObservation, 5> fingers;
};
```

固定公式：`qRelative = inverse(qPalmWorld) * qFingerWorld`；`qCorrected = qMount * qRelative * inverse(qMount)`。拇指与长指分别配置分解轴。公式与乘法顺序必须由合成四元数单测冻结。

### 7.6 HandSkeletonFrame

```cpp
enum class BoneSource { Measured, Estimated, Held, Recovered, Invalid };
struct HandBoneFrame {
    QString boneName;
    int parentIndex;
    QMatrix4x4 bindLocalMatrix;
    QVector3D localTranslation;
    QQuaternion localRotation;
    QVector3D localScale;
    QMatrix4x4 localMatrix;
    QMatrix4x4 globalMatrix;
    QMatrix4x4 skinMatrix;
    bool valid;
    float confidence;
    BoneSource source;
};
struct HandSkeletonFrame {
    quint8 sequence;
    qint64 timestampNs;
    HandSide handSide;
    QString skeletonId;
    QMatrix4x4 rootTransform;
    QVector<HandBoneFrame> bones;
    bool coupledApproximation;
    QVector<Diagnostic> diagnostics;
};
```

现有 `hand_skeleton_types.h` 缺少 `handSide`、`skeletonId`、完整绑定 TRS、`valid`、`Measured/Recovered` 来源，阶段三必须升级并迁移调用方。

## 8. 模型与骨骼配置

### 8.1 目标 GLB 硬契约

- glTF 2.0 GLB。
- 单网格、单 primitive、单 skin，三角形模式。
- 25 个标准关节；关节名称以 Python 参考中的 `wrist`、`thumb-*`、`index-finger-*`、`middle-finger-*`、`ring-finger-*`、`pinky-finger-*` 为准。
- 目标资产共有 30 个节点、1360 个顶点、6942 个索引；25 个 skin joint 在 `Armature` 下平铺，资产 `children` 不能作为解剖父链。
- 产品必须分离两套索引：`skinJointPalette` 保持 GLB joint 顺序，`kinematicBones` 根据标准名称和配置建立虚拟解剖层级；二者通过唯一骨名映射。
- 顶点至少包含 POSITION、NORMAL、TEXCOORD_0、JOINTS_0、WEIGHTS_0 和 indices。
- 逆绑定矩阵数量与 skin joints 数量相同。
- 每顶点最多四个骨骼影响；权重归一化误差超过容差时报告并安全归一化。

### 8.2 导入策略

首选使用 Assimp 5.4.3 导入 GLB，复用 archived `RiggedModel` 数据结构。必须新增针对目标 GLB 的测试，证明：

- 关节名称、父索引和数量正确；
- 网格顶点/索引/权重有效；
- 绑定局部矩阵和 inverse bind 可重建绑定姿态；
- bind pose CPU 蒙皮顶点误差不超过 `1e-4` 模型单位。

若 Assimp 无法满足目标 GLB，允许替换导入实现，但不得改变 `RiggedModel` 和上层骨骼契约。

### 8.3 新模型配置

新增 `assets/hand_rig_generic_left.json`，包含：

- `schemaVersion`、`skeletonId`、`handSide`；
- root/wrist 骨骼；
- 五指标准骨链；
- 每关节 flexion/abduction/twist 轴、限位、锁轴和耦合；
- 每传感器安装四元数；
- 缺帧保持、回中和恢复限速参数。

旧 `archived/config/hand_rig.json` 的匿名 FBX 骨名不得直接复制。

## 9. 融合、校准与异常策略

### 9.1 硬件基线冻结

真实硬件开发前必须产生 `testdata/hardware/<dataset-id>/metadata.json` 与 `raw.bin`，记录：

- 串口号、921600/8N1 是否实测；
- 固件/设备标识；
- 加速度、陀螺仪、磁力计量程和单位；
- 原始轴到应用坐标轴映射；
- 目标采样率；
- 六颗 IMU 的物理位置和安装方向；
- 采集时间、操作者、动作说明和配置版本。

缺少上述参数时，仅允许执行协议和合成数据测试，不允许给出真实姿态精度结论。

### 9.2 磁场状态机

状态为 `Unavailable / Healthy / Disturbed / Recovering`。进入干扰态需连续异常样本，恢复需连续正常样本；干扰时融合退化到 SixD，恢复航向修正受速率限制。阈值进入版本化配置。

### 9.3 失效与恢复

- 单指无效：保留上一姿态，标记 `Held`，置信度按时间衰减；超时平滑回中立位。
- 单指恢复：限制每秒最大角速度并短时标记 `Recovered`。
- 手腕无效：冻结整手相对观测和骨骼，产生阻断诊断；不得用各指世界姿态继续生成相对角。
- 任意非法数值：保持上一有效值、降低置信度并记录诊断，禁止发布 NaN/Inf。

## 10. 录制与回放格式

每次录制目录：

```text
recordings/<UTC>-<session-id>/
├─ metadata.json
├─ raw.bin
├─ raw_frames.jsonl
├─ fused_poses.jsonl
├─ observations.jsonl
├─ skeleton_frames.jsonl
└─ diagnostics.jsonl
```

`metadata.json` 包含 schema、应用版本、Git revision（若可得）、设备、模型哈希、配置哈希、算法和平台信息。JSON 四元数一律 `wxyz` 并显式写字段名；矩阵为 16 个数并记录存储顺序。写入使用有界队列，磁盘过慢时优先保留 `raw.bin` 和诊断，并报告各层丢弃数。

回放从 `raw.bin` 进入同一解析链路，支持原速、暂停、逐组和无限速确定性测试。同一原始输入与配置重复运行，离散字段必须一致，浮点字段在 `1e-6` 容差内一致。

## 12. SubStage 划分与依赖

1. **SubStage 1：工程基座与统一契约**：独立可执行；冻结产品目标、目录、类型、诊断、配置 schema，剥离网络依赖。
2. **SubStage 2：输入、协议、录制与回放**：依赖 SubStage 1；复用协议核心，建立统一数据源和确定性数据集。
3. **SubStage 3：校准与融合层**：依赖 SubStage 1；可与 SubStage 2 的非接口实现并行，最终用其录制数据集集成。
4. **SubStage 4：手部观测与骨骼求解**：依赖 SubStage 1、3；移植 archived 数学能力，输出完整 `HandSkeletonFrame`。
5. **SubStage 5：GLB 导入与 OpenGL 渲染**：依赖 SubStage 1；可与 SubStage 2、3 并行；以目标 GLB 和 `HandSkeletonFrame` 为唯一输入。
6. **SubStage 6：UI、线程与系统集成**：依赖 SubStage 2、3、4、5；接通真实硬件、回放、录制和显示，执行启动测试。

跨 SubStage 只通过第 7 节类型、`IDataSource`、`IFusionFilter`、`RiggedModel` 和 `HandSkeletonFrame` 交互。

## 13. 测试设计

### 13.1 单元测试

- 协议：分包、粘包、噪声、CRC、未知地址、重复节点、序号回绕、pending 上限。
- 配置：schema、非法单位/矩阵/四元数、配置升级和哈希。
- 融合：静止、已知单轴旋转、非法 dt、磁干扰切换、四元数归一与符号连续。
- 观测：公共手掌旋转抵消、安装修正顺序、五指映射、拇指独立轴、奇异输入。
- 骨骼：绑定姿态、限位、骨长、耦合、缺帧保持、恢复限速、有限矩阵。
- GLB：25 关节、父链、顶点属性、逆绑定、bind pose 蒙皮不变性。
- 录制回放：状态机、暂停不写、元数据完整、原始字节保真、重复回放确定。
- UI：离屏创建、数据源切换、状态展示和退出时线程释放。

### 13.2 启动与功能测试

- 启动 `HandSkeletonStudio.exe`，加载目标 GLB，无模型错误和 OpenGL 错误。
- 连接真实六路串口，确认六路帧率、完整组率和姿态持续更新。
- 执行中立校准、手掌三轴旋转、逐指屈伸/张合、拇指对掌。
- 开始/暂停/恢复/停止录制，随后用该会话回放。
- 模拟单指丢失、手腕丢失、串口断连重连和磁干扰。
- 运行至少 30 分钟，记录内存、pending、队列水位、处理延迟和 FPS。

## 14. 构建与发布

基线命令：

```powershell
cmake -S . -B build-v2 -DBUILD_TESTING=ON -DHAND_SKELETON_FETCH_ASSIMP=ON
cmake --build build-v2 --config Release
ctest --test-dir build-v2 -C Release --output-on-failure
```

最终构建不得探测或调用 Python。发布目录包含 EXE、Qt 运行库、OpenGL/平台插件、目标 GLB 和 JSON 配置；启动时资产缺失必须给出明确错误并安全退出。

## 15. 禁止事项

- 禁止保留 Python 作为隐藏回退路径、离线处理器或测试必需项。
- 禁止让 UI、录制器或渲染器读取融合器内部对象。
- 禁止将 SlimeVR 网络库链接到产品运行时。
- 禁止在显示层交换四元数分量或取反轴来修复安装错误。
- 禁止拼接不同 sequence 的传感器数据形成完整组。
- 禁止使用未验证默认量程产出真实精度结论。
- 禁止直接修改指尖位置伪造骨骼动作。
- 禁止在骨骼矩阵中累积上一帧结果。
