# V2.0.0 六路 IMU 手部骨骼闭环 总结报告

## 1. 版本结论

- 版本号：V2.0.0
- 版本名称：六路 IMU 手部骨骼闭环
- 结论：软件闭环完成；验收为**限条件通过（待批准豁免）**。
- 唯一阻断：真实硬件（COM12 FTDI 六路设备）被 DSH 沙箱拒绝访问，真实动作/精度/耐久验收需用户侧补验（问题清单 v3 Q4）。

## 2. 达成内容

- 纯 C++20/Qt6 产品 `HandSkeletonStudio`（工程根 `Document/Research/手套IMU解算MVP`），构建、运行、测试零 Python 依赖。
- 六层完整链路：串口/回放原始字节 → 协议解析与六路同步 → 量程/轴/零偏/磁校准 → Madgwick/VQF 融合 → 掌指相对与安装修正 → 虚拟层级 FK 骨骼解算 → `HandSkeletonFrame` → GLB GPU 蒙皮与骨架覆盖显示。
- 录制与回放：raw.bin 字节保真 + metadata + fused/observation/skeleton jsonl，确定性回放验证通过。
- 矩阵/四元数契约冻结：Hamilton wxyz；`globalMatrix` 含显示根变换、`skinMatrix = globalMatrix × inverseBind`；bind pose 逐顶点蒙皮不变性误差 7.468e-07（阈值 1e-4）。
- 质量门禁：全量 Release 构建 exit 0；ctest 18/18；demo/回放启动测试退出码 0 且有截图；产品不链接 SlimeVR 网络与遗留 six_imu_core。

## 4. 关键决策记录

1. 主实现载体：纯 C++/Qt，移除全部 Python 运行时依赖（用户确认）。
2. 核心验收模型：现有 `generic-hand-left.glb`（用户确认）。
3. 目标 GLB 25 关节在资产中平铺 → 蒙皮 palette 与虚拟解剖层级解耦，以唯一骨名映射（专项分析结论）。
4. Assimp 因沙箱 TLS 阻断无法获取 → 按任务书 §6 授权替换为自包含 glTF2/GLB 解析器，契约与 bind 不变性测试一致。
5. VQF 由仓库自有 `lib/vqf`（MIT）vendor，封装 pimpl 不泄漏内部类型。
6. 跨 SubStage 并行协作：根 CMakeLists 由 MainAgent 独占，各 SubStage 使用独立 `cmake/substageN.cmake` 与独立构建目录，共享区只读。
7. 骨骼空间契约（SubStage 6 冻结）：`globalMatrix = displayRoot × bindWorld × accumulatedDelta`、`skinMatrix = globalMatrix × inverseBind`、`rootTransform` 仅记录值。

## 5. 遗留问题（进入后续版本或补验）

1. 真实硬件验收（六路实时、动作矩阵 F03/F13、精度/漂移、30 分钟耐久）——用户侧补验。
2. UI 接线缺口：回放速度控件、校准持久化对话框、`--config` 到 CalibrationPipeline 的参数映射。
3. 磁力计增益默认值未确认；磁健康仅按模长判异常；硬/软铁简化为轴向缩放。
4. 旧 `six_imu_core`/`src/imu_types.h` 等遗留适配层可在确认后退役；`madgwick_filter.cpp` 双编译待清理。
5. git tag：`Document/` 未跟踪，需用户确认提交范围后打 `v2.0.0`。
