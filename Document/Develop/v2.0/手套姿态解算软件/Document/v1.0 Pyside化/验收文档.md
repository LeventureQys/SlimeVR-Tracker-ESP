# 验收文档 —— v1.0 PySide 桌面化

- 版本：v1.0（目录 `Document/v1.0 C++化/`）
- 阶段：阶段四·验收执行依据（阶段三完成后按本文件逐层验收，产出 `验收报告.md`）
- 依据：`设计文档.md`（契约/算法/参数）、四份 SubStage 任务书（各自验收标准）

## 0. 验收总原则

- 四层顺序执行：**编译测试 → 启动测试 → 功能完整性测试 → 整体测试**；每层记录证据（命令输出原文、截图说明、操作记录）写入 `验收报告.md`；任一层失败即定位 SubStage 修复，不得跳过。
- "显示效果与 web 端一致"的口径：读数/曲线/姿态**数值一致**为硬标准（同一移植公式，误差 < 1e-6）；渲染**观感一致**为软标准（默认视角构图、皮肤半透明、骨骼覆盖层、网格、雾、配色逐项比对，允许轻微光照差异，逐项记录结论）。
- 本机无硬件串口时，真实串口路径以「单元测试（合成字节流）+ 代码走查」证明；端到端核心路径用模拟数据源实测。

## 4. 第四层：整体测试（数值一致 + 观感一致）

### 4.1 数值一致性（硬标准）

- 方法：同一脚本 t=0.5/1.0/2.0s 的 demo 参数，分别喂 web 端（临时用 `serve_app.py` + 浏览器或直接运行 `web/js` 逻辑的 Node/手工对照）与桌面端（单测 + 运行观察），比对：bend/sway 读数（±0.1° 显示精度内一致）、最大弯曲/侧摆、曲线值（< 1e-6）、姿态（bind 不变性测试 + 满握拳关节角测试已在单测覆盖）。
- 若无法运行 web 端（无浏览器自动化条件），以移植公式单测 + 设计文档 5.3 常量对照表代替，并在报告中注明。

### 4.2 观感一致性（软标准，逐项记录结论）

## 5. 验收结论与门禁

- 全部通过 → 阶段四完成：归档 web 端（`web/`、`tools/serve_app.py` 移入 `archived/`，README 更新）、打 tag `v1.0.0`、产出 `验收报告.md` 与 `总结报告.md`。
- 部分失败 → 定位 SubStage 修复后重跑对应层；验收标准本身不清 → 先补文档再验收。
- 归档动作在用户确认验收报告后进行。
